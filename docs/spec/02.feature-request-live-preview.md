## 1. 배경

DocuLight 2.0 은 **옵시디언(Obsidian)의 편집·열람 경험을 웹으로 옮기고, 옵시디언에 없는 사용자·그룹 접근제어를 더한** 사내 문서 시스템이다. 마크다운 문서는 서버 파일시스템에 저장되고, 프론트엔드는 Vite + React + TypeScript SPA 다.

제품 요구사항 **R1** 은 "에디터와 렌더링 결과가 옵시디언과 동일해야 한다"이다. 이 요구의 실질 비용은 대부분 **라이브 프리뷰** 한 기능에 집중되어 있다.

**이 작업을 독립 세션으로 분리하는 이유:**

프론트엔드 스택 후보 3종(React / Next.js / Svelte)을 각각 검토한 결과, **세 검토자 전원이 공통으로 지적한 사실**이 있다.

> 옵시디언식 라이브 프리뷰는 **기성 패키지가 존재하지 않는다.** CodeMirror 6 의 `ViewPlugin` + `Decoration.replace` + `atomicRanges` 를 직접 구현해야 하며, **스택 선택으로 줄어들지 않는 유일한 항목**이다.

공수 추정은 검토자에 따라 **8~12일** 또는 "Phase 1 공수의 절반 가까이"로 제시되었다. 즉 이 항목이 Phase 1 일정의 주 리스크이며, 나머지 기능과 병행 개발이 가능하도록 **프레임워크 중립 모듈로 분리**한다.

## 2. 무엇을 만드는가

**CodeMirror 6 확장 세트**로 구현된 마크다운 라이브 프리뷰 에디터. React 애플리케이션에 얹히지만, **핵심은 프레임워크에 의존하지 않는다**(R33-c).

### 라이브 프리뷰의 정의

커서(및 선택 영역)가 **닿지 않은** 마크다운 구문은 **문법 기호를 감추고 렌더링된 모습**으로 보여주고, 커서가 **닿는 순간 원문(raw source)이 드러난다.**

```
커서가 다른 곳에 있을 때        커서가 그 안에 있을 때
─────────────────────         ─────────────────────
문서 제목                       ## 문서 제목
굵은 글씨                       **굵은 글씨**
• 항목                          - 항목
```

편집 중에도 문서는 항상 **하나의 CodeMirror 인스턴스** 안에 있다. 프리뷰 창을 따로 띄우거나 렌더링된 HTML 을 편집하는 방식이 **아니다.**

## 3. 기능 요구사항

### 3.1 라이브 프리뷰 대상 요소 (R16-a)

아래 9종이 Phase 1 필수 대상이다.

| # | 요소 | 커서 밖 표시 | 커서 안 표시 |
|---|---|---|---|
| 1 | **헤딩** `## 제목` | 마커 숨김 + 헤딩 크기·굵기 적용 | `## ` 노출 |
| 2 | **강조** `**굵게**` `*기울임*` `~~취소~~` | 마커 숨김 + 스타일 적용 | 마커 노출 |
| 3 | **목록** `- 항목` `1. 항목` | 불릿·번호 글리프로 대체, 들여쓰기 유지 | 원문 마커 노출 |
| 4 | **링크** `[텍스트](url)` · `[[위키링크]]` | 표시 텍스트만, 클릭 가능 | 전체 구문 노출 |
| 5 | **인용** `> 인용문` | `>` 숨김 + 좌측 보더·배경 | `>` 노출 |
| 6 | **코드블록** ` ```lang ` | 블록 스타일 + 구문 하이라이팅(shiki) | 펜스 라인 노출 |
| 7 | **표** `\| a \| b \|` | **렌더된 표** | 원문 파이프 구문 |
| 8 | **수식** `$x$` `$$…$$` | KaTeX 렌더 | 원문 노출 |
| 9 | **Mermaid** ` ```mermaid ` | 다이어그램 렌더 | 원문 노출 |

**7번(표)이 가장 어렵다.** 여러 줄에 걸친 블록을 위젯으로 대체하면서 커서 진입 시 원문으로 되돌리는 전이가 까다롭고, 표 안에서의 편집 경험이 문제가 된다. **착수 시 이 항목을 먼저 검증하고, 난이도가 예상을 크게 넘으면 보고할 것.**

### 3.2 "커서가 닿는다"의 정밀 정의

수용 기준 2 는 "커서가 없는 **줄**"이라고 서술되어 있으나, 옵시디언의 실제 동작은 요소 종류에 따라 다르다. 아래를 정본으로 한다.

| 구분 | 판정 단위 | 예 |
|---|---|---|
| **인라인 요소** (강조·인라인 코드·링크·인라인 수식) | **노드 단위** | `**굵게** 와 *기울임*` 에서 커서가 `굵게` 안에 있으면 **그 노드의 마커만** 드러나고 `*기울임*` 은 렌더 상태 유지 |
| **블록 요소** (헤딩·인용·목록 항목) | **줄 단위** | 커서가 그 줄 어디에 있든 마커 노출 |
| **멀티라인 블록** (코드블록·표·수식 블록·Mermaid) | **블록 전체** | 커서가 블록 내부 어디에 있으면 블록 전체가 원문으로 |

**선택 영역이 요소에 걸쳐 있으면 그 요소는 원문으로 드러낸다.** (선택 상태에서 사용자가 구조를 파악해야 하므로)

### 3.3 소스 모드 (R90)

편집 모드 안에 **라이브 프리뷰 ↔ 소스** 하위 토글을 둔다. 소스 모드는 **모든 데코레이션을 끄고 순수 마크다운 원문**을 보여준다(구문 하이라이팅은 유지). 라이브 프리뷰에서 숨겨지는 원문 — 표 구분선, 각주 정의 등 — 을 통째로 편집하기 위한 수단이다.

전환 시 **커서 위치와 스크롤이 보존**되어야 한다.

### 3.4 위키링크 (R16)

기본 마크다운 문법에 없으므로 **`@lezer/markdown` 확장으로 파서에 추가**해야 한다.

- 문법: `[[문서명]]` · `[[문서명|표시 텍스트]]` · 첨부 임베드 `![[…]]`
- `[[` 입력 시 **자동완성**이 뜬다. 후보 목록은 **외부에서 주입되는 비동기 함수**로 조회한다(§5 인터페이스). 에디터는 후보를 자체 판단하지 않는다 — 권한 필터가 서버에서 적용되기 때문
- 존재하지 않거나 접근 권한이 없는 대상을 가리키는 링크는 **깨진 링크 스타일**로 표시한다(구별 없이 동일하게 — 존재 여부가 노출되면 안 됨)
- 링크 클릭 시 **콜백으로 위임**한다. 에디터가 직접 라우팅하지 않는다

### 3.5 첨부 붙여넣기·드래그 (R49)

편집기에 이미지·바이너리를 **붙여넣거나 드래그**하면 업로드된다. UX 는 **GitHub 마크다운 편집기와 동일** — 업로드 중에는 자리표시자가 삽입되고, 완료 시 실제 링크로 치환된다.

- 업로드는 **외부 주입 함수**가 수행한다(§5). 에디터는 파일을 넘기고 결과 URL 을 받는다
- 삽입되는 링크는 **위키링크 또는 워크스페이스 기준 절대경로만** 사용한다. **상대경로 삽입 금지**(R65-a)
- 업로드 실패 시 자리표시자를 제거하고 콜백으로 알린다

### 3.6 저장 연동 (R75)

문서는 **무버튼 자동 저장**이다.

- 입력이 멈추면 **디바운스(약 2초)** 후 저장 콜백 호출
- `Ctrl+S` 는 즉시 저장 + 버전 스냅샷 강제 생성 신호
- 저장 콜백이 **충돌을 반환**하면 자동 저장을 **일시 중단**하고 상위에 알린다. 재개는 상위가 지시한다
- 에디터는 저장 자체를 수행하지 않는다 — 콜백만 호출한다

### 3.7 충돌 병합 뷰 (R18 · R63-a)

`@codemirror/merge` 를 사용한 병합 뷰를 **같은 모듈에서 제공**한다. 저장 충돌 해소와 문서 버전 비교·복원 두 곳에서 재사용된다.

## 4. 기술 제약 (필수 준수)

### 4.1 문서 본문을 React state 로 올리지 않는다 (R33-d) — **가장 중요**

CodeMirror 인스턴스가 **문서 본문의 SSOT** 다. React 의 controlled `value` 패턴으로 묶으면 다음이 발생한다.

- 커서가 튀는 현상
- **한글 IME 조합이 깨지는 현상**

본문은 `ref` 로 접근하고, React 는 문서 내용이 아니라 **메타 상태**(모드·저장 상태·충돌 여부)만 관리한다.

### 4.2 한글 IME 무결 (수용 기준 7)

**조합 중(`view.composing === true`)에 데코레이션을 재계산하면 조합이 깨진다.** ViewPlugin 의 `update()` 에서 조합 상태를 확인하고, 조합 중에는 데코레이션 갱신을 **억제**했다가 조합 완료 후 재계산해야 한다.

이 항목은 **자동화가 어려워 수동 체크리스트로 검증**한다. 체크리스트를 산출물에 포함할 것.

### 4.3 프레임워크 중립 (R33-c)

핵심 로직은 순수 CodeMirror 6 확장이어야 한다. React 결합은 **얇은 래퍼 한 겹**(`ref` + `useEffect` 마운트/언마운트)으로 제한한다.

**React 19 StrictMode 의 이중 마운트**에 주의한다 — `useRef` 가드 없이 effect 에서 CM 인스턴스를 만들면 인스턴스가 둘 생긴다.

### 4.4 사용 패키지

| 용도 | 패키지 |
|---|---|
| 코어 | `@codemirror/state` `@codemirror/view` `@codemirror/commands` `@codemirror/language` |
| 마크다운 | `@codemirror/lang-markdown` `@lezer/markdown` (위키링크 확장용) |
| 자동완성 | `@codemirror/autocomplete` |
| 검색 | `@codemirror/search` |
| 병합 | `@codemirror/merge` |
| 렌더 | `katex`(수식) `mermaid`(다이어그램) `shiki`(구문 하이라이팅) |

`mermaid` · `katex` · `@codemirror/merge` 는 번들이 크므로 **동적 import 로 분리**한다.

### 4.5 성능

수천 줄 문서에서 타이핑 지연이 체감되지 않아야 한다. 데코레이션은 **뷰포트 범위만** 계산하고(`view.visibleRanges`), 문서 전체를 매번 순회하지 않는다.

## 5. 인터페이스 계약 (제안 — 조정 가능)

에디터가 외부와 주고받는 경계다. **이 계약은 이 문서에서 처음 제안하는 것이므로, 구현 편의에 따라 조정을 제안해도 좋다.** 다만 §4.1(본문을 React state 로 올리지 않음)은 조정 대상이 아니다.

```ts
interface MarkdownEditorOptions {
  // 초기 문서 — 이후 본문은 CM 이 소유한다
  initialDoc: string;

  mode: 'live' | 'source';        // R90
  readOnly: boolean;              // 보기 권한만 있는 경우 (R91)

  // 위키링크 자동완성 후보 — 권한 필터는 서버가 적용한다
  queryLinkTargets: (prefix: string) => Promise<LinkTarget[]>;

  // 링크 대상의 존재·접근 가능 여부 (깨진 링크 판정)
  resolveLinks: (targets: string[]) => Promise<Record<string, boolean>>;

  // 첨부 업로드 — 결과는 워크스페이스 절대경로 또는 위키링크
  uploadAttachment: (file: File) => Promise<{ insertText: string }>;

  // 자동 저장 (디바운스는 에디터가 관리)
  onSave: (doc: string, opts: { force: boolean }) => Promise<SaveResult>;

  onLinkClick: (target: string) => void;
  onDirtyChange: (dirty: boolean) => void;
}

type SaveResult =
  | { ok: true }
  | { ok: false; reason: 'conflict'; serverDoc: string }
  | { ok: false; reason: 'forbidden' | 'error'; message: string };

interface LinkTarget { path: string; title: string; }
```

**충돌 처리 흐름**: `onSave` 가 `conflict` 를 반환 → 에디터가 자동 저장 중단 + `serverDoc` 을 병합 뷰로 노출 → 사용자가 해소 → 상위가 자동 저장 재개를 지시.

- §3 의 전 항목 (라이브 프리뷰 9종 · 소스 모드 · 위키링크 · 첨부 · 저장 연동 · 병합 뷰)

| 2 | **IME 조합 중 데코레이션 억제** | `view.composing` 확인 필수. 억제 해제 타이밍이 어긋나면 조합 문자가 사라지거나 중복된다 |
| 3 | **`atomicRanges` 와 커서 이동** | 위젯을 커서가 통과하지 못하게 해야 하지만, 과하게 걸면 방향키 이동이 부자연스러워진다 |
| 4 | **`@lezer/markdown` 위키링크 확장** | 기존 링크 파서와 충돌하지 않게 우선순위를 잡아야 한다 |
| 5 | **Mermaid 렌더 비용** | 다이어그램이 많은 문서에서 뷰포트 진입 시 lazy 렌더 필요 |
| 6 | **React 19 peer 호환** | 일부 CM 관련 패키지의 React 19 공식 지원 명시 여부는 **확인 필요** |

### 참고

- 옵시디언 자체가 CodeMirror 6 기반이다
- `codemirror-rich-obsidian` 등 유사 목적의 오픈 구현이 존재한다고 보고되었으나 **프로덕션 채택 여부는 확인되지 않았다.** 참고 자료로만 활용하고 검증 없이 의존하지 말 것
- `@uiw/react-codemirror` 같은 래퍼는 데코레이션을 직접 다루는 이 작업에서 **오히려 방해가 될 수 있다.** 초기 스파이크에만 쓰고 걷어내는 것을 권한다
