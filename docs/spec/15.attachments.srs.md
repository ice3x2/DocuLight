### FR-ATTACH-001 — 트리 드래그앤드롭 파일 업로드

| Field | Value |
| --- | --- |
| Type | functional |
| Target | phase-1 |
| Status | planned |
| Priority | high |
| Tags | upload, file-tree, drag-and-drop |
| Risk | medium |
| Stability | stable |
| Verification Method | Playwright E2E |
| GitHub Issue | - |
| Related Docs | [셸 화면 설계](./03.screen-design-shell.md) |

#### Requirement

사용자가 로컬 파일을 트리의 디렉토리 노드 위로 드래그앤드롭하면 시스템은 그 파일을 해당 디렉토리에 업로드한다. 업로드 전용 화면·모드는 두지 않으며 현재 화면에서 업로드가 완결된다.

#### Rationale

R2 가 1.0 의 「업로드 모드 / 뷰어 모드」 분리를 폐기했지만 폐기된 것은 업로드 **화면**이지 업로드 **기능**이 아니다. 원장이 두 조항이 모순되지 않음을 명시했다. 기각된 대안 — 업로드 전용 화면을 다시 두는 것.

#### Acceptance Criteria

- [ ] AC-1: 로컬 파일을 트리의 디렉토리 노드 위로 드롭하면 그 디렉토리에 파일이 생성된다.
- [ ] AC-2: 업로드가 끝나면 새 파일이 그 디렉토리의 자식 노드로 트리에 나타난다.
- [ ] AC-3: 업로드를 위해 별도 화면·모드로 전환하지 않고 현재 화면에서 드롭만으로 업로드가 완료된다.

#### Requirement

트리 목록은 md 가 아닌 파일도 숨기지 않고 그대로 표시한다.

#### Rationale

옵시디언과 명시적으로 다른 지점이다 — 옵시디언은 md 위주로 표시한다. 기각된 대안 — 옵시디언의 md 위주 표시를 답습하는 것. 업로드가 모든 형식을 허용하므로(R46) 트리가 md 만 보여주면 방금 올린 파일이 사라진 것처럼 보인다.

#### Acceptance Criteria

- [ ] AC-1: 디렉토리에 md 가 아닌 파일(이미지·바이너리)이 있으면 그 파일이 트리의 자식 노드로 표시된다.
- [ ] AC-2: 확장자를 이유로 트리 목록에서 제외되는 파일이 없다.

### FR-ATTACH-003 — 비-md 파일 열기 — 이미지는 미리보기, 그 외는 다운로드 링크만

| Field | Value |
| --- | --- |
| Type | functional |
| Target | phase-1 |
| Status | planned |
| Priority | medium |
| Tags | non-markdown, preview, download |
| Risk | medium |
| Stability | stable |
| Verification Method | test |
| GitHub Issue | - |
| Related Docs | [셸 화면 설계](./03.screen-design-shell.md) |

#### Requirement

비-md 파일을 클릭하면 이미지는 본문 영역에 미리보기로 표시하고, 이미지가 아닌 형식은 다운로드 링크만 표시한다. 이 규정의 범위는 Phase 1 이다.

#### Rationale

원장 `R48` 의 비고가 이 규칙을 명시적으로 Phase 1 규정으로 못박았기 때문에 요구 문면이 범위 한정을 함께 지닌다. 한정이 필요한 이유는 Phase 2 에서 이 규칙의 「그 외는 다운로드 링크만」 갈래가 두 군데서 깨지기 때문이다 — `R146` 이 PDF 를 `pdf.js` 뷰어로, `R147` 이 `.task` 를 할 일 목록으로 열어 그 갈래에서 빠진다. 범위를 적지 않으면 Phase 2 확장이 이 조항의 위반으로 읽히고, 반대로 Phase 1 에서 뷰어를 미리 넣는 근거로도 오독된다.

#### Acceptance Criteria

- [ ] AC-1: 비-md 이미지 파일을 클릭하면 본문 영역에 그 이미지의 미리보기가 표시된다.
- [ ] AC-2: 이미지가 아닌 비-md 파일을 클릭하면 다운로드 링크만 표시되고 내용 뷰어가 열리지 않는다.
- [ ] AC-3: PDF 를 클릭하면 Phase 1 에서는 다운로드 링크만 표시되고 PDF 뷰어가 열리지 않는다.

### FR-ATTACH-004 — 문서 편집기 붙여넣기·드래그 첨부 업로드

| Field | Value |
| --- | --- |
| Type | functional |
| Target | phase-1 |
| Status | planned |
| Priority | high |
| Tags | upload, editor, paste |
| Risk | medium |
| Stability | stable |
| Verification Method | Playwright E2E |
| GitHub Issue | - |
| Related Docs | [셸 화면 설계](./03.screen-design-shell.md) |

#### Requirement

문서 편집기에 이미지·바이너리를 붙여넣거나 드래그하면 시스템이 그 파일을 업로드하고 본문에 그 첨부를 가리키는 링크를 삽입한다. 상호작용은 GitHub 마크다운 편집기와 동일하다. 문서에 대한 편집 권한은 그 문서 소유 첨부의 업로드 권한을 포함한다.

#### Rationale

R49-a 는 감사 L5 를 해소한다 — 문서에만 편집 권한을 받은 사용자(디렉토리 권한 없음)도 이미지를 붙여넣을 수 있어야 R49 가 성립한다. 그래서 문서 편집 권한이 그 문서 소유 첨부의 업로드 권한을 포함하도록 정했다. 두 조항이 같은 동작의 성립 조건이므로 R49-a 를 AC-3 으로 흡수했다.

#### Acceptance Criteria

- [ ] AC-1: 편집기에 이미지를 붙여넣으면 그 이미지가 업로드되고 본문 커서 위치에 그 첨부를 가리키는 링크가 삽입된다.
- [ ] AC-2: 편집기에 파일을 드래그해 놓으면 붙여넣기와 같은 경로로 업로드되고 본문에 링크가 삽입된다.
- [ ] AC-3: 어느 디렉토리에도 편집 유효 권한이 없고 대상 문서에만 편집 유효 권한을 가진 사용자가 그 문서 편집기에 이미지를 붙여넣으면 업로드가 성공한다.
- [ ] AC-4: 대상 문서에 편집 유효 권한이 없는 사용자의 붙여넣기 업로드는 거부된다.

### DR-ATTACH-001 — 첨부 저장 레이아웃 — 워크스페이스 루트 .res 디렉토리와 해시 파일명

| Field | Value |
| --- | --- |
| Type | data |
| Target | phase-1 |
| Status | planned |
| Priority | high |
| Tags | attachment, storage, hash |
| Risk | high |
| Stability | stable |
| Verification Method | Playwright E2E |
| GitHub Issue | - |
| Related Docs | [셸 화면 설계](./03.screen-design-shell.md) |

#### Requirement

편집기 업로드(R49)로 올린 파일은 해시 파일명으로 워크스페이스 루트의 `.res/` 한 곳에 저장한다. 해시 앞 2글자를 서브디렉토리로 분할한다 (`.res/a3/f9c2….png`). 이미지뿐 아니라 일반 바이너리도 동일하다.

#### Rationale

감사 C2·C3 해소. 첨부를 문서와 같은 디렉토리에 두면 첨부의 접근 권한이 위치에 묶여, 문서를 옮길 때마다 유출(넓은 곳으로 이동)과 파손(좁은 곳으로 이동) 양방향이 생긴다. 저장을 워크스페이스 루트 한 곳으로 모아 위치와 권한을 분리했고, 권한은 소유 문서로 판정한다(R66). 해시 앞 2글자 분할은 한 디렉토리에 파일이 무한히 쌓이는 것을 막는다.

#### Acceptance Criteria

- [ ] AC-1: 편집기로 업로드한 파일이 워크스페이스 루트의 `.res/` 아래에 저장된다.
- [ ] AC-2: 저장된 파일명이 원본 파일명이 아니라 해시 값이다.
- [ ] AC-3: 저장 경로가 해시 앞 2글자를 서브디렉토리로 갖는다.
- [ ] AC-4: 이미지가 아닌 바이너리도 같은 규칙으로 `.res/` 에 저장된다.
- [ ] AC-5: 첨부가 소유 문서와 같은 디렉토리에 저장되지 않는다.

- [ ] AC-4: 소유 문서를 공개 위치로 이동하면 그 첨부가 즉시 열린다.

#### Implementation Notes

- `G35`-④ 미결 — PAT `읽기 전용` 스코프(R58-c)로 댓글을 달 수 있는지가 규정되지 않았다. 이 조항이 `보기` 권한자에게 작성을 허용했으므로 스코프 축과 권한 축이 갈린다. 이 축은 AC 로 채우지 않았다. 댓글 허용 설정(R148-a)을 바꿀 권한은 이 요구가 정하지 않는다 — 그것은 `G35`-⑤ 로 여전히 열려 있다.
