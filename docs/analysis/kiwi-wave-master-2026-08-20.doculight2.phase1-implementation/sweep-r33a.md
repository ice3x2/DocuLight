## 1. 개정 전/후 문면

### 개정 전 — `docs/spec/00.decision-log.md:445`

```
| R33-a | 빌드 산출물(정적 파일)은 **기존 Express 가 그대로 서빙**한다. Node 프로세스는 1개를 유지한다 | 동일 오리진이라 CORS·CSRF 문제가 없고 기존 PM2 배포 구성을 그대로 쓴다 |
```

### 개정 후 — 같은 줄 (445, 줄 번호 불변)

**결정 칸**

> **개정 (2026-08-20)** — 빌드 산출물(정적 파일)은 **2.0 의 Express 서버가 API 와 같은 오리진에서 그대로 서빙**한다. 별도의 프론트엔드 서버를 두지 않으며 **Node 프로세스는 1개를 유지**한다

**비고 칸**

> **초판은 결정이 *"빌드 산출물(정적 파일)은 기존 Express 가 그대로 서빙한다. Node 프로세스는 1개를 유지한다"*, 비고가 *"동일 오리진이라 CORS·CSRF 문제가 없고 기존 PM2 배포 구성을 그대로 쓴다"* 였다.** `R21` 개정(**백엔드·프론트엔드 전부 신규 작성**)으로 **「기존 Express」에는 가리킬 대상이 없어졌다** — 2.0 의 Express 는 새로 쓰는 것이다. **이 조항의 실질 셋은 그대로 살아 있다** — ① 정적 산출물을 **API 서버가 같은 오리진에서** 서빙한다 ② **Node 프로세스 1개** ③ 근거는 **CORS·CSRF 회피**. 셋 다 `R21` 개정과 무관하게 유효하므로 개정에서 떨어뜨리지 않았다. **프로세스 관리자로 PM2 를 쓰는 선택 자체는 유지한다.** 다만 초판 비고의 *"기존 PM2 배포 구성을 그대로 쓴다"* 는 **사용자 결정(2026-08-20)으로 실효됐다** — **1.0 의 배포 구성을 파일로 복사하지 않고, 읽기 전용으로 참고하되 구성은 2.0 용으로 신규 작성한다.** `R21-b`(*"2.0 의 어떤 설정도 1.0 경로를 가리키지 않는다"*)와 같은 방향이다. **SRS `OPS-ARCH-001` 은 2026-08-19 에 이미 이 방향으로 고쳐졌고 원장만 낡아 있었다** — `R124-a` 스윕이 `R21` 개정 때 이 행에 닿지 않았다

  검증 가능한 형태로 못박고 싶다면 AC 신설을 검토할 만하다 — **이 스윕이 정하지 않는다.**

### [2] `OPS-ARCH-001` Rationale — 낡은 전제의 잔재 (우선순위 중간)

**512행**

> `PM2 로 단일 프로세스를 띄우는 배포 방식(R33-a)이 **그대로 성립해** 운영 절차가 늘지 않는다.`

*"그대로 성립"* · *"늘지 않는다"* 는 **이어받을 기존 운영 절차가 있다는 전제**에서만 뜻이 선다.
`R21` 개정 뒤 2.0 의 배포 구성은 신규 작성이므로 「늘지 않는다」의 기준점이 없다.
제목·Requirement·AC-1 은 2026-08-19 에 고쳐졌는데 **Rationale 의 이 구절만 남았다.**

- 제안 — *"PM2 로 단일 프로세스를 띄우므로 운영이 관리할 프로세스가 하나로 끝난다"* 류로,
  1.0 연속성 함의 없이 같은 결론을 말하게 고친다. **규범 변화 없음**(문언 정합만).

### [3] `CON-ARCH-002` Implementation Note — 현재형 사실 주장이 거짓이 됐다 (우선순위 중간)

## 6. 확인하지 못한 것

1. **`docs/` 밖은 훑지 않았다.** 스윕 범위가 `docs/` 전체로 지시됐다. 코드·설정
   (`package.json` · CI · 배포 스크립트 · `ecosystem.config.*` 등)에 `R33-a` 옛 문면을 전제한
   자리가 있는지는 **미확인**이다. 다만 wave-1 이 아직 착수 전이라 배포 구성 산출물 자체가
   존재하지 않을 가능성이 높다 — **가정이며 실측하지 않았다.**
2. **SRS 3건(§4)의 실제 수정 여부.** speckiwi 관리 파일이라 지시대로 보고만 했다.
   `edit_requirement_fields` 등으로 반영됐는지는 이 문서가 확인하지 않는다.
3. **`design-baseline/wave-1.md` 와 두 JSON 의 갱신 판단.** 「규범 발췌인가 이력인가」를
   내가 판정했다. 파일 머리가 *"충돌하면 원장이 이긴다"* 를 달고 있어 **그대로 두는 선택도
   방어 가능**했다 — 낡은 사본이 wave-1 구현자에게 먼저 읽힌다는 이유로 갱신 쪽을 택했다.
   재생성 파이프라인이 이 파일들을 덮어쓴다면 **원장에서 다시 뽑히므로 결과는 같다.**
4. **`R33-a` 를 인용하지 않으면서 그 규범에 암묵적으로 기대는 산문.** ID·어휘 6갈래로 훑었으나
   *"프로세스를 하나로"* 같은 말을 **다른 낱말로 쓴 자리**가 있다면 잡히지 않는다.
   §3 의 ⑤가 그 완화책이지만 **전수라고 단정하지 않는다.**
5. **`R33-a` 개정이 다른 조항의 전제를 흔드는지.** `R19`(단일 인스턴스 규모)·`R87`(백업)·
   `CON-ARCH-001` 과의 정합은 **표면만 확인**했고 전수 심의는 하지 않았다.
