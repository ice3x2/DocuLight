# wave-2 — 주체와 ACL 판정 코어 (헤드리스 도메인)

> 설계 발췌. 정본은 `docs/spec/00.decision-log.md` 이며 이 파일은 그 wave 범위의 사본이다.
> 충돌하면 원장이 이긴다.

**목표** — 사용자·그룹·시스템 그룹(슈퍼유저·default)의 데이터 모델과 슈퍼유저 판정을 세우고, 그 위에 ACL 판정 엔진을 만든다. 상속+가산으로만 넓히고 좁히기는 상속 끊기뿐이며 거부 규칙이 없는 단조 모델, 매 요청 계산, 완전 숨김(트리 숨김·pass-through·존재 구별 불가 응답), 상방 게이트, 조작별 필요 권한 표가 화면 없이 순수 함수로 검증된다.

**요구사항** 31건 · **설계 항목(원장 조항)** 48건

| `R128-b` | §2.4 접근 제어 (ACL) | 253 | 수요는 세 경로로 흡수한다 — ① 하위 특정 노드에서 **`상속 끊기`**(R70-c, `관리`) ② 디렉토리 대신 **개별 문서에 부여**(R9) ③ 경계가 상시 필요하면 **별도 워크스페이스로 분리**(R69-d · R71-d) |

| `R69-a` | §2.4 접근 제어 (ACL) | 256 | 트리에 표시되는 것은 **① 사용자가 유효 권한을 가진 노드**와 **② 그런 노드로 가는 경로상의 조상**뿐이다. 조상의 **형제 노드는 표시하지 않는다** |

| `R69-c` | §2.4 접근 제어 (ACL) | 258 | pass-through 여부는 **저장하지 않고 매 요청 계산**한다 |
| `R69-d` | §2.4 접근 제어 (ACL) | 259 | pass-through 는 **디렉토리 이름을 노출한다.** 경로 이름 자체가 기밀인 경우는 **별도 워크스페이스로 분리**하여 대응한다 |

| `R95` | §2.4 접근 제어 (ACL) | 261 | 생성·업로드가 **요청자에게 보이지 않는 동명 노드와 충돌**하면, 존재를 드러내지 않고 덮어쓰지도 않는다 — **자동 리네임 후 일반 안내만** 표시한다. 깨진 위키링크 클릭 시의 문서 생성(옵시디언과 동일)도 같은 규칙을 따른다 |
