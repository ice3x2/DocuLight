# wave-3 — 인증·세션·PAT·설치 마법사

> 설계 발췌. 정본은 `docs/spec/00.decision-log.md` 이며 이 파일은 그 wave 범위의 사본이다.
> 충돌하면 원장이 이긴다.

**목표** — 슈퍼유저 0명 상태에서 설치 마법사가 강제되고, 그 안에서 최초 슈퍼유저와 기본 워크스페이스의 default 초기 권한이 정해진다. 로그인·세션·계정 4상태 게이트·가입 모드 3종이 서고, 전역 API Key 대신 사용자별 PAT 가 도입된다. 이 wave 가 끝나면 '이 요청이 누구인가'가 확정되어 wave-2 의 판정 엔진에 실제 주체가 주입된다.

**요구사항** 25건 · **설계 항목(원장 조항)** 28건

| `R72-c` | §2.4 접근 제어 (ACL) | 279 | **설치 토큰의 수명은 출력 시점부터 30분**이며, 만료 시각을 **절대시각으로 콘솔에 함께 출력**한다 |
| `R72-d` | §2.4 접근 제어 (ACL) | 280 | **서버 재기동 시 이전 토큰은 무효가 되고 새 값이 출력된다.** 같은 값을 다시 내보내지 않는다 |
| `R72-e` | §2.4 접근 제어 (ACL) | 281 | **토큰 분실·만료 시 복구 경로는 서버 프로세스 재기동 하나다.** 재발급 API·CLI 하위명령·토큰 파일을 두지 않는다 |
| `R72-f` | §2.4 접근 제어 (ACL) | 282 | **`1회용`(R72-b)은 "설치를 성공적으로 완료하면 소진"을 뜻한다** — 소진 시점은 최초 슈퍼유저를 만드는 트랜잭션이 커밋되는 순간이며, 그 전까지는 실패·중단과 무관하게 재입력할 수 있다 |
| `R72-g` | §2.4 접근 제어 (ACL) | 283 | **설치 마법사의 모든 서버 요청은 토큰 검증으로 발급된 설치 세션을 요구한다. 토큰을 진입 시점에만 검사하지 않는다** |
| `R72-h` | §2.4 접근 제어 (ACL) | 284 | **설치 완료 전 응답하는 경로는 `설치 화면 · 그 정적 자산 · 토큰 검증 · 설치 커밋` 넷으로 한정한 허용목록이며, 그 밖의 모든 경로는 차단한다** |
| `R72-i` | §2.4 접근 제어 (ACL) | 285 | **R57 rate limit(F2)의 적용 단위를 소스 IP 로 명시한다. 전역 카운터를 쓰지 않는다** |
| `R72-j` | §2.4 접근 제어 (ACL) | 286 | **인지된 잔여 위험 — 토큰이 콘솔에 평문으로 출력된다.** 로그 수집기·화면 공유·터미널 스크롤백에 남는 것을 제품이 막지 못한다. R72-c 의 30분 수명이 노출 창을 줄이는 유일한 완화책이다 |
| `R73` | §2.4 접근 제어 (ACL) | 287 | **슈퍼유저 그룹의 `active` 멤버 수가 0 이 되는 결과를 만드는 모든 조작을 거부한다** — 멤버 제거, `suspended`/`pending`/`rejected` 전환 등 전 경로 |
| `R83` | §2.14 초기 상태 | 503 | 기본 워크스페이스에 대한 **default 그룹의 초기 권한은 설치 마법사(R72)에서 선택**한다: 없음 / 보기 / **편집(기본값)** |
| `R83-a` | §2.14 초기 상태 | 504 | 접근 가능한 노드가 0개인 사용자에게는 **빈 상태 안내 화면**을 보여준다 — 상황 설명과 관리자 문의 안내 |
| `R57` | §2.15 인증 | 513 | **개정 (2026-08-19)** — 1.0 과 **같은 기술 선택**을 쓰되 **구현은 신규 작성**한다 — bcrypt, HttpOnly 세션 쿠키, `express-rate-limit` |
| `R58` | §2.15 인증 | 514 | **1.0 의 전역 API Key 를 폐기**하고 **사용자별 개인 액세스 토큰(PAT)** 으로 대체한다 |
| `R58-a` | §2.15 인증 | 515 | PAT 는 **해시로 DB 에 저장**하고, 발급 시 **평문을 1회만 노출**한다. 만료일·마지막 사용 시각을 기록하고 폐기할 수 있다 |
| `R58-c` | §2.15 인증 | 517 | PAT 발급·폐기는 **본인만** 할 수 있다. 발급 시 **`읽기 전용 / 읽기+쓰기` 스코프**를 선택하며, 실제 권한은 스코프와 실시간 유효 권한(R59)의 **교집합**이다 |
| `R59` | §2.15 인증 | 519 | **세션과 토큰에 권한 스냅샷을 담지 않는다.** 매 요청 principal 을 조회한다 |
| `R60` | §2.15 인증 | 520 | **계정 상태 게이트**를 둔다: `active` / `pending`(승인 대기) / `suspended`(정지) / `rejected`(가입 거절). `active` 외 상태는 로그인·토큰 인증 단계에서 차단한다 |
| `R60-a` | §2.15 인증 | 521 | **default 그룹 소속은 계정이 `active` 로 전환되는 시점**에 이뤄진다. `pending` 사용자는 어떤 그룹 ACL 의 유효 권한도 갖지 않는다 |
| `R60-b` | §2.15 인증 | 522 | 상태별 로그인 시 안내를 정의한다 — `pending`: "승인 대기 중" / `suspended`: "계정이 정지됨" / `rejected`: "가입이 거절됨". 거절 계정은 슈퍼유저가 가입 승인 화면에서 `pending` 으로 되돌려 재심사할 수 있다 |
| `R143` | §2.15 인증 | 523 | **인증 전(pre-auth) 화면은 R23 의 모달 구조를 따르지 않고 전체 화면으로 둔다.** 대상은 **로그인 · 가입 신청 폼(R7-①②) · 설치 마법사(R72)** 다 |
| `R143-a` | §2.15 인증 | 524 | **R7-③(슈퍼유저 직접 등록)은 인증 후 관리 기능이므로 R24 가 정면으로 적용된다.** 별도 화면을 만들지 않고 **설정 모달 › 인스턴스 › `사용자 관리`**(R24-a) 안의 조작으로 둔다 |
| `R144` | §2.15 인증 | 525 | **본인이 자기 비밀번호를 변경할 수 있다.** 소재는 R24-a 개인 구역의 **`계정`** 카테고리이며 **본인만** 할 수 있다 |
| `R145` | §2.15 인증 | 526 | **사용자가 자기 세션을 종료할 수 있다(로그아웃).** 소재는 R144 와 같은 **`계정`** 카테고리다 |
