# wave-8 — 확인 등급 — 파괴적 조작 앞의 마찰

> 설계 발췌. 정본은 `docs/spec/00.decision-log.md` 이며 이 파일은 그 wave 범위의 사본이다.
> 충돌하면 원장이 이긴다.

**목표** — L1·L2·L3 등급 체계와 배정 기준이 서고, 앞 wave 들이 만든 조작 전량에 등급이 얹힌다 — 휴지통·계정·그룹·토큰·권한 배정표, 이동·복사·상속 끊기·넓히기·회수·오프보딩·보존 기간 축소. 확인 화면이 수치를 열 때 재조회하고, 그 흐름이 완전 숨김을 우회하는 정보 통로가 되지 않도록 분모·미도달 건수·첨부 개수가 차단된다.

**요구사항** 33건 · **설계 항목(원장 조항)** 57건

| `R142-a` | §2.1 UI · 에디터 | 164 | **주체 다건 일괄 회수를 허용한다** — R43-1 의 술어를 `IN (…)` 으로 넓히는 것이며 새 조작 종류가 아니다. 적용 범위는 R101-f 를 그대로 따르고, 시스템 그룹이 섞이면 R119·R119-a 의 안내가 **주체별로 각각** 표시된다(묶음 확인으로 접히지 않는다). **`G9` 의 둘째 갈래 종결** |
| `R142-b` | §2.1 UI · 에디터 | 165 | **일괄 조작의 확인은 묶음 1회다.** 항목 단위로 받지 않는다 |
| `R142-c` | §2.1 UI · 에디터 | 166 | **일괄 회수 L3 의 타이핑 토큰은 영향 건수(회수될 `acl_entry` 항목 수)로 한다.** 건수는 R116 으로 확인 시점 재조회하고 R116-a 로 잠기면 토큰도 갱신된다. **`0건` 은 L2 로 강등하는 것이 아니라 실행 자체를 막는다** |
| `R142-d` | §2.1 UI · 에디터 | 167 | **오프보딩(R101-b) ①②③단계는 다건화하지 않는다.** 다건 회수는 **④단계에 한정**하며, 20명 오프보딩은 `①②③ × 20` + `④ 일괄 1회` 다 |
| `R142-e` | §2.1 UI · 에디터 | 168 | **`G9` 등재 사유의 인과 서술을 정정한다** — *"L3 20회를 피하려고 오프보딩을 미루면 안전 장치가 자기 목적을 무너뜨린다"* 는 **심각도가 과장됐다.** ④단계를 미뤄 남는 것은 **즉시 노출이 아니라 휴면 잔존 권한**이다 |
| `R142-f` | §2.1 UI · 에디터 | 169 | **`G26` ③ 과 `G9` 는 같은 자리가 아니다 — 두 결정은 독립이다.** `G9` 를 "일괄 조작 없음" 으로 닫아도 다건 감사 입도 문제는 그대로 남으므로 **R141 계열은 `G9` 와 무관하게 강제된다** |
| `R116` | §2.1 UI · 에디터 | 170 | **확인 다이얼로그를 열 때 표시할 수치를 재조회하고, 직전 값과 다르면 실행을 잠그고 갱신된 값을 보여준다** |
| `R116-a` | §2.1 UI · 에디터 | 171 | 재조회로 수치가 바뀌어 실행이 잠기면 **L3 의 타이핑 토큰도 갱신된 수치로 바뀐다.** 잠금 해제 후에는 새 수치를 입력해야 한다 |
