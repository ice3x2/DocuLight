## 2. 각 행의 스키마 함의

| 조항 | 스키마에 무엇을 정하는가 |
|---|---|
| `R139` | **세 축이 전부다** — `유형` · `참조 감사 행 1..N` · `해소 감사 행`. 시각·대상 노드·행위자·해소 시각·해소자를 **자기 칸으로 갖지 않는다.** `미해소` 는 `해소 감사 행` 이 **비어 있는 상태**이지 별도 칸이 아니다 |
| `R139-a` | 참조는 **감사 행 ID** 다. 경로·시각·행위자를 자기 칸으로 갖지 않으므로 `R124` 위반이 아니다 — **값이 갈릴 자리를 만들지 않는 것이 면제의 조건**이다. 재조정 신규 노드는 `audit_log` 에 `생성` 1행 + 대기열에 그 행을 가리키는 항목 1건 |
| `R139-b` | 행위자는 대기열이 아니라 **감사 행**에 있고, 사람이 아닌 주체는 예약 주체 행(`system:reconciler` 등)이다. 대기열 스키마에 행위자 칸이 없다는 것과 짝이다 |
| `R139-c` | 해소는 **새 감사 행 추가**로만 한다. 원 감사 행은 `R84-a` 대로 불변. **그 해소 감사 행이 곧 `해소 감사 행` 칸**이므로 해소 시각·해소자를 대기열이 따로 갖지 않는다 |
| `R139-d` | 화면 소재(`워크스페이스 관리 › 감사 로그` 안 두 번째 화면). **스키마 제약은 아니다** — 다만 감사 로그 표에 섞지 않는다는 것이 별개 저장소라는 `REL-AUDIT-001` 과 같은 방향이다 |
| `R139-e` | **스코프는 참조 감사 행들의 대상 노드에서 파생한다** — 대기열에 **워크스페이스 칸을 두지 않는다.** 기준의 정본은 `R141` 이고 여기 다시 적지 않는다(`R124`) |
| `R139-f` | 미해소 건수 배지. 조회 요건이지 칸 요건이 아니다 — `해소 감사 행 IS NULL` 로 세어진다 |
| `R139-g` | **이름은 `재조정 대기열`** 이다. 한정어 없는 `감사 목록` 을 지시어로 쓰지 않는다. 테이블·타입·화면 라벨이 이 이름을 쓴다 |

## 3. 확정 계약

### 3.1 칸

| 칸 | 널 허용 | 근거 |
|---|---|---|
| `id` | NOT NULL | 식별자 |
| `kind` (유형) | **NOT NULL** | `R139` 세 축의 첫째 |
| `audit_ref` (참조 감사 행 1..N) | **NOT NULL · 1건 이상** | `R139` — 시각·대상 노드·행위자·해소 시각·해소자의 **유일한 출처**. 비우면 그 다섯이 사라지고 `R139-a` 가 `R124` 면제의 조건으로 든 「값이 갈릴 자리를 만들지 않는다」도 성립하지 않는다 |
| `resolved_audit_ref` (해소 감사 행) | **NULL 허용** | `R139` — `미해소` 는 이 칸이 **비어 있는 상태**다. 별도 상태 칸을 두지 않는다 |

`audit_ref` 가 `1..N` 이므로 **별도 조인 테이블**(`reconciliation_finding_audit_ref`)로 표현한다.
그 테이블에도 **항목당 1건 이상**을 강제한다 — 칸이 NOT NULL 인 것만으로는 0건 삽입을 막지 못한다.

### 3.2 두지 않는 칸 — 금지 목록과 근거 1:1

| 금지 칸 | 근거 조항 | 왜 |
|---|---|---|
| `occurred_at` (시각) | `R139` | 참조 감사 행에서 읽는다 |
| `node_id` (대상 노드) | `R139` | 참조 감사 행에서 읽는다 |
| `actor` (행위자) | `R139` · `R139-b` | 참조 감사 행에서 읽는다. 사람이 아닌 주체도 거기 산다 |
| `resolved_at` (해소 시각) | `R139` · `R139-c` | 해소 감사 행에서 읽는다 |
| `resolver` (해소자) | `R139` · `R139-c` | 해소 감사 행에서 읽는다 |
| `workspace_id` (워크스페이스) | `R139-e` | 참조 감사 행들의 대상 노드에서 파생한다 |
| `status` / `is_resolved` (상태) | `R139` | `미해소` 는 `resolved_audit_ref IS NULL` 이지 별도 칸이 아니다 |
| `path` (경로) | `R139-a` | 경로를 자기 칸으로 갖지 않는 것이 `R124` 면제의 조건이다 |

### 3.3 조회로 얻는 것

| 필요 | 방법 |
|---|---|
| 미해소 목록 | `resolved_audit_ref IS NULL` |
| 미해소 건수 배지 (`R139-f`) | 위 조건 + 열람자 스코프 필터 |
| 스코프 판정 (`R139-e`) | 참조 감사 행들의 대상 노드 → 귀속 워크스페이스. 참조가 둘 이상이고 서로 다른 워크스페이스면 **인스턴스 스코프로 격상** |
| 시각·행위자 표시 | 참조 감사 행과 조인 |

### 3.4 이름 (`R139-g`)

**`재조정 대기열`.** 테이블은 `reconciliation_finding`(`R139` 문면), 코드 타입과 화면 라벨은 이 이름을 쓴다.
한정어 없는 `감사 목록` 을 지시어로 쓰지 않는다 — 그 이름은 `상속 끊김 노드 감사 목록`(`R43-3`)·`감사 로그`(`R84`)와 충돌한다.

## 4. wave-1 이 만드는 범위

`REL-AUDIT-001` 은 **저장소가 별개라는 것**을 정한다. 이 wave 는 그 테이블과 제약을 세우고,
`DR-WORKSPACE-002` 의 `id` 중복 발견이 기재될 자리를 연다.

**화면(`R139-d`)·배지(`R139-f`)·스코프 격상(`R139-e`)은 이 wave 밖이다** — 감사 로그 화면이 뒤 wave 소유다.
다만 **스키마가 그것들을 가능하게 해야 하며**, 위 §3.2 의 금지 칸을 하나라도 두면 뒤 wave 가
`R124` 위반을 안고 시작한다.

## 5. 함정

**`audit_ref` 를 nullable 로 만들고 싶어지는 순간이 온다** — wave-1 에는 `audit_log` 가 없기 때문이다
(`R84` 계열은 뒤 wave 소유). 그때 비우면 `R139` 를 정면 위반한다.

**해법은 참조를 비우는 것이 아니라 감사 행을 쓰는 것이다.** `R139-a` 가 이미 그 형태를 정했다 —
재조정이 신규 노드를 만들면 `audit_log` 에 `생성` 1행을 쓰고 대기열이 그것을 가리킨다.
wave-1 의 `REL-STORAGE-001`(기동 시 재조정)이 발견을 만들므로, **그 발견을 기록할 최소 감사 행 경로가
같은 wave 안에 있어야 한다.**

〔이것이 `REL-AUDIT-001` 과 `REL-STORAGE-001` 을 wave-9 에서 wave-1 로 옮긴 이유와 같은 뿌리다〕

## 6. 확인하지 못한 것

- **`audit_log` 의 스키마를 확정하지 않았다** — `R84` 계열은 이 wave 밖이고, 이 문서는 대기열이 그것을
  **참조한다**는 사실만 정한다. 감사 행의 칸 구성이 정해지면 조인 방식을 다시 봐야 한다.
- **`R141` 의 스코프 기준 문면을 읽지 않았다** — `R139-e` 가 정본을 그쪽으로 넘기고 여기 다시 적지
  말라고 한다(`R124`). 스코프 판정을 구현하는 wave 가 그 조항을 읽어야 한다.
- **참조가 둘 이상일 때의 인스턴스 격상 조건을 코드로 옮기지 않았다** — `R139-e` 가 정하지만 그
  판정이 필요한 화면이 이 wave 에 없다.
