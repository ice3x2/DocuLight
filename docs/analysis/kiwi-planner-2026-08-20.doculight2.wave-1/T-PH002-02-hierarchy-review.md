## 1. 판정 — **깊이 상한이 아니다. 계층의 종류를 닫은 조항이다**

착수 전 구현 가능성 판정 초판이 이 조항을 *"4단계 계층 상한 … 경로 파싱에서 깊이를 세면 된다"* 로
읽었고, 독립 검증이 **CRITICAL** 로 지적했다. 그 지적이 옳다. 근거는 요구사항 자신에 있다.

**요구사항 문면** — *"옵시디언의 볼트에 해당하는 **별도 계층**을 두지 않는다. 노드 계층은
`루트 → 워크스페이스 → 디렉토리 → 문서` 로 끝나며 그 사이에 **중간 계층을 추가하지 않는다.**"*

**Rationale** — *"**기각된 대안을 명시적으로 닫는 조항**이다 — 링크 경계와 권한 경계를 분리하는
**3계층 안(볼트 계층을 따로 두는 안)**은 복잡도 대비 이득이 없어 폐기했다."*

**Implementation Notes** — *"이 조항은 **새 계층을 요구하는 설계 압력**이 들어올 때 먼저 검사하는
관문이다. 계층을 늘리고 싶어지는 전형적 동기는 「링크는 넓게, 권한은 좁게」인데…"*

**원장 `R38`** — *"**볼트에 해당하는 별도 계층을 두지 않는다.** 계층은 `루트 → 워크스페이스 →
디렉토리 → 문서` 로 끝난다."*

세 자리가 같은 것을 말한다 — **닫은 것은 「종류」이지 「개수」가 아니다.** 그리고
`Verification Method` 가 `test` 가 아니라 **`review`** 인 것이 그 성질을 확인해 준다.

### 깊이로 읽으면 제품이 깨진다

`디렉토리` 는 계층의 **한 종류**이고, 디렉토리가 디렉토리를 담는 것은 **새 종류를 만들지 않는다.**
깊이로 읽어 5단계를 거부하면 `워크스페이스/a/b/c.md` 가 막힌다.

- `R40-c` 가 *"문서와 디렉토리는 **실제 이름을 그대로 유지**한다"* 로 옵시디언 호환을 지킨다.
- **옵시디언 볼트는 폴더를 임의 깊이로 중첩한다.**
- `DR-WORKSPACE-001` 이 볼트를 그대로 넣는 것을 요구한다.

즉 깊이 상한은 `R1`·`R3` 이 세운 **이 제품의 존재 이유**와 정면으로 충돌한다.

### AC-4 의 모호성 — 실재하지만 이 해석으로 닫힌다

`AC-4` *"노드 경로·ID 체계·권한 모델은 **4단계를 넘는 조상 체인을 전제하지 않는다**"* 는
깊이 읽기로도 읽힌다. **모호성은 실재한다.**

**닫는 해석** — *"전제하지 않는다"* 는 **모델이 특정 깊이를 가정하고 지어지지 않는다**는 뜻이다.
「4단계를 넘는 체인이 존재하면 거부한다」가 아니다. 체인의 **종류**가 넷(`루트`·`워크스페이스`·
`디렉토리`·`문서`)이고 그 밖의 종류를 전제하지 않는다는 뜻이며, 같은 종류의 반복(중첩 디렉토리)은
새 종류가 아니다.

이 해석이 나머지 세 AC 및 Rationale 과 정합하고, 깊이 해석은 `R40-c`·`DR-WORKSPACE-001` 과
충돌한다. **정합하는 해석을 택한다.**

## 2. AC 별 판정

| **AC-1** | 루트와 워크스페이스 사이에 어떤 중간 계층도 존재하지 않는다 | **충족** | `R40` 이 물리 구조를 `docsRoot/<워크스페이스ID(해시)>/…` **단일 루트 하위 폴더**로 못박는다. wave-1 의 워크스페이스 레이아웃(PH-005)이 그 형태를 그대로 만들며 중간 디렉토리를 끼우지 않는다 |
| **AC-2** | 워크스페이스와 디렉토리 사이에 어떤 중간 계층도 존재하지 않는다 | **충족** | 같은 조항. 워크스페이스 디렉토리 **바로 아래**가 사용자 디렉토리·문서다. `.workspace.json`(`R40-b`)·`.res/`(`R50`)·`.trash`·`.versions` 는 **계층이 아니라 예약 항목**이며 `R64` 가 그것들을 점 접두로 숨긴다 |

| **AC-4** | 노드 경로·ID 체계·권한 모델은 4단계를 넘는 조상 체인을 전제하지 않는다 | **충족** | 종류가 넷으로 닫혀 있고 그 밖의 종류를 전제하는 코드가 없다. **ID 체계는 오히려 깊이 독립적이다** — `DR-STORAGE-003`(`R76`)이 경로 독립 안정 ID 를 두고 *"**경로는 파생 캐시다**"* 로 정하므로, 조상 체인의 길이가 ID·ACL·버전·휴지통 어디에도 들어가지 않는다 |

## 3. 깊이 카운팅 거부 코드 — **0건**

```
grep -rnE "depth\s*[<>]=?\s*[0-9]|MAX_DEPTH|maxDepth" packages/server/src packages/web/src   →  0
```

2026-08-21 실측. 뒤 Task 가 경로 검증을 구현할 때 **이 검사를 다시 돌려야 한다** —
`FR-WORKSPACE-004` 의 경로 총길이 상한은 **바이트 길이 제한**이지 세그먼트 수 제한이 아니다.

## 4. 구현자에게 남기는 함정

**「4단계」라는 말을 보고 세그먼트를 세고 싶어지는 순간이 온다.** 그때 이 문서를 보라.

- 세어야 하는 것은 **종류**(루트·워크스페이스·디렉토리·문서)이고, 그것은 **타입 시스템으로
  표현할 일**이지 런타임 검사가 아니다.
- 경로에 상한을 두는 것은 `FR-WORKSPACE-004` 의 **총길이**(바이트) 뿐이다.
- 중첩 깊이를 거부하면 옵시디언 볼트가 열리지 않는다.

## 5. 확인하지 못한 것

- **`SEC-WORKSPACE-001`·`FR-WORKSPACE-002` 의 본문을 직접 읽지 않았다.** AC-3 판정은 요구사항
  Rationale 의 서술(*"링크 경계라는 개념 자체가 제품에 없다"*)과 두 요구사항의 제목에 기댔다.
  링크·검색을 구현하는 wave 가 그 둘을 읽고 이 판정을 재확인해야 한다.
- **`.workspace.json`·`.res/`·`.trash`·`.versions` 를 「계층이 아니라 예약 항목」으로 판정한 것은
  이 문서의 해석**이다. 원장이 그 낱말로 구별하지는 않는다 — 다만 `R64` 가 점 접두 항목을
  트리에서 숨기므로 사용자가 보는 계층에 들어가지 않는다는 것이 근거다.
- **PH-005 의 워크스페이스 레이아웃 구현이 아직 없다.** AC-1·AC-2 판정은 `R40` 조항과 계획의
  의도에 기댄 것이고, 그 코드가 선 뒤 다시 확인해야 한다.
