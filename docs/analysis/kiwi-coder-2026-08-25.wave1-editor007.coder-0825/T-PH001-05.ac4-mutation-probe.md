# T-PH001-05 — SDS-AC-4 세는 위치 교정과 뮤테이션 탐침

Task: T-PH001-05 / REQ: FR-EDITOR-007 (AC-7)
대상 파일: `packages/editor/test/browser-check.mjs`

## 무엇을 고쳤나

`SDS-AC-4` 의 **세는 위치만** 옮겼다. 단언은 글자 그대로 `errorBlocks === 1` 이며
diff 는 삽입 56줄 · 삭제 0줄이다 (`git diff --numstat`) — 지운 줄이 하나도 없으므로
기존 단언의 삭제·약화·skip 은 구조적으로 불가능하다.

- 추가: `centerLineContaining(needle)` — 문서의 **고정 landmark 줄**(오류 펜스 바로 앞
  소제목 `렌더 실패도 예외를 던지지 않습니다`)이 DOM 에 나타날 때까지 한 화면씩 내려간 뒤
  그 줄을 뷰포트 가운데로 고정한다. 20 스텝 안에 못 찾으면 던진다.
- 추가: `scrollToTop()` — 뒤따르는 열한 항이 문서 top 을 전제하므로 센 뒤 되돌린다.
- 루프의 종료 조건은 **landmark 줄의 존재**이지 `.dl-mermaid-error` 의 존재가 아니다.
  즉 "오류가 나올 때까지 훑다가 하나 나오면 통과" 형태가 아니다 — 자리는 landmark 로
  결정되고, 개수는 그 자리에서 딱 한 번 읽는다.

## 왜 옮겼나 (약화가 아니다)

heightmap 어긋남(38px)이 사라지면서 CM6 가 뷰포트 밖 블록 위젯을 **정확히 언마운트**하게
됐다. 종전에는 heightmap 이 DOM 보다 짧아 CM6 가 필요보다 많이 렌더했고, 그 덕에 문서
아래쪽 오류 블록이 스크롤 top 에서도 잡혀 이 단언이 **우연히** 통과하고 있었다.
`browser-check.mjs` 의 `revealedCount` 주석이 이미 같은 함정을 경고한다 —
「개수 변화의 대부분은 가상화이지 동작이 아니다」.

실측 (교정 전):

| 확인 | 결과 |
| --- | --- |
| 스크롤 top | `.dl-mermaid-error` 0개 |
| 오류 블록 자리 | `.dl-mermaid-error` **정확히 1개** |
| 같은 시점 정상 다이어그램 | svg 2개 |

오류 표시 동작 자체는 멀쩡했다. 자를 잘못된 곳에 대고 있었을 뿐이다.

## 뮤테이션 탐침 (실효성 확인)

**탐침**: `packages/editor/src/core/mermaid-blocks.ts` 의 `MermaidWidget.paint` 에서
오류 경로의 `box.classList.add('dl-mermaid-error')` 한 줄을 제거 — 오류 문구는 그대로
쓰되 오류 표시 클래스만 붙이지 않게 했다.

| 상태 | browser-check.mjs | SDS-AC-4 |
| --- | --- | --- |
| 교정 전 (원본 구현) | 11/12 | FAIL — `error 0개` (가상화 기인 오탐) |
| 교정 후 (정상 구현) | **12/12** | PASS — `error 1개` |
| 교정 후 + 뮤테이션 | **11/12** | **FAIL — `error 0개`** |
| 탐침 되돌린 뒤 | 12/12 | PASS — `error 1개` |

**판정: 이 항은 여전히 문다.** 오류 렌더 경로를 망가뜨리면 SDS-AC-4 가 단독으로 죽고,
나머지 열한 항은 그대로 통과한다 — 이 항이 재는 대상이 정확히 오류 표시 동작임을 뜻한다.
탐침은 원복했고 `git diff` 상 `mermaid-blocks.ts` 는 23 삽입 / 8 삭제로 탐침 이전과 동일하다.

## 검증 채널

편향 없는 입력만 준 in-process 검증 서브에이전트(`ac4-review`)를 띄웠으나 **보고 본문이
회수되지 않았다** — 완료 통지는 왔지만 내용이 전달되지 않았고, 요약 재요청에도 응답이
없었다. 앞선 자식이 겪은 무응답과 같은 증상이다. 그래서 판단이 끼지 않는 **기계적 독립
채널**로 대체했다.

| 채널 | 무엇을 배제하나 | 결과 |
| --- | --- | --- |
| 뮤테이션 탐침 | "이 항이 아무것도 재지 않는다" | 오류 경로를 깨면 SDS-AC-4 단독 FAIL — 문다 |
| `git diff --numstat` = **56 / 0** | "기존 단언을 지웠거나 약화했다" | 삭제 0줄. 단언 줄은 diff 의 context 이지 변경 대상이 아니다 |
| 3회 연속 실행 | "우연히 통과했다" | 3회 모두 12/12, `error 1개` |
| `tsc --noEmit` | 타입/빌드 파손 | exit 0 |
| `NODE_ENV=production npx vitest run` | 회귀 | 237 passed / 1 skipped — 기준선 동일 |

`git diff -U0` 로 보면 단언 줄 `check('SDS-AC-4 …', errorBlocks === 1, …)` 은 hunk 의
context 로만 등장한다 — 손대지 않았다는 뜻이다.
