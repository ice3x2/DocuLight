### 1.1 탐침 ④ 가 증명한 것

판정 ②(실제 제스처)와 판정 ⑤(데코레이션 규칙)는 **서로 다른 축**을 잰다.
`ignoreEvent` 를 되돌리면 커서 진입 경로만 끊기고 데코레이션 규칙은 그대로이므로
② 는 죽고 ⑤ 는 산다. 둘이 함께 죽었다면 두 판정이 같은 것을 재고 있다는 뜻이었을 것이다.

### 1.2 어느 축도 재어지지 않은 채 남지 않았다

탐침 ①②④ 는 E2E 판정을, 탐침 ③ 은 `read-only.test.tsx` 를 각각 죽였다.
탐침 ⑤ 만 아무것도 죽이지 않았고, 그것은 시험의 결함이 아니라 **되돌릴 동작 자체가 없었다**는 뜻이다(§3).

## 2. OQ-03 — 탐침 ⑤ 의 측정 수단

계획이 지정하지 않았던 「키 입력이 문서를 건드리는지」의 측정을 이렇게 정했다.

1. 표를 화면에 들인 뒤 **표 밖**(인용문 줄)을 클릭해 CM6 선택을 표 밖에 둔다.
2. `document.querySelector('.cm-atomic-table-cell-source').focus()` 로 칸에 DOM 초점을 준다 —
   이것이 코드 주석이 지목한 바로 그 상태다(칸이 DOM 초점을 쥐고 CM6 선택은 딴 곳에 있다).
3. 키 하나(`Z`)를 누른다.
4. `view.state.doc.toString()` 을 전후 비교해 **변화 유무**와 **변화가 일어난 줄**을 잰다.
   더해서 CM6 선택 머리의 줄도 전후 비교한다.

누출의 정의: 변화가 **CM6 선택이 있던 표 밖 줄**에 나타나면 키 입력이 문서로 샌 것이다.
변화가 **표 안 칸 줄**에 나타나면 칸 자신의 편집 경로가 정상으로 흐른 것이다.

## 3. 탐침 ⑤ 의 실측과 그 함의 (보고 — 계획 조항은 고치지 않았다)

| | 구현 원본(대조군) | 탐침 ⑤(모든 이벤트 개방) |
| --- | --- | --- |
| 칸이 DOM 초점을 쥐었나 | `activeIsCell: true` | `activeIsCell: true` |
| `view.hasFocus` | `false` | `false` |
| CM6 선택 줄 (키 입력 전 → 후) | 92 → 92 | 92 → 92 |
| 문서가 바뀌었나 | 예 | 예 |
| 바뀐 줄 | **94 (표 안)** | **94 (표 안)** |
| 표 밖 선택 줄이 바뀌었나 | 아니오 | 아니오 |
| 결과 문면 | `| Z표 | 편집 |` | `| Z표 | 편집 |` |

변형이 실제로 서빙되는지는 따로 확인했다 —
`curl -s http://localhost:3399/src/vendor/atomic-editor/table-widget.ts` 가 변형된 `ignoreEvent` 를 돌려준다.
따라서 이 null 결과는 「변형이 반영되지 않았다」가 아니다.

**함의.** `ignoreEvent` 의 포인터 한정에 붙은 사유 — 「모든 이벤트를 열면
칸 초점 상태의 키 입력이 문서를 대신 편집한다」 — 는 이 측정으로 **재현되지 않는다.**
기제는 이렇다. 칸의 `contenteditable` 이 DOM 초점을 쥐면 `view.hasFocus` 가 거짓이고,
CM6 는 자기 `contentDOM` 이 초점을 쥐지 않은 동안 키 입력을 문서 편집으로 처리하지 않는다.
`ignoreEvent` 는 **위젯을 거쳐 가는** 이벤트를 걸러 줄 뿐, 초점이 어디 있느냐를 바꾸지 못한다.

이 사실이 무엇을 뜻하는지 둘로 갈라 적는다.

- 포인터 한정 자체는 **해롭지 않고 틀리지도 않았다.** 걷어도 시험이 깨지지 않고 동작도 같다.
- 다만 그 한정에 적힌 **사유**는 이 저장소의 현재 위젯에서는 근거가 없다.
  계획 `§5.1 R-02` 의 「표는 안에 편집 서브시스템이 있어 모든 이벤트를 열면 칸 초점 상태의
  키 입력이 문서로 샌다」와 `table-widget.ts` 의 `ignoreEvent` 위 주석이 같은 주장을 담고 있다.

계획 조항의 수정은 이 Task 의 권한 밖이므로 **고치지 않고 보고만 한다.**
덧붙일 범위 한정: 이 측정은 인쇄 가능한 문자 하나에 대한 것이며, 주석이 지목한 상태
(칸이 DOM 초점을 쥐고 CM6 선택은 딴 곳) 를 정확히 재현한 위에서 이뤄졌다.
`paste` · IME 조합 같은 다른 입력 경로는 재지 않았다.

## 4. 판정 ③ 의 하향 (계획 §3.PH-001.T-PH001-03 ⑥)
