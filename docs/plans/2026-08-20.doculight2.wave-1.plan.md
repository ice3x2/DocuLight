## §1 개요

### 1.1 목표

저장소에 루트 `package.json` 과 npm workspaces 를 세우고, Express 백엔드와 Vite/React/TS SPA 를 한 Node 프로세스로 띄운다. 파일시스템(`docsRoot`)과 SQLite 두 저장소를 열고, 모든 노드에 경로 독립적인 랜덤 안정 ID 를 붙이며, 워크스페이스 물리 레이아웃과 사이드카·이름 검증·서빙 거부 규칙을 세운다. 최초 기동 시 기본 워크스페이스가 생긴다.

현재 저장소의 실측 상태 — 루트에 `package.json` 이 없고 백엔드가 0줄이며 기존 패키지는 `packages/editor` 하나다. 이 wave 는 **백지에서 시작한다.**

### 1.2 범위

요구사항 **24건** · 수용 기준 **118개**. Stability 는 stable 22 · evolving 2(`CON-ARCH-009` · `FR-WORKSPACE-004`)이며 draft·deprecated 는 0건이라 착수 게이트에 걸리는 요구사항이 없다.

scope 별 분포 — `ARCH` 7건(AC 30) · `AUDIT` 1건(AC 8) · `STORAGE` 9건(AC 38) · `WORKSPACE` 7건(AC 42). **이 분포는 인벤토리에서 계산한 값이다.**

**wave 경계가 두 자리에서 고쳐진 상태로 들어왔다.** 판정 문서 §3 B-5 가 `REL-STORAGE-001`(재조정)과 `REL-AUDIT-001`(재조정 대기열)을 wave-1 로 옮기라고 권고했고 이 계획의 입력 인벤토리는 그것이 반영된 24건이다. 그래서 `SEC-STORAGE-006` AC-3(재조정 전까지 서빙되지 않는다)과 `DR-WORKSPACE-002` AC-6(격리 사실이 대기열에 기재된다)이 이 wave 안에서 닫힌다.

### 1.3 제외사항

- `packages/editor/src/**` 를 **건드리지 않는다.** 이 wave 가 그 패키지에 하는 일은 루트 워크스페이스 편입과 `vite.config.ts` 의 `test.include` 교정뿐이다.
- **인증·권한(ACL)·감사 로그 화면·트리 UI·에디터 화면·첨부·휴지통·버전** 은 이 wave 밖이다. 그것들에 걸린 AC 는 §5.4 에 유예로 올렸다.
- **DocuLight 1.0 저장소는 읽기 전용 참고**이며 어떤 파일도 수정하지 않고 배포 구성을 복사하지 않는다.
- **`docs/spec/*.srs.md` 를 손으로 고치지 않는다.** 요구사항 갱신이 필요한 자리(T-PH002-01)는 speckiwi MCP mutation 으로만 처리한다.

### 1.4 전제조건

- Node v24.16.0 · npm 11.5.2 · speckiwi 2.13.1 이 동작한다(실측).
- 활성 target 은 `phase-1` 이며 wave 는 요구사항 ID 부분집합으로 범위를 한정한다(C-23). wave 전용 target 을 새로 만들지 않는다.
- 착수 전 결정 셋(§5.5 · PH-002)이 코드 작성보다 먼저 닫힌다.
- 개발 서버 기본 포트는 3399 다(C-09). 배치는 §5.1 RISK-09 에 적었다.

### 5.2 Open Questions

#### OQ-01 — `CON-WORKSPACE-001` AC-4 를 경로 깊이 상한으로 읽는가

- **판정** — 아니다 — 계층의 **종류**를 닫은 조항으로 읽는다. 깊이를 세어 거부하는 코드를 만들지 않는다.
- **근거** — 요구사항 문면과 AC-1~AC-3 이 전부 "중간 계층" 형태이고 Rationale 은 기각된 3계층(볼트) 안을 닫는 이야기뿐이며 디렉토리 중첩 깊이가 한 글자도 나오지 않는다. Verification Method 가 `review` 로 코드 강제 대상이 아니다. 깊이로 읽으면 `워크스페이스/a/b/c.md` 가 막히고 그것은 `DR-WORKSPACE-001` AC-7(볼트를 그대로 넣어도 내부 경로·파일명 무변형)과 `R1`·`R3` 이 세운 제품 정의를 깬다.
- **남는 것** — AC-4 "4단계를 넘는 조상 체인을 전제하지 않는다" 는 깊이 읽기로도 읽힌다. 모호성은 실재하며 원의도는 조항 저자만 확정할 수 있다. 이 판정은 근거를 명시한 해석이지 저자 확인이 아니다.
- 사용자 확인 필요: **예** · 착수 차단: 아니오

#### OQ-02 — `docsRoot` 절대 경로 예산 경고를 조항으로 올릴 것인가

- **판정** — wave-1 에서 구현하지 않는다.
- **근거** — 기동 시 `docsRoot` 절대 경로 길이를 재서 남는 예산이 상한 미만이면 경고를 내는 것은 RISK-03 의 최소 방어이지만, 그 동작을 덮는 AC 가 `FR-WORKSPACE-004` 에도 다른 어느 요구사항에도 없다. SRS 가 덮지 않는 동작을 구현하지 않는다는 규칙이 우선한다.
- **남는 것** — 조항을 신설할지는 사용자 판단이다. 신설하면 뒤 wave 에서 구현한다.
- 사용자 확인 필요: **예** · 착수 차단: 아니오

#### OQ-03 — `OPS-STORAGE-001` 을 문서화로 닫을 것인가 스크립트로 닫을 것인가

- **판정** — 둘로 가른다 — AC-1·AC-4 는 운영 런북(문서)으로, AC-2·AC-3 은 자동 테스트로 닫는다.
- **근거** — 요구사항 Implementation Notes 가 "운영 절차 요건이라 자동 검증보다 절차 검토가 검증 방법이다. 복원 후 스캔이 도는지 자체는 재조정 요구의 시험으로 함께 확인된다" 라고 두 축을 이미 갈라 놓았다. `REL-STORAGE-001` 이 wave-1 로 들어와 재조정이 같은 wave 에 있으므로 AC-2·AC-3 은 실제로 코드로 닫힌다. 백업 도구·주기·보관 위치는 원장이 정하지 않았으므로 스크립트로 지어내면 원장에 없는 결정을 코드에 굳히게 된다.
- **남는 것** — 백업 자동화 스크립트를 둘지는 배포 환경이 정해진 뒤의 판단이다.
- 사용자 확인 필요: 아니오 · 착수 차단: 아니오

#### OQ-06 — 비-ASCII 케이스 폴딩 규칙을 무엇으로 하는가

**예약 장치 이름 — 채택 목록(28개, Microsoft Learn 2025-04-11 판 기준)**

`CON` · `PRN` · `AUX` · `NUL` · `COM1`~`COM9` · `COM¹` · `COM²` · `COM³` · `LPT1`~`LPT9` · `LPT¹` · `LPT²` · `LPT³`

- 상첨자 변종 여섯을 포함하는 근거 — Microsoft 는 ISO/IEC 8859-1 상첨자 `¹`·`²`·`³` 를 숫자로 인식해 `COM#`·`LPT#` 의 일부로 취급하며 그 이름들도 모든 디렉토리에서 예약된다. Linux 에서 만든 `COM¹.md` 가 정확히 이 목록이 막아야 하는 사례다.
- **이 목록을 「전량」이라고 적지 않는다.** 채택 시점 판본 기준의 목록이며, 구현자는 블록리스트를 확정하기 전에 출처 판본을 다시 대조한다. `COM0`·`LPT0` 은 대조한 판본의 목록에 없어 넣지 않았다 — 다툼이 있는 자리이므로 값을 확정할 때 근거 판본을 함께 적는다.
- **판정은 확장자를 뗀 basename 에 대해 유니코드 기본 케이스 폴딩으로 한다.** `CON.md` 도 `con.txt` 도 Windows 는 장치 이름으로 해석한다. 이 세부는 요구사항이 "구현 판단으로 남긴다" 고 적은 자리다.
- Windows 제약을 강제하는 근거는 요구사항 자신의 Rationale 이다 — 워크스페이스 계층은 해시 디렉토리명으로 문제를 회피하지만 문서·디렉토리 계층은 실제 이름을 유지하므로 같은 문제가 그대로 노출되고, **그 계층에서는 이 검증이 유일한 방어선**이다. 여기에 옵시디언 호환 축이 더해진다 — 볼트는 OS 를 옮겨 다니고, Linux 에서 만든 `aux.md` 는 그 볼트를 Windows 에서 열 수 없게 만든다. **원장은 서버가 Windows 에서 돈다고 말하지 않는다** — 이 값의 목표는 「어느 OS 에서도 열리는 볼트」이며 그 목표 자체가 조항으로 서 있지는 않다.

#### ② 최대 이름 길이 — **UTF-8 인코딩 후 255바이트**

- 실질 제약은 **ext4 의 255바이트**다(`ext4_dir_entry_2` 의 `name_len` 이 `__u8`). 255 UTF-8 바이트는 NTFS 의 UTF-16 코드 단위 255 를 어떤 조합에서도 넘지 않는다(ASCII 최악의 경우 정확히 255).
- **단위가 바이트인 것이 핵심이다.** 한글은 UTF-8 3바이트이므로 ext4 에서 85자에 걸리고 NTFS 에서는 255자까지 들어간다. 바이트로 재야 어느 파일시스템에서도 통과한다.
- **대가를 명시한다** — 한글 이름은 실질 85자로 제한된다. 사용자에게는 "너무 긴 이름" 이라는 안내가 나가는데 화면에 보이는 글자 수는 85 다. AC-7 이 거부 응답에 위반 규칙을 알리라고 요구하므로 **바이트 한계임을 문구에 드러내야 한다.**
- macOS/APFS 는 이 계산에 근거로 쓰지 않았다 — 255 는 APFS 자체의 한계가 아니라 macOS 가 거는 제한이고 출처마다 단위가 갈린다. 결론은 ext4 와 NTFS 만으로 선다.

#### ③ 경로 총길이 상한 — **워크스페이스 루트 기준 상대 경로 UTF-8 512바이트**

**측정 기준을 상대 경로로 두는 근거** (판정 문서 §2.2 ③ 에서 철회되지 않은 두 근거)

1. 워크스페이스 디렉토리명이 해시라 길이가 고정되므로 예산 계산이 결정적이다.
2. `docsRoot` 절대 경로가 배포마다 달라져도 볼트 자체는 이식 가능하다. 절대 경로로 검사하면 같은 볼트가 배포 환경마다 다른 판정을 받는다.

**255 를 쓰지 않는 근거**

판정 문서가 255 를 정당화한 세 번째 근거(*"4단계 계층 상한이 이미 깊이를 묶으므로 255 는 넉넉하다"*)는 철회됐다 — `CON-WORKSPACE-001` 은 깊이를 묶지 않는다(OQ-01). 중첩이 자유로우면 한글 디렉토리 서너 겹으로 255바이트에 닿고, 그러면 `DR-WORKSPACE-001` AC-7(볼트를 그대로 넣어도 내부 경로·파일명이 변형되지 않는다)이 깨진다.

**512 를 고르는 근거**

상한의 목적은 이식성 보장이 아니라 병리적 입력 차단이다 — 이식성 보장은 원리적으로 불가능하다(RISK-03). 그렇다면 값은 **이름 상한과의 정합성**에서 도출된다: 경로 상한이 이름 상한(255바이트)의 두 배에 못 미치면 **AC-5 가 허용하는 이름을 AC-6 이 거부하는 자기모순**이 생긴다 — 상한 길이의 디렉토리 하나 아래에 상한 길이의 파일 하나를 둘 수 없기 때문이다. `255 × 2 + 2`(구분자 여유) = **512** 가 두 AC 를 동시에 성립시키는 최소 값이며, 그보다 큰 값을 고를 근거는 원장에 없다.

**남는 것** — 이 값은 Windows `MAX_PATH` 를 보장하지 않는다. `docsRoot` 절대 경로가 길면 상대 경로가 512 안에 있어도 파일시스템 호출이 실패할 수 있다. 기동 시 예산 경고가 최소 방어이나 그 동작을 덮는 AC 가 없어 이 wave 에서 구현하지 않는다(OQ-02).

## §6 부록

### 6.1 커버리지 판정 규칙

- **covered** — wave-1 이 그 AC 에 대한 검증 산출물(테스트·명령·검토 기록)을 만든다. AC 가 이름으로 드는 주체 일부가 wave-1 에 없더라도 **존재하는 주체에 대해 실제로 시험되면** 커버로 센다. 그 경우 Task 의 `dod` 가 잔여를 적고 §5.1 의 위험이 재판정을 예약한다.
- **deferred** — 그 AC 에 대한 검증 산출물을 wave-1 이 **전혀** 만들 수 없다. §5.4 에 사유와 소유 예상을 함께 적고, 사이드카에서는 `ac_deferred` 와 `deferred_ac[]` 가 그 사실을 유지하며 `missing_ac_ids` 에도 반영된다(스키마 항등식).
- **사유 없는 누락** — 이 계획에서 0건이다.
- 세 값의 합이 `ac_total` 과 같은지, `stable` 요구사항에 사유 없는 누락이 있는지는 사이드카 생성 시점에 기계로 검사했다. 검사에 걸린 건은 0건이다.

### 6.2 금지된 확장 — 계획이 하지 않은 것

- **SRS 가 덮지 않는 동작을 Task 로 만들지 않았다.** `docsRoot` 예산 경고(OQ-02)가 대표적이다 — 유용하지만 AC 가 없어 넣지 않았다.
- **`R139` 대기열의 참조 감사 행을 nullable 로 만들지 않는다.** 비우면 시각·대상 노드·행위자·해소 시각·해소자 다섯 값의 유일한 출처가 사라져 `R139` 를 정면 위반하고, `R139-a` 가 준 `R124` 면제의 조건도 사라진다. 그래서 wave-1 이 최소 `audit_log` 를 함께 연다(OQ-08 · RISK-02).
- **디렉토리 중첩 깊이를 세어 거부하는 코드를 만들지 않는다**(OQ-01). T-PH002-02 의 검토가 그 부재를 확인한다.
- **`packages/editor` 의 테스트 작업량을 미리 추정하지 않았다.** T-PH001-03 이 켜고 러너가 보고하며, 그 결과의 처리는 T-PH001-04 가 별도로 받는다(RISK-01).
