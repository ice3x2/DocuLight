## §1 개요

### 1.1 목표

`FR-EDITOR-007` AC-7 의 **드러나는 절반**을 세운다. 라이브 프리뷰에서 커서를 표에 올리면 그 표의 마크다운 원문(`|` 와 `---`)이 드러나야 하는데, 지금은 어떤 수단으로도 드러나지 않는다.

숨는 절반은 이미 동작한다. 이 계획은 **드러나는 절반 하나만** 다루되, 그것이 성립하려면 **두 축**이 함께 서야 한다.

| 축 | 지금 상태 | 근거 |
| --- | --- | --- |
| (a) 선택이 표에 겹치면 데코레이션을 걷는다 | 없다 — `table-widget.ts:1313` 의 `if (!tr.docChanged) return deco;` 가 순수 선택 이동을 버리고, `buildTableWidgets`(1223-1256)는 선택을 보지 않는다 | 실측 |
| (b) 사용자가 표 줄에 커서를 **놓을 수 있다** | 없다 — `TableWidget.ignoreEvent()`(708-710)가 무조건 `true` 라 CM6 가 위젯 안 클릭에 관여하지 않고, 칸 편집 dispatch 세 자리(936 · 1087 · 1132)도 `changes:` 만 보내 `state.selection` 이 표 밖에 남는다 | 실측 |

**(a) 만 세우면 AC-7 은 성립하지 않는다.** 커서가 표에 닿을 길이 없으므로 데코레이션을 걷는 조건이 영영 참이 되지 않는다. 이 계획의 초판이 (a) 만 다뤘고 독립 검증이 그 누락을 잡았다.

### 1.4 전제조건 / 가정

**착수 전에 정해야 했던 결정 하나를 아래로 확정한다.** 이것이 `Wave 2-a` 의 `DI-W1-02` 다.

> **라이브 프리뷰에서는 원문 노출이 칸 직접 편집보다 우선한다.**

근거 넷이다.

1. **AC-7 의 문면** — 「그 줄에 커서를 올리면 원문이 드러난다」. 예외 조항이 없다.
2. **`FR-EDITOR-003` 의 Rationale** — 「라이브 프리뷰에서는 표 구분선·각주 정의 같은 원문이 **화면에서 사라지는데**, 소스 모드가 없으면 그 원문을 고칠 수단이 제품에 없다」. 제품이 의도한 라이브 프리뷰 의미론을 그 조항이 스스로 적고 있다.
3. **`FR-EDITOR-001`(옵시디언 동일성)** — 옵시디언은 커서가 표에 들어가면 표의 마크다운 원문을 드러낸다.
4. **대안의 대가** — 칸 편집을 지키려면 원장 §4 수용 기준 2 가 「`R16-a` 가 정한 요소 **전부**」로 예외 없이 못박고 있어 **원장 개정까지** 필요하다. 그것은 목표를 향해 가는 것이 아니라 목표를 낮추는 것이다.

**이 결정은 (b) 축의 구현 지시다.** 칸을 클릭했을 때 칸 편집기가 그 자리를 붙잡는 대신 커서가 문서의 그 자리로 들어가야 한다. 결정을 §1.4 에만 적고 Task 로 옮기지 않으면 결정하지 않은 것과 같다.

**그 수단은 저장소에 이미 선례가 있다.** `packages/editor/src/core/mermaid-blocks.ts:139-142` 의 `ignoreEvent(event)` 가 **편집 모드에서 `false` 를 돌려주고**, 그 앞 주석이 이렇게 적는다 — 「읽기 전용에서는 CM6 의 마우스 처리를 막아 캐럿이 블록 안으로 들어가지 않게 한다. **편집 모드에서는 클릭으로 원문이 열리는 것이 라이브 프리뷰의 정상 동작이므로 CM6 에 넘긴다.**」

⚠️ **표는 그 선례를 그대로 베끼면 안 된다.** mermaid 위젯은 안이 비어 있지만 **표 위젯은 안에 `contenteditable` 편집 서브시스템을 갖고 있다**(`makeCell` 713-786 · `attachCellEditing` 786-903). 편집 모드에서 `ignoreEvent` 를 **모든** 이벤트에 열면, 칸에 초점이 남은 상태의 `keydown` 이 CM6 키맵으로 새어 문서를 건드린다 — 컨텍스트 메뉴가 행을 더한 뒤 `firstSource.focus()` 로 칸에 초점을 남기는 경로가 실제로 그렇다.

**그래서 개방은 포인터 이벤트로 한정한다** — `mousedown` 과 `click` 에만 `this.readOnly` 를 돌려주고(읽기 전용에서는 종전대로 막는다) 그 밖의 모든 이벤트에는 `true` 를 돌려준다. 클릭만 CM6 로 넘어가 커서 진입이 서고, `keydown`·`beforeinput`·`paste` 는 종전대로 위젯 안에 갇힌다.

⚠️ **칸 안에서 손으로 `selection` 을 dispatch 하는 길은 쓸 수 없다.** CM6 의 `view.hasFocus` 는 `root.activeElement === contentDOM` 일 때만 참인데(`@codemirror/view` `index.js:8611`), 칸을 클릭하면 초점이 칸 안쪽 `contenteditable` div 로 가서(`table-widget.ts:726-729 · 899-902`) `hasFocus` 가 거짓이 된다. 그러면 바로 아래의 초점 게이팅이 노출을 막아 **판정이 영영 green 이 될 수 없다.** `ignoreEvent` 를 편집 모드에서 열어 CM6 가 클릭을 처리하게 하면 초점이 `contentDOM` 에 남아 두 제약이 함께 성립한다.

**충돌하는 요구는 없다.** `phase-1` 안에서 표 위젯의 칸 편집을 재는 요구는 존재하지 않는다(SRS 전수 실측).

#### 반드시 지킬 구현 제약 하나 — 초점 게이팅

**순수 선택 판정만으로 구현하면 기존 시험이 죽는다.** `packages/editor/src/vendor/atomic-editor/__tests__/read-only.test.tsx:39` 의 fixture 는 문서 **전체가 표**(`| A | B |\n| --- | --- |\n| 1 | 2 |`)라, 기본 선택 위치 0 이 곧 표 안이다. `code-blocks.ts` 식 순수 `selectionTouches` 를 쓰면 그 시험들에서 표가 언제나 드러나 `.cm-atomic-table-cell-source` 를 찾지 못한다.

그래서 같은 vendor 파일인 `inline-preview.ts`(376-393 · 898-966)의 방식을 따른다 — **`view.hasFocus && !readOnly` 로 게이팅**하고 선택이 움직일 때 다시 그린다. CM6 는 마운트 시 자동으로 초점을 잡지 않으므로(`AtomicCodeMirrorEditor.tsx:397`) 이 게이팅이 그 시험들을 살린다. `live-preview.test.tsx` 의 `reveal()` 헬퍼가 선택을 옮기기 **전에** `view.focus()` 를 부르는 이유도 그것이다.

⚠️ `table-widget.ts` 는 `StateField` 라 `view.hasFocus` 를 직접 볼 수 없다. 초점을 상태로 들여오는 수단이 필요하며 **`EditorView.focusChangeEffect`** 가 그 자리다 — `@codemirror/view` 6.43.9 의 `index.d.ts:1255` 에 실재함을 확인했다.

#### 검증 수단은 브라우저 E2E 이고, 커서는 **실제 제스처**로 넣는다

`packages/editor/test/live-preview.test.tsx:265-268` 의 `it.skip` 은 happy-dom 재진입 문제로 막혀 있고, 251-264 행의 주석이 **「통과시키려 손대면 재는 대상이 바뀐다」**고 경고한다. 그 경고를 무시하지 않는다 — 그 스킵은 그대로 두고, 저장소 선례인 `packages/editor/test/browser-check.mjs` 의 모양으로 **실제 브라우저 시험을 새로 세운다.** `FR-EDITOR-007` 의 `Verification Method` 도 `Playwright E2E` 다.

**커서를 넣는 수단이 판정의 핵심이다.** `dispatch({selection})` 으로 커서를 넣으면 위 (b) 축의 결함을 구조적으로 우회해, 시험이 전건 green 이어도 사용자는 여전히 원문을 볼 수 없다. 선례가 그 반대로 되어 있다 — `browser-check.mjs:60` 은 같은 모양의 항을 `page.locator('.dl-mermaid').first().click()` 이라는 실제 클릭으로 잰다. 그래서 이 계획의 **AC-7 본 판정은 실제 제스처**(칸 클릭 · 화살표 이동)이고, `dispatch({selection})` 판정은 「데코레이션 규칙」을 재는 **보조 판정**으로 이름을 갈라 남긴다.

**포트는 3399 그대로다.** `packages/editor/vite.config.ts:28` 의 `server.port` 가 3399 이고 `browser-check.mjs` 가 그 주소에 붙는다. 저장소 `CLAUDE.md` 도 3399 를 기본으로 규정한다. 새 시험은 **서버를 띄우지 않고 이미 떠 있는 3399 에 붙는다** — 선례와 같은 구조다.

⚠️ **3399 에 뜨는 것이 둘이다.** 저장소 루트의 `npm run dev` 는 `package.json:14` 상 `npm run dev --workspace @doculight/web` 이라 **web 앱**을 3399 에 띄우고(`packages/web/vite.config.ts:44`), editor 데모는 `packages/editor` 의 `dev` 스크립트가 같은 3399 에 띄운다. 둘을 동시에 띄울 수 없고, 새 시험이 붙어야 하는 것은 **editor 데모** 쪽이다.

그래서 이 계획의 브라우저 시험을 돌리는 명령은 아래 하나로 고정한다.

```bash
# 터미널 1 — editor 데모 (루트의 npm run dev 가 아니다)
npm run dev --workspace @doculight/editor

# 터미널 2
cd packages/editor && npm run test:browser:table
```

시험은 붙은 화면이 정말 editor 데모인지 **스스로 확인한다** — 데모에만 있는 표식(`.demo-toggle`)이 없으면 판정을 내리지 않고 「editor 데모가 3399 에 떠 있지 않다. `npm run dev --workspace @doculight/editor` 로 띄우라」는 안내와 함께 종료한다. 확인하지 않으면 web 앱 화면에서 표를 못 찾은 것을 AC-7 실패로 오독한다.
