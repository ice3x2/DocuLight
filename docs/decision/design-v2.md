- 결정일: 2026-09-23
- 상태: 사용자 승인 · 시각 디자인 확정 · 기존 요구와 부딪히는 여덟 건도 같은 날 사용자가 결정
- 승인 내용: “네, 이렇게 갑니다. 디자인 시안을 이렇게 고정합니다.”
- 승인 시안: [디자인 v2 HTML](./design-v2.html)
- 대체하는 결정: 2026-09-16 [신문지 테마 결정](./README.md)과 그 후속 가이드 세 문서

## 배경

사용자는 기존 신문지 디자인이 「RBAC 을 지원하는 온라인 옵시디언」이라는 제품 방향에 미치지 못한다고 평가했다. v2 는 옵시디언의 화면 문법(리본, 파일 탐색기, 탭, 설정 행, 빠른 전환 창)을 따르되, 옵시디언의 보라색 대신 도쿠위키처럼 옅은 누런 톤을 쓴다. 첫 시안을 본 사용자가 「약간 덜 누리끼리하게」를 요청해, 메뉴 채도를 아래 파생 규칙의 값으로 낮췄다.

## 확정 사항

### 서체

- 화면 전체에 나눔고딕 하나를 쓴다. 코드, 마크다운 소스, PAT 처럼 고정폭이 필요한 값에만 나눔고딕코딩을 쓴다. 기존 요구는 고정폭만 정하고(`IR-EDITOR-002` AC-1), 나눔고딕코딩은 시안에서 고른 서체다.
- 신문지 테마의 명조체 제목은 쓰지 않는다.
- 크기 단계는 12 · 13 · 14 · 16 · 21 · 30px 를 기본으로 한다. 본문은 16px, 행간 1.75 다. 시안의 대화상자 제목(17px), 정하지 않은 H3 크기, 시안에서 의도와 달리 14px 로 그려지는 인용 크기는 SRS 반영 때 정한다.

### 색

- 누런 톤은 **메뉴 영역**(리본, 사이드바, 탭 바, 상태 바, 오른쪽 패널)의 바탕에 쓴다. 문서, 대화상자, 입력칸, 컨텍스트 메뉴의 바탕은 흰색(`#FFFFFF`)이고, 어두운 테마에서는 `#1F1F1D` 다.
- 흰 바탕 영역에도 강조색을 아주 옅게 섞은 `--accent-soft` 가 좁은 곳에 쓰인다: 태그, 라이브 편집의 현재 줄, 컨텍스트 메뉴 항목 위에 올렸을 때, 폴더 고르기 창의 선택 항목, 세그먼트 선택, 끄는 동안 커서 옆의 결과 표시. 밝게에서는 여섯 프리셋 모두 이 색이 메뉴 바탕과 거의 같으므로(메뉴 밝기 기본값에서 대비 1.00~1.02:1, ±2 단계에서도 1.12:1 이하), 구현 때 흰 바탕 영역에서 메뉴 색이 넓게 번져 보이지 않는지 확인한다.
- 강조색은 주 버튼, 포커스, 선택, 태그, 링크, 인용 막대, 켜진 토글과 체크박스, 워크스페이스 표식, 활성 아이콘에 쓴다.

### 사용자별 기본 색상

- 개인 설정의 외관 항목에서 사용자마다 고른다. 테마 선택(밝게 · 어둡게 · 시스템 따라)과 그 기본값(시스템 따라, `IR-SHELL-004` AC-5)은 기존대로 둔다. 시안의 기본값이 「밝게」인 것은 시연용이다. 시안의 라벨(외관, 밝게 · 어둡게 · 시스템 따라)은 SRS 의 「외모(테마)」, 라이트 · 다크 · 시스템과 다르며, 라벨을 바꿀지는 SRS 반영 때 정한다.
- 프리셋 여섯 가지와 직접 고르기를 제공한다.

  | 프리셋 | 기준색 |
  | --- | --- |
  | 한지 (기본값) | `#B8860B` |
  | 모래 | `#8C6E57` |
  | 쑥 | `#5E7A44` |
  | 쪽빛 | `#34628E` |
  | 자주 | `#6E55A8` |
  | 먹 | `#5E5C57` |

- 파생 규칙: 고른 색의 HSL 색상과 채도를 가져오고, 명도는 역할마다 정해진 단계로 자동 결정한다. 계산의 정본은 시안의 `derive()` 함수다. 시안 CSS `:root` 의 값은 스크립트가 돌기 전의 임시값이며 `derive()` 결과와 조금 다르다.
- 메뉴 명도 단계:

  | 역할 | 밝게 | 어둡게 |
  | --- | --- | --- |
  | 사이드바 · 탭 바 | 92% | 15% |
  | 리본 · 상태 바 | 89% | 12% |
  | 항목 위에 올렸을 때 | 85% | 20% |
  | 현재 항목 | 79% | 26% |
  | 경계선 | 82% | 23% |

- 채도 (`s` 는 고른 색의 채도, `ms = min(s × 0.45, 40%)`):

  | 역할 | 밝게 | 어둡게 |
  | --- | --- | --- |
  | 메뉴 바탕 · 올렸을 때 · 경계선 | `ms` | `ms × 0.5` |
  | 현재 항목 | `min(ms + 6%, 46%)` | `ms × 0.6` |
  | 메뉴 글자 · 보조 글자 | 12% · 10% 고정 | 10% · 8% 고정 |
  | 강조색 | `min(s, 72%)` | `min(s, 60%)` |

- 대비 목표와 명도 자동 조정: 아래 목표에 닿을 때까지 명도를 한 방향으로 옮긴다.
  - 강조색과 문서 바탕: 4.6:1 (밝게), 5:1 (어둡게)
  - 메뉴 글자와 현재 항목 배경: 7:1
  - 메뉴 보조 글자와 리본 · 상태 바 배경(밝게) 또는 사이드바 배경(어둡게): 4.5:1
- 여섯 프리셋 × 두 테마 × 메뉴 밝기 다섯 단계에서는 모든 목표를 충족한다. 직접 고른 색은 목표에 못 미칠 수 있다. 예를 들어 어둡게 + 메뉴 밝기 +1 에서 `#FFFF00` 은 메뉴 글자 대비가 6.92:1 이다. 메뉴 보조 글자는 현재 항목 배경 위에서는 모든 프리셋이, 올렸을 때 배경 위에서는 대부분의 프리셋이 4.5:1 에 못 미친다. 최저값은 2.83:1(한지 · 어둡게 · 메뉴 밝기 +2 · 현재 항목 배경)이고, 밝게만 보면 3.33:1 이다. 두 문제는 구현 때 해결한다.
- 메뉴 밝기는 −2 ~ +2 단계로 조정하며, 한 단계는 명도 2% 다. 문서 바탕은 바뀌지 않는다.

### 입력 폼과 버튼

- 옵시디언 설정 화면의 문법을 따른다: 행의 왼쪽에 이름과 한 줄 설명, 오른쪽에 컨트롤.
- 컨트롤 높이는 30px, 모서리는 4px 이다.
- 입력칸과 버튼의 테두리, 꺼진 토글의 채움색은 바탕과의 대비를 3:1 이상으로 둔다: 밝게 `#8F8B82`(3.40:1), 어둡게 `#75726B`(3.44:1).
- 글자로 쓰이는 흐린 색(`--text-faint`: 저장 상태, 단축키 표시, 경로, 입력 안내)도 문서 바탕 위에서 4.5:1 이상으로 둔다: 밝게 `#7A766C`(4.53:1), 어둡게 `#8C8A84`(4.78:1). 강조색 옅은 배경 위에서는 흐린 색 대신 본문 글자색이나 보조 글자색을 쓴다: 메뉴 항목 위에 올렸을 때의 단축키, 폴더 고르기 창 선택 행의 경로, 라이브 편집 현재 줄의 마크다운 기호.
- 포커스를 받으면 강조색 2px 외곽선을 2px 띄워 표시한다. 시안에서 폴더 고르기 창의 검색 입력(외곽선 없음)과 세그먼트 선택(안쪽 2px 링)은 이 규칙을 따르지 않으므로 구현 때 맞춘다.
- 선택 상태는 색 이외의 표식도 함께 쓴다 (`IR-SHELL-006` AC-7). 폴더 고르기 창의 선택 행은 옅은 배경과 왼쪽 강조 막대로, 트리의 현재 문서는 배경과 굵은 글자로 표시한다. 시안의 리본 활성 아이콘은 색과 옅은 배경 타일로만 구별되어 이 규칙을 충족하지 못하고, 강조색 아이콘과 타일의 대비도 일부 조합에서 3:1 에 못 미친다(쑥 · 밝게 · 메뉴 밝기 −2 에서 2.78:1). 구현 때 모양 표식을 더하고 이 대비를 맞춘다.
- 버튼은 주 동작(강조색 채움), 보조 동작(흰 바탕 테두리), 파괴적 동작(빨강 채움), 도구 버튼(테두리 없음) 네 종류다.

### 편집 모드

- 문서는 편집 권한이 있으면 **라이브 편집**, 없으면 **보기**로 연다. 이 규칙은 트리 클릭, 탭, 백링크, 딥링크 등 문서를 여는 모든 경로에 같게 적용한다(결정 5). 기존 설계는 이 경로들에서 모두 보기 모드로 열도록 정했으므로 함께 고친다(후속 명세 표의 설계서 행).
- 개인 설정 「기본 열람 모드」는 남기고 기본값을 「권한에 따라」로 바꾼다. 시안은 다른 선택지의 예로 「항상 보기」를 든다. 허용값 집합은 SRS 반영 때 정한다.
- 기존의 상단 보기·편집 토글과 라이브·소스 하위 토글은 없앤다.
- 문서 제목 줄 오른쪽에 아이콘 하나를 둔다. 아이콘은 **지금 모드**를 나타낸다: 눈(보기), 연필(라이브 편집), `</>`(소스 편집).
- 아이콘을 누르거나 `Ctrl+E`(macOS 는 `Cmd+E`)를 누르면 보기 → 라이브 편집 → 소스 편집 → 보기 순서로 바뀐다. 마우스를 올리면 지금 모드와 다음 모드를 말풍선으로 보여 준다.
- 문서 본문을 우클릭하거나 제목 줄의 「더 보기(⋯)」를 누르면 세 모드 중 하나를 바로 고르는 메뉴가 열린다. 이 메뉴에는 버전 기록 보기와 공유도 있다 (`FR-SHELL-002` AC-2 · AC-3).
- 읽기 전용이면 눈 아이콘만 보이고, 눌러도 바뀌지 않으며, 말풍선은 「읽기 전용 문서입니다」다. 이 아이콘은 편집 권한이 있는 사람의 보기 모드 아이콘과 모양과 색이 같아서, 구별은 말풍선, 보조 기술용 이름, 커서 모양, 올렸을 때 배경이 생기지 않는 것, 저장 상태 표시가 숨는 것뿐이다. 비활성 상태를 따로 구분하라는 `IR-SHELL-006` AC-7 과 어떻게 맞출지는 SRS 반영 때 정한다. 본문 위에도 상태 바에도 권한 안내 문구를 두지 않는다. 우클릭 메뉴의 편집 두 모드는 흐리게 두고 「권한 없음」을 붙이며, 잘라내기 · 붙여넣기 · 링크 삽입과 공유(대상 `편집` 필요)도 흐리게 두고 「권한 없음」을 붙인다.
- 비-md 파일에서는 모드 아이콘 자체를 숨긴다 (`FR-EDITOR-006`). 그래서 권한 때문에 편집할 수 없는 경우(눈 아이콘과 「읽기 전용 문서입니다」)와 형식 때문에 편집할 수 없는 경우(아이콘 없음)가 구별되고, `FR-EDITOR-004` 의 취지가 이어진다. 이 부분은 사용자 결정이 아니라 기존 요구에서 끌어낸 것이다. 비-md 파일의 ⋯ · 우클릭 메뉴 처리는 SRS 반영 때 정한다 (`03.screen-design-shell.md` §3.3 은 비-md 파일에서 버전 기록을 숨긴다).

### 파일 탐색기

- 우클릭 메뉴의 항목과 순서:

  ```
  새 노트
  새 폴더
  ───
  복사본 생성
  다른 곳으로 복사…
  폴더 이동
  폴더에서 검색
  ───
  URL 복사
  공유…
  즐겨찾기에 추가         (이미 즐겨찾기면 「즐겨찾기 해제」)
  ───
  새 버전 올리기…         (파일에만 나타난다)
  ───
  이름 변경      F2
  삭제          Delete
  ```

- 사용자가 지정한 목록에 기존 메뉴의 네 기능(다른 곳으로 복사, 공유, 즐겨찾기, 새 버전 올리기)을 더했다. 앞의 셋은 관련 묶음에 끼워 넣고, 새 버전 올리기는 따로 묶었다. 복사는 워크스페이스 경계를 넘는 유일한 수단이고 트리 메뉴에서 닿아야 하며 (`FR-SHELL-003` Rationale, `FR-SHELL-015` AC-4 · AC-5), 새 버전 올리기의 진입점은 트리 메뉴다 (`FR-SHELL-008`, 원장 `R102-b`).
- 다른 곳으로 복사는 폴더 고르기 창을 복사 모드로 연다. 원본은 보기 권한만 있으면 된다 (`FR-SHELL-003` AC-6).
- 새 버전 올리기는 파일 노드에만 나타나고 디렉토리와 pass-through 노드에는 나타나지 않는다 (`FR-SHELL-003` AC-4 · AC-5).
- 볼 권한이 없는 노드는 트리에 아예 나타나지 않는다. 잠금 아이콘 같은 대체 표시도 두지 않는다 (`SEC-ACL-004` AC-2, 원장 `R25`). 예외는 pass-through 노드 하나다: 볼 수 있는 하위를 품은 상위 디렉토리는 이름만 보이고, 메뉴의 모든 항목이 비활성이며, 드롭 대상이 되지 않는다 (`SEC-ACL-004` AC-5, 원장 `R69`, `03.screen-design-shell.md` §2.2.3). 시안의 「공지」 폴더는 보기만 가능한 폴더의 예이며, 시안에는 pass-through 노드가 없다.
- 메뉴에서 권한이 모자란 항목은 숨기지 않고 흐리게 둔 뒤 「권한 없음」을 붙인다. 기존 설계의 「비활성 + 툴팁」(`03.screen-design-shell.md` §2.2.5)을 바꾸는 것이다.
- 시안에서 트리의 빈 곳을 우클릭하면 맨 위를 대상으로 새 노트, 새 폴더, 폴더에서 검색만 보인다. 이것은 한 워크스페이스만 그린 시안의 예시다. 워크스페이스가 나란히 보이는 제품에서는 워크스페이스 행의 메뉴(`03.screen-design-shell.md` §2.2.5: 새 문서 · 새 디렉토리 · 공유만 활성)를 따르고, 빈 곳 우클릭의 대상은 SRS 반영 때 정한다.
- 새 노트와 새 폴더는 누른 폴더 안에 만든다. 노트를 눌렀다면 그 노트가 든 폴더에 만든다.
- 이름을 먼저 받는다: 트리 안에 기본 이름이 골라진 입력 줄이 생기고, `Enter` 로 확정해야 만든다. `Esc` 를 누르면 아무것도 만들지 않는다 (`FR-SHELL-016` AC-3). 입력 줄을 벗어날 때도 만들지 않는 것은 v2 의 설계 판단이다. 이름 변경은 입력 줄을 벗어나면 확정한다. 이것도 v2 의 설계 판단이며, 기존 설계는 `Enter` 확정과 `Esc` 취소만 정한다. 트리 상단의 새 노트 버튼은 이름을 묻지 않고 바로 만든다 (AC-7). 만드는 곳은 선택한 폴더이고, 문서를 선택 중이면 그 문서가 든 폴더이며, 선택이 없으면 버튼이 비활성이다. 만든 문서는 바로 연다 (`03.screen-design-shell.md` §2.2.4). `Ctrl+N` 도 같은 기준을 따른다 (§9.1). 시안에서는 열린 문서를 선택으로 보고, 폴더는 선택할 수 없으며, 버튼을 끄는 대신 상태 바에 안내를 띄운다. 이 차이는 시안의 단순화다 (설계서 §2.2.4, §11-5).
- 복사본 생성은 같은 폴더에 만들므로 그 폴더의 쓰기 권한이 필요하다. 시안의 「이름 사본」 명명은 제안이며, 이름이 겹칠 때 서버가 접미사를 붙이는 `SEC-SHELL-002` 와 함께 SRS 에서 정한다.
- 폴더 이동과 다른 곳으로 복사는 옵시디언의 빠른 전환 창과 같은 형태의 폴더 고르기 창을 연다. 폴더 경로로 목록을 좁히는 검색 입력을 둔다. 후보는 트리에 보이는 폴더뿐이며 트리와 같은 표시 규칙을 따른다 (`03.screen-design-shell.md` §2.2.8, 원장 `R25` · `R69`). 쓸 수 없는 폴더도 흐리게 보이지만 고를 수 없고, 그 아래의 쓸 수 있는 폴더는 고를 수 있다. 이동 모드에서는 다른 워크스페이스를 고를 수 없다 (`SEC-ACL-014` AC-5).
- 폴더에서 검색은 검색 범위를 그 폴더로 좁힌다. 노트에서 고르면 그 노트가 든 폴더가 범위다. 기존 검색 요구(`FR-SHELL-013`)에 폴더 범위가 없으므로 SRS 에 반영해야 한다(기존 요구 개정이나 새 요구).
- URL 복사는 문서, 폴더, 일반 파일 모든 노드에 나타나고 노드 ID 로 된 주소를 복사한다(결정 8). 폴더 주소를 열면 트리에서 그 폴더를 펼친 채 고른다 (`03.screen-design-shell.md` §3.9.1). 기존 요구(`FR-SHELL-006`)는 문서 딥링크만 정하므로 넓힌다. 시안의 경로 형식 URL 은 예시다.
- 끌어서 놓기:
  - 5px 이상 움직이거나 0.35초 동안 누르면 끌기가 시작된다.
  - 폴더에 놓으면 이동, `Ctrl` 또는 `Alt`(macOS 는 `Option`)를 누른 채 놓으면 복사다. 끄는 도중에 키를 누르거나 떼도 바로 반영된다.
  - 노트 위에 놓으면 그 노트가 든 폴더가 대상이다. 접힌 폴더 위에 0.6초 머물면 펼친다. `Esc` 로 취소한다.
  - 끄는 동안 커서 옆에 결과(「이동: 회의록」)나 놓을 수 없는 이유를 표시하고, 놓을 폴더를 강조한다. 기존 설계는 놓을 수 없는 노드 위에서 반응하지 않았다(`03.screen-design-shell.md` §6.1). v2 는 이유를 보여 준다. 이유는 요청자 자신의 권한에 관한 것으로 한정하고, 숨은 하위가 있다는 사실을 드러내지 않는다 (`03.screen-design-shell.md` §2.2.3 근거 2, §2.2.7, §2.2.8).

## 시안이 기존 요구사항보다 앞서지 않는 것

시안의 드래그, 폴더 고르기 창, 복사본 생성은 **확인 없이 바로 실행되는 것처럼** 그려져 있고, 삭제에는 되돌리기 안내가 없다. 이것은 제스처와 화면을 확정한 것이며, 아래 기존 요구사항을 우회하라는 뜻이 아니다.

- 조작에 필요한 권한은 기존 규칙을 따른다. 공유는 대상 `편집`이다 (원장 `R70-a`, `03.screen-design-shell.md` §2.2.5). 이동은 대상 `편집`과 목적지 `편집`이다 (`SEC-ACL-012` AC-5, 원장 `R74`). 두 곳 모두 원래 폴더의 권한을 조건으로 열거하지 않는다. 복사는 원본 `보기`와 목적지 `편집`을 요구하고 (원장 `R97-b`, `SEC-ACL-014` AC-3), 메뉴 항목은 원본 `보기`만으로 켜진다 (`FR-SHELL-003` AC-6). 시안도 이 규칙으로 판정한다. 다만 시안은 보기 전용 폴더의 제한이 하위에 그대로 이어지는 단순한 모델이라, 부모는 보기 전용이고 노드에만 편집이 있는 경우와 pass-through 노드를 보여 주지 못한다.

- 이동은 실행 전에 접근 가능 인원의 변화를 미리 보여 주고, 그 변화에 맞는 확인 등급을 거친다 (`FR-ACL-006`, `FR-CONFIRM-016`, `IR-SHELL-011`). 끌어서 놓기와 폴더 고르기 창도 이 절차로 이어진다. 이동 창은 접근 가능 인원 프리뷰를 반드시 보이며, 그 프리뷰는 목적지를 고르는 창 안에 있어야 한다 (`SEC-ACL-012` AC-7 · VE-2, `FR-ACL-006` AC-1 · AC-2). 그래서 폴더 고르기 창의 이동 모드는 창 아래에 접근 가능 인원의 변화를 보이고, 목적지를 바꾸면 그 값을 새로 계산한다. 시안의 수치는 예시다. 인원이 그대로인 이동은 확인 없이 실행하고 되돌리기 안내를 띄운다 (`FR-CONFIRM-016` AC-3, `03.screen-design-shell.md` §2.2.7). 끌어서 놓기로 목적지가 정해져도 필요한 확인은 생략하지 않고, L2 를 클릭 한 번으로 실행하는 경로를 두지 않는다 (`FR-CONFIRM-005` AC-3 · AC-4).
- 복사는 끌어서 복사와 복사본 생성을 포함해 언제나 L2 확인을 거친다 (`FR-CONFIRM-017`, `IR-SHELL-011` AC-3). 디렉토리는 보이는 노드만 복사하고 복사한 개수를 알린다 (`SEC-SHELL-003`). 폴더 고르기 창의 복사 모드에도 고정 문구 「권한에 따라 일부 항목이 제외될 수 있습니다」를 둔다 (`SEC-SHELL-003` AC-3).
- 삭제는 확인 없이 휴지통으로 옮기되 되돌리기 안내를 띄운다 (`FR-CONFIRM-006` AC-1).
- 워크스페이스 경계를 넘는 이동은 차단하고 복사만 허용한다 (`SEC-ACL-014`). 기존 설계는 다른 워크스페이스 위로 끌면 자동으로 복사로 바꾸고 「복사」 뱃지를 붙인다 (`03.screen-design-shell.md` §2.2.6). v2 의 수정키(`Ctrl` · `Alt`) 복사 모델과 이 자동 전환을 SRS 반영 때 맞춘다.
- 숨은 하위가 있는 디렉토리의 이동과 삭제는 관리 레벨을 요구한다 (`SEC-ACL-013`).
- 트리로 파일을 끌어다 놓아 올리는 기능(`FR-ATTACH-001`)과 트리 안의 항목 끌기가 서로 방해하지 않도록 구현 때 설계한다. 「노트 위에 놓으면 그 노트가 든 폴더」 규칙은 기존 설계에도 있다 (`03.screen-design-shell.md` §2.2.6). 반면 업로드 드롭은 디렉토리 노드만 대상으로 한다 (`FR-ATTACH-001` AC-1). 두 규칙을 맞출지는 SRS 반영 때 정한다.
- 조작 결과는 기존 규칙대로 알림으로 알린다 (`IR-SHELL-011` AC-7, 원장 `R105-b`). 시안이 상태 바에 결과를 잠시 띄우는 것은 시연용이다.

다음 시안 요소는 외관을 설명하는 예시다. 시안을 승인했다고 해서 요구사항으로 추가되거나 기존 요구가 바뀌지 않는다.

- 예시 데이터와 역할 이름(관리자 · 편집자 · 독자). SRS 의 권한 레벨은 보기 · 편집 · 관리다.
- 사이드바 맨 위의 워크스페이스 머리글과 한 워크스페이스만 그린 트리. 제품 트리는 접근 가능한 워크스페이스를 나란히 보여 주고 전환 UI 를 두지 않는다 (`FR-WORKSPACE-003` AC-3, 원장 `R41`).
- 오른쪽 패널의 개요, 「이 문서에 접근할 수 있는 역할」. 접근자 명단은 관리 전용이다 (`SEC-ACL-015`). 오른쪽 패널의 탭 구성은 `FR-SHELL-004` 를 따르고, 목차는 Phase 2 다.
- 상태 바의 단어 수, 리본의 링크 그래프 · 권한 관리 · 휴지통 버튼. 그래프 뷰는 Phase 2 예약 기능이고 (`03.screen-design-shell.md` §9.2), 관리 진입점은 설정 모달 하나다 (`CON-SHELL-001`).
- 권한 부여 모달의 「설계 폴더와 그 하위 문서 12개에 적용됩니다」. 적용 하위 개수는 확인 다이얼로그에만 둔다 (원장 `R126-d`, 설계서 §2.2.8).
- 권한 부여 모달의 메모 「감사 기록에 함께 남습니다」. 감사 기록의 의미 칸에 메모가 없다 (`12.audit-log.srs.md`).
- 워크스페이스 설정 예시의 「가입 신청 받기」. 가입 모드는 슈퍼유저만 보는 인스턴스 설정이다 (`IR-SHELL-002` AC-6 · AC-7).
- 워크스페이스 설정 예시의 「새 멤버의 기본 역할」과 「초대 메일」. SRS 에 초대 흐름이 없다.
- 사이드바 도구 줄의 정렬 · 모두 접기 버튼과 문서 제목 줄의 링크 복사 버튼. 트리 상단의 버튼은 새 노트 하나다 (`FR-SHELL-003` AC-1, `03.screen-design-shell.md` §2.2.4). 시안에 있던 새 폴더 버튼은 설계서가 원장 `R124`(한 사실은 한 곳에만)를 근거로 뺀 버튼이라 걷어냈다 (§2.2.4).
- 오른쪽 패널에는 백링크의 개수를 표시하지 않는다 (`03.screen-design-shell.md` §2.2.8 · §6.6).
- 워크스페이스 설정 예시의 「외부 공유 링크」와 「휴지통 비우기」. Phase 1 에는 휴지통 일괄 영구 삭제가 없다 (`FR-CONFIRM-006` AC-9).
- 권한 부여 모달의 「만료일」, 폴더에 부여하는 「관리자」 역할, 「하위 폴더에도 적용」. ACL 에는 만료일이 없고 (원장 `R110`), `관리` 는 워크스페이스에만 부여한다 (원장 `R36` · `R135-a`).
- 외관 설정을 브라우저 저장소(`localStorage`)에 두는 것. 제품은 사용자별 DB 행에 저장한다 (`IR-SHELL-007` AC-3, `DR-SHELL-002`).

리본은 v2 의 배치로 확정한다. 기존 좌측 사이드바 상단 탭(`FR-SHELL-001`)의 기능을 리본으로 옮기는 것은 SRS 반영 때 정한다.

## 기존 요구와 부딪힌 여덟 건의 결정

첫 시안이 기존 요구사항과 정면으로 부딪힌 네 건이다. 2026-09-23 사용자가 네 건 모두 권장안을 골랐고, 승인 시안도 그에 맞게 고쳤다.

1. **기본 열람 모드 설정.** `IR-SHELL-004` AC-3 은 개인 설정 「기본 열람 모드」의 기본값을 보기로 정하고, 원장 `R152` 는 그 근거로 의도치 않은 쓰기를 든다.
   → 설정을 남기고 기본값을 「권한에 따라」로 바꾼다. 허용값 집합(기존 「편집」을 남길지, 「항상 보기」를 둘지)과 「편집 하위 뷰」 설정은 세 모드 순환과 함께 SRS 반영 때 다시 정한다. 원장 `R152` · `R2` · `R90` 을 먼저 고친다.
2. **트리 메뉴에서 빠졌던 네 기능.** 기존 메뉴(`FR-SHELL-003`, 원장 `R88-a`)의 공유, 즐겨찾기, 새 버전 올리기, 다른 곳으로의 복사가 첫 v2 목록에 없었다.
   → 사용자 지정 목록은 그대로 두고, 앞의 세 기능은 관련 묶음에 끼워 넣고 새 버전 올리기는 따로 묶는다(파일 탐색기 절의 목록). 원장 `R88-a` 를 고친다.
3. **입력 컨트롤의 접근성 기준.** `IR-SHELL-006` 은 컨트롤 최소 높이 36px(AC-4), 2px 외곽선과 2px 간격의 포커스 표시(AC-7), 활성 컨트롤 경계 대비 3:1(AC-8)을 요구한다. 첫 시안은 높이 30px, 테두리 + 3px 링, 입력 경계 대비 1.71:1 이었다.
   → 테두리 대비를 3:1 이상으로 올리고 포커스를 2px 외곽선 + 2px 간격으로 바꾼다. 높이는 30px 로 두고 AC-4 를 고친다. 같은 AC 의 다른 치수는 결정 7 을 따른다. 컨트롤 높이는 WCAG 2.2 의 최소 목표 크기(24px)를 넘는다.
4. **새 노트의 이름 받는 순서.** 첫 시안은 먼저 만들고 이름을 받아서 `Esc` 를 눌러도 「새 노트」가 남았고, 상단 버튼도 이름을 물었다.
   → 기존 요구(`FR-SHELL-016` AC-3 · AC-7)를 유지한다.

검증을 거듭하며 나온 네 건은 같은 날 두 번째 질문으로 정했다. 네 건 모두 권장안이다.

5. **문서를 여는 경로.** 기존 설계는 트리 클릭 · 백링크 · 딥링크로 열 때 모두 보기 모드로 연다 (`03.screen-design-shell.md` §3.2.3 · §3.9.2 · §7.1 · §7.4 · §7.11, 판단 §11-11 · §11-25).
   → 「권한이 있으면 라이브 편집, 없으면 보기」를 모든 경로에 같게 적용한다.
6. **다음 단계.** 결정 기록의 검증을 여섯 번 돌린 뒤, 남은 대조는 SRS 반영 단계에서 기존 요구 · 원장 · 설계서 전체와 함께 한다.
7. **화면 밀도.** `IR-SHELL-006` AC-4 · AC-9 는 아이콘 클릭 영역 36px, 입력 글자 14/22px, 필드 간격 20px, 트리 행 40px 를 정한다.
   → 시안의 촘촘한 값(아이콘 30px, 사이드바 도구 28px, 입력 글자 13px, 필드 간격 16px, 트리 행 약 26px)으로 기준을 고친다. WCAG 2.2 의 최소 목표 크기 24px 는 지킨다. 시안의 토글(높이 22px)과 색 직접 고르기 칸(22 × 18px)은 구현 때 이 기준에 맞춘다.
8. **URL 복사의 대상.** 첫 v2 목록은 대상을 정하지 않았고, 기존 요구는 문서 딥링크만 정한다.
   → 문서, 폴더, 일반 파일 모든 노드에 둔다.
