# 신문지 테마 — 입력폼과 공통 조작 규칙

이 문서는 [승인된 디자인](./README.md)을 입력폼·버튼·선택기·모달에 적용하는 UX 설계 지침이다. 대상은 Phase 1 데스크톱이다. 제품 동작의 정본은 `docs/spec/`이며, 아래 새 치수·접근성·검증 시점 제안은 구현 전 관련 SRS에 반영할 설계안이다. 승인된 핵심 팔레트나 기존 권한·확인 등급을 바꾸지 않는다.

## 1. 입력폼의 기본 모양

폼은 종이 위에 정렬된 단일 열을 기본으로 한다. 서로 관련된 짧은 필드만 같은 행에 둔다. 명조체는 문서 제목에 사용하고 폼·모달 제목과 라벨·입력값·설명·오류·버튼은 고딕체로 읽기 쉽게 표시한다.

| 항목 | 설계값 | 적용 원칙 |
| --- | --- | --- |
| 일반 입력·선택기·버튼 | 최소 높이 36px | 설정·관리 화면 기본값 |
| 인증·설치 주요 입력·버튼 | 최소 높이 40px | 로그인·가입·설치 화면 |
| 좌우 내부 여백 | 12px | 아이콘 영역과 입력 문자가 겹치지 않게 추가 여백 확보 |
| 모서리 | 4px | 입력·버튼·선택기 공통; 알약 모양 금지 |
| 입력 테두리 | 1px, `#7A7B71` | 장식 구분선 `#CCCBC3`와 분리; 실제 상태별 대비는 구현 후 검증 |
| 입력 배경·글자 | `#FAF9F5` / `#242521` | 공통 컨트롤 표면과 기본 글자 토큰 사용 |
| 라벨 / 입력값 | 13px·행간 20px / 14px·행간 22px | 라벨 중간 굵기, 입력값 보통 굵기 |
| 도움말·오류 | 12px, 행간 18px | 여러 줄 줄바꿈 허용; 높이 고정 금지 |
| 라벨 → 입력 / 입력 → 설명 | 6px / 6px | 입력 그룹 안의 결속 유지 |
| 필드 사이 / 구역 사이 | 20px / 32px | 단일 구역 안에 과도한 카드 중첩 금지 |
| 일반 폼 폭 | 최대 560px | 좁아지면 컨테이너 폭에 맞춤; 수치는 고정폭 강제가 아님 |
| 여러 줄 입력 | 최소 높이 96px | 본문 편집기는 별도 편집기 규칙 적용 |
| 아이콘 버튼 | 최소 36×36px | 도형은 기본 16px, 필요 시 20px; 보이는 이름이 없으면 접근 가능한 이름 제공 |

치수는 최소값이다. 확대·긴 번역·오류 문구로 내용이 늘면 높이를 늘린다. 폼 정렬을 위해 글자를 잘라내거나 작은 글꼴로 축소하지 않는다. 200% 확대 상태에서도 제출·취소·오류에 도달할 수 있게 한다.

## 2. 라벨·설명·오류

1. 모든 입력에는 지속적으로 보이는 라벨을 둔다. placeholder는 예시이며 라벨을 대신하지 않는다. 필수 필드는 `이름 (필수)`처럼 글자로 표시한다.
2. 라벨은 필드 바로 위 왼쪽에 둔다. 라벨과 컨트롤을 연결하고, checkbox·radio는 문구를 눌러도 선택되게 한다. 관련 선택지는 `fieldset`·`legend`로 묶는다.
3. 도움말은 입력 전 알아야 할 조건·단위·영향을 설명한다. 허용 길이·비밀번호 정책·만료일 기본값은 SRS의 확정값만 쓴다.
4. 오류는 해당 입력 아래에 해결 방법과 함께 쓴다. `잘못된 값` 대신 `이름을 입력해 주세요`처럼 행동을 안내한다. 서버가 제공하지 않은 원인을 추측하지 않는다.
5. 오류 필드는 `aria-invalid`와 설명 연결을 제공한다. 붉은 테두리만 사용하지 않고 오류 문구와 아이콘을 함께 둔다. 도움말이 오류로 대체돼도 필수 조건은 사라지지 않게 한다.
6. 제출 후 여러 필드가 잘못되면 상단에 오류 요약을 두고 해당 필드로 이동할 수 있게 한다. 입력값은 보존하되 비밀번호·토큰은 보안 요구사항을 따른다.
7. 권한으로 숨겨야 하는 조작은 비활성 버튼이나 도움말로 노출하지 않는다. 비활성 사유에도 숨겨진 대상·권한 정보가 새지 않아야 한다.

## 3. 버튼과 행동의 위계

| 종류 | 모양 | 사용 |
| --- | --- | --- |
| 기본 실행 | 잉크 블루 `#365B70` 배경, `#FAF9F5` 글자 | 한 작업 구역의 최종 실행 하나 |
| 보조 실행 | 종이색 배경, 잉크색 글자, 입력 경계색 테두리 | 취소·이전·보조 조작 |
| 약한 실행 | 투명 배경, 잉크색 글자 | 툴바·탭 주변의 반복 조작 |
| 위험 실행 | 별도 danger 토큰, 구체적 동사 | 영구 삭제·토큰 폐기 등; 색상만으로 위험을 설명하지 않음 |
| 링크 | 잉크 블루 글자와 밑줄 | 다른 위치로 이동; 저장·삭제에 링크 외형 사용 금지 |

버튼 문구는 `확인`보다 `토큰 폐기`, `변경 사항 저장`처럼 결과를 말한다. 수평 액션 행은 `취소 → 실행` 순서로 오른쪽에 둔다. 위험 조작은 일상적인 저장과 떨어뜨린다. 모든 버튼에 강한 채움색을 사용하지 않는다.

로딩 중에는 폭이 흔들리지 않게 진행 표시와 `저장 중…` 등의 문구를 넣는다. 중복 제출을 막고 처리 결과를 알린다. 재시도 가능 여부는 실제 동작에 따르며 지원하지 않는 취소 버튼을 만들지 않는다. 폼 내부의 복사·보기 전환·닫기는 제출 버튼으로 취급하지 않는다.

## 4. 선택 컨트롤

| 컨트롤 | 선택 기준 | 표시·키보드 원칙 |
| --- | --- | --- |
| Checkbox | 서로 독립적인 복수 선택 | 체크 표식과 문구; Space로 전환; 부분 선택은 혼합 상태 표시 |
| Radio | 동시에 비교할 짧은 단일 선택 목록 | 원형 표식; 그룹 안 방향키 이동; 의미 없는 기본값 추가 금지 |
| Select | 이미 정해진 목록 중 하나 선택 | 선택값과 펼침 표시; 선택 전 placeholder는 실제 값 아님 |
| Combobox | 사용자·그룹처럼 검색이 필요한 목록 | 검색어·현재 선택·결과를 구분; 방향키와 Enter로 결과 선택 |
| Switch | 즉시 반영되는 독립적인 켜기/끄기 | 상태가 라벨과 함께 이해돼야 함; 명시적 저장 폼은 checkbox 우선 |

선택기 안에 다시 선택기를 넣지 않는다. 검색 결과 없음·조회 중·조회 실패를 별개로 표시한다. 결과 중 `비활성` 같은 상태 배지는 이름과 분리한다. 권한 선택지·기본값·검색 대상의 노출 범위는 SRS를 그대로 따른다. Combobox의 Enter는 결과 선택이며 바깥 폼 제출로 전파하지 않는다.

## 5. 검증 시점과 저장 방식

빈 폼을 열자마자 오류로 채우지 않는다. 일반 입력은 처음에는 blur 또는 제출 때 검증하고, 이미 오류가 드러난 필드는 수정 중 오류 해소를 알려준다. 조합 중인 한글을 미완성 값으로 검증하거나 Enter 확정으로 제출하지 않는다. 검색 역시 IME 조합 완료를 고려한다.

| 화면 종류 | 저장 표현 | 지켜야 할 구분 |
| --- | --- | --- |
| 문서 편집 | 문서 헤더의 저장 중·저장됨·실패 상태 | 기존 자동 저장·충돌·본문 구제 계약 유지; 폼 제출 규칙을 이식하지 않음 |
| 개인 설정 — 에디터·외모 | 필드 변경 후 저장 상태를 가까이 표시 | 기존 설계의 즉시 저장 흐름; 실패를 성공으로 표시하지 않음 |
| 인스턴스 설정 | 하단 액션 바의 명시적 저장 | 변경값을 검토할 여유 제공; 위험 변경의 확인 관문은 별도 |
| 생성·로그인·토큰 발급 | 명시적인 실행 버튼 | 입력 중에는 생성·발급·인증을 실행하지 않음 |
| 트리 이름 입력 | 기존 Enter 확정·Esc 취소 | IME Enter와 구분; 일반 모달로 변경하지 않음 |

계정의 비밀번호 변경·PAT 발급/폐기·휴지통 조작은 각 명시적 실행 흐름을 사용한다. 개인 구역에 있다는 이유로 자동 저장을 적용하지 않는다. 저장 지연 시간·재시도 정책·미저장 경고 대상을 이 문서에서 새로 정하지 않는다. 에디터·외모 설정과 인스턴스 설정의 구별은 [설정 설계 §2.1·§2.12](../spec/04.screen-design-settings.md)를 따르되, 동작 변경은 해당 SRS의 수용 기준에 먼저 반영한다.

## 6. 비밀번호와 PAT

- 비밀번호는 기본 마스킹하고 붙여넣기와 비밀번호 관리자를 방해하지 않는다. 표시 전환을 제공할 경우 현재 상태와 동작을 읽을 수 있는 이름을 준다. 로그인과 새 비밀번호의 자동완성 목적을 구분한다.
- 비밀번호 길이·복잡도, 현재 비밀번호 요구 여부, 변경 후 세션·PAT 처분은 스타일 결정으로 확정하지 않는다. `SEC-AUTH-018`과 관련 확정 명세가 우선한다.
- PAT는 `SEC-AUTH-006`의 평문 1회 노출 원칙을 보존한다. 전체 값은 고정폭 글꼴로 선택·복사 가능하게 표시하며 말줄임 때문에 복사 대상이 불명확해지지 않게 한다.
- PAT 평문 화면은 Escape·바깥 클릭으로 닫히지 않는 기존 예외를 유지한다. 명시적인 닫기 경로와 재확인을 보존하며, 복사 성공은 실제 클립보드 성공 후에만 표시한다. 실패 시 수동 선택·복사 안내를 제공한다.
- 평문을 목록·토스트·오류 문구·로그·예제 데이터에 반복 노출하지 않는다. 발급·폐기는 본인에게만 제공하고 폐기는 L2를 유지한다(`SEC-AUTH-007`, `FR-CONFIRM-006`).

## 7. 모달·팝오버·위험 확인

설정은 `Dialog`, 가까운 짧은 선택은 `Popover`, 위험 확인은 `AlertDialog`를 사용한다. shadcn 외관을 입혀도 Radix의 역할·포커스·키보드 계약을 유지한다. 팝오버를 긴 관리 폼의 컨테이너로 사용하지 않는다.

일반 폼 모달은 최대 폭 560px·내부 여백 24px를 기준으로 하고 화면 가장자리에 최소 24px를 남긴다. 긴 내용은 본문 영역에서 스크롤하며 제목·현재 행동·닫기 경로가 가려지지 않게 한다. 설정의 2단 모달은 기존 설정 셸 치수를 사용한다. 모달에는 접근 가능한 제목·설명을 제공한다.

일반 모달을 여러 겹 쌓지 않고 설정 본문 안에서 하위 화면을 전환한다. 기존 설계의 위험 확인만 상위 오버레이로 올린다. Escape는 최상단의 닫기 가능한 층에만 작용한다. 일반 모달의 바깥 클릭·미저장 처리 여부는 해당 화면 계약을 따르며 일괄 덮어쓰지 않는다. AlertDialog는 바깥 클릭으로 닫지 않는다. PAT 평문은 위 §6의 별도 예외다.

2026-09-16 위임 결정과 `IR-AUTH-003`에 따라 PAT 발급·평문 표시·닫기 재확인은 설정 본문의 단계로 옮긴다. 평문이 보이는 동안 Escape·바깥 클릭은 닫히지 않으며 설정 닫기·카테고리 이동도 폐기 재확인을 거친다. 복사하고 닫기는 실제 복사 성공 뒤에만 수행한다. 기존 평문 보호·명시적 닫기·재확인 계약을 유지하고 별도 일반 모달을 쌓지 않는다. 구현·독립 검증은 #63의 후속 작업이다.

| 등급 | 기존 동작의 표현 | 금지 사항 |
| --- | --- | --- |
| L1 | 즉시 실행하고 되돌리기 토스트 표시 | 디자인 통일을 이유로 사전 확인 추가 금지 |
| L2 | 대상·영향·지연 효과를 설명한 실행 전 확인 | 입력 폼의 실행 버튼으로 확인 대체 금지 |
| L3 | L2 설명에 SRS 지정 토큰의 타이핑 확인 추가 | 임의의 `DELETE` 문구나 고정 토큰으로 대체 금지 |

등급 정본은 `FR-CONFIRM-001`~`005` 및 조작별 지정이다. 넓히기 L1의 토스트는 `실행취소` 대신 `회수`를 쓴다(`FR-CONFIRM-014`). 영향 수치는 열 때 재조회하며 값이 바뀌면 잠금 사유·갱신값·새 입력 조건을 보여준다(`FR-CONFIRM-004`). 확인 수치나 문구로 숨겨진 대상의 존재를 드러내지 않는다(`SEC-CONFIRM-001`).

## 8. 포커스와 상태 표현

키보드 포커스는 2px 잉크 블루 외곽선과 2px 간격을 기본으로 한다. 잉크 블루 채움 버튼에는 밝은 컨트롤 표면색 `#FAF9F5`의 2px 분리 영역을 반드시 두어 같은 색의 외곽선이 버튼과 합쳐지지 않게 한다. outline을 지우지 않고 잘림·가림이 없게 한다. 초기 포커스는 일반 폼의 첫 유효 입력, 위험 확인의 취소 또는 설명으로 두며 파괴적 실행에 자동 포커스하지 않는다. 닫힌 뒤에는 트리거 또는 논리적인 다음 위치로 복원한다.

| 상태 | 시각 표현 | 입력·보조기술 표현 |
| --- | --- | --- |
| 기본 | 종이 배경, 짙은 입력 경계 | 라벨과 현재 값 |
| Hover | 약한 배경 변화 또는 경계 강화 | 레이아웃·크기 변화 없음 |
| Focus | 외곽선 | 오류·선택과 함께 표시 가능 |
| 선택 | 청회색 배경과 체크·활성 표식 | 적절한 선택 상태 속성 |
| Disabled | 대비를 낮춘 별도 표면 | 실제 비활성; 노출 허용된 사유는 인접 문구로 제공 |
| Read-only | 읽을 수 있는 텍스트, 편집 불가 표시 | 선택·복사 가능; disabled와 구분 |
| Invalid | 오류 경계·아이콘·문구 | 오류 연결, 제출 후 오류 위치 안내 |
| 처리 중 | 진행 아이콘과 구체적 문구 | 중복 실행 방지, 완료·실패 알림 |
| 성공 | 간단한 완료 문구 | 입력마다 성공 토스트를 남발하지 않음 |
| 실패 | 지속되는 오류·가능한 다음 행동 | 값 보존; 서버 오류를 임의의 필드 오류로 오인하지 않음 |

비활성 상태 외의 일반 텍스트는 배경 대비 4.5:1, 큰 텍스트는 3:1, 컨트롤 경계·상태 표식은 인접 색 대비 3:1을 설계 목표로 한다. 사이드바의 보조 글자는 공통 보조색 대신 전용 `#5E5F58`을 사용한다. 이 문서는 접근성 인증 결과가 아니다. 실제 조합·투명도·포커스 겹침·확대 상태를 구현 후 별도 검증해야 한다. 성공·경고·오류 토큰과 정적 대비표는 [공통 스타일 가이드 §3](./newspaper-style-guide.md)에 따른다.

## 9. 폼 구조 예시

아래는 구조 설명용이며 필드·기본값·생성 권한을 새로 확정하지 않는다.

```text
워크스페이스 만들기                           [닫기]
함께 사용할 문서 공간의 정보를 입력하세요.

이름 (필수)
┌─────────────────────────────────────────┐
│ 제품 문서                               │ 36px 이상
└─────────────────────────────────────────┘
목록에서 구분할 수 있는 이름을 입력하세요.

관리자 (필수 여부는 해당 명세에 따름)
┌─────────────────────────────────────────┐
│ 사용자 검색                           ⌄ │
└─────────────────────────────────────────┘
오류가 있다면 해당 필드 아래에 해결 방법 표시

───────────────────────────────────────────
                            [취소]  [생성]
```

생성 버튼 뒤의 확인은 `FR-CONFIRM-019`와 해당 워크스페이스 SRS를 따른다. 외형 예시가 입력 폼과 확인 관문을 합치거나 기존 단계 수를 바꾸는 근거가 될 수 없다.

## 10. 후속 SRS 반영 및 검토 항목

36/40px 치수, 입력 경계·상태 토큰, 오류 표시 시점, IME 제출 방지, 포커스 복원, 대비 목표, 확대 대응은 `IR-SHELL-006`~`008`에 후속 수용 기준으로 등록됐다. PAT 이탈 정책은 `IR-AUTH-003`이 정한다. 비밀번호 정책·PAT 만료 기본값·자동 저장 지연 조절은 기존 계약을 유지한다. [구현 핸드오프](./newspaper-implementation-handoff.md)에 전체 이슈별 REQ/AC 매핑과 결정 처분을 기록했다. 기존 관련 요구사항은 `CON-ARCH-004`, `IR-SHELL-001`, `IR-SHELL-004`, `DR-SHELL-002`, `SEC-AUTH-006`, `SEC-AUTH-007`, `SEC-AUTH-018`, `FR-CONFIRM-001`~`005`, `FR-CONFIRM-006`, `FR-CONFIRM-014`, `FR-CONFIRM-019`, `SEC-CONFIRM-001`이다.
