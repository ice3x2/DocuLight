# DocuLight 신문지 디자인 스타일 가이드

작성일: 2026-09-16 · 대상: 데스크탑 웹 · 기반: Radix UI + shadcn/ui

## 1. 문서의 지위와 읽는 순서

이 문서는 [승인된 디자인 결정](./README.md)과 [HTML 시안](./newspaper-theme.html)을 제품에 적용하기 위한 시각·UX 설계 가이드다. 신문지 라이트 외관은 사용자 승인 사항이며, 이 문서에서 구체화한 치수·상태·입력 규칙은 후속 구현을 위한 설계 기준이다. 제품 적용 완료나 접근성 인증을 뜻하지 않는다.

요구사항의 정본은 `docs/spec/`이다. 동작·권한·저장·확인 등급·지원 범위는 해당 SRS가 우선한다. 이 문서는 요구사항 ID를 신설하거나 수용 기준을 대신하지 않는다. 기존 SRS에 없는 동작을 적용하려면 먼저 해당 SRS에 반영한다. 2026-09-16 위임 결정으로 다크 팔레트와 미결 UX 계약이 [구현 핸드오프](./newspaper-implementation-handoff.md) 및 관련 SRS에 확정됐다. 아래 초기 가이드와 후속 결정의 세부값이 다르면 해당 SRS와 핸드오프를 따른다. 다크 시안·독립 검증은 별도 완료 증거가 필요하다.

- 전체 색상·글꼴·배치: 이 문서.
- 입력폼·버튼·선택·모달·오류·키보드 규칙: [입력폼과 컴포넌트 UX 규칙](./newspaper-forms.md).
- 외관 비교 기준: 승인 HTML. HTML의 목차·속성·단축키·모바일 구성은 기능 승인 목록이 아니다.

## 2. 디자인 원칙

1. 회백색 종이 위에 잉크로 인쇄한 듯한 차분함을 유지한다. 노란 양피지, 종이 얼룩, 배경 질감 이미지를 사용하지 않는다.
2. 큰 작업 영역에서는 문서를 주변 패널보다 밝게 둔다. 입력·팝오버 표면은 조작 구분을 위해 더 밝게 둘 수 있다.
3. 제목의 명조체가 개성을 담당한다. 본문·입력·관리 UI는 고딕체로 읽기와 조작을 돕는다.
4. 여백과 얇은 선으로 구조를 만든다. 모든 영역을 카드로 감싸거나 그림자로 띄우지 않는다.
5. 잉크 블루는 주요 동작·선택·포커스에 사용한다. 상태는 색과 함께 문구·아이콘으로 구분한다.
6. 밀도는 높이되 작은 글자와 좁은 클릭 영역으로 압축하지 않는다. 승인 HTML의 10~11px 보조 문구를 제품 전체의 기본 크기로 복제하지 않는다.

선택 행은 배경만 바꾸지 않고 굵기·측면 표시 등으로 선택을 보강한다. 본문 링크는 밑줄을 사용한다. disabled는 전체 opacity를 낮춰 텍스트까지 지우기보다, 배경·텍스트·테두리 토큰으로 표현하고 사용 불가 사유를 함께 제공한다.

`--border-subtle`은 입력 경계를 식별하는 유일한 단서로 쓰지 않는다. 표 행 구분선과 활성 컨트롤 경계는 대비 요구가 다르다.

### 3.3 접근성 목표

일반 텍스트와 placeholder는 실제 배경에 대해 4.5:1 이상을 목표로 한다. 조작 식별에 필요한 경계·아이콘·상태 표시는 인접 배경에 대해 3:1 이상을 목표로 한다. 장식 구분선은 동일 기준을 일괄 적용하지 않는다. 정적 HEX 대비와 실제 렌더링 검증을 구분한다. 투명도·오버레이·이미지 위 글자는 최종 합성색으로 다시 검사한다.

근거: [W3C 텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [W3C 비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). 이 목표만으로 WCAG 전체 준수를 주장하지 않는다.

아래는 불투명한 sRGB 색상값의 정적 대비 계산 결과다. 승인 보조색 `#65665F`를 사이드바 `#DEDDD6` 위에 쓰면 4.26:1이므로 일반 크기 글자에는 사용하지 않고 전용 보조색을 적용한다. 승인 핵심색 자체는 유지한다.

| 전경 / 배경 | 대비 | 용도 |
| --- | --- | --- |
| `#242521` / `#F5F4EF` | 14.00:1 | 문서 기본 글자 |
| `#65665F` / `#F5F4EF` | 5.27:1 | 문서 보조 글자 |
| `#5E5F58` / `#DEDDD6` | 4.74:1 | 사이드바 보조 글자 |
| `#FAF9F5` / `#365B70` | 6.90:1 | 주요 버튼 글자 |
| `#963F38` / `#F3E5E1` | 5.58:1 | 오류 안내 |
| `#3E6049` / `#E4EAE2` | 5.77:1 | 성공 안내 |
| `#79571F` / `#F0E8D7` | 5.39:1 | 경고 안내 |
| `#7A7B71` / 앱·문서·컨트롤·사이드바·선택 면 | 3.47 / 3.89 / 4.07 / 3.15 / 3.42:1 | 컨트롤 경계 |

이 값은 투명도·합성 배경·실제 글꼴·상태 전환·포커스 잘림을 검증한 결과가 아니다. 포커스 링이 주요 버튼 채움과 합쳐지지 않도록 밝은 2px 분리 영역을 적용하고 실제 렌더링에서 다시 확인한다.

## 4. 글꼴과 타이포그래피

기본 루트 크기는 16px이며, 아래 크기는 설계 기준값이다. 실제 CSS 글자 크기는 rem으로 표현한다. 브라우저 확대와 사용자 글꼴 설정을 막지 않는다.

| 용도 | 글꼴 계열 | 크기 / 행간 | 굵기 |
| --- | --- | --- | --- |
| 문서 제목 | 바탕, Georgia, serif | 36 / 50px | 700 |
| 문서 H2 / H3 | 같은 명조 계열 | 24 / 36px, 20 / 30px | 700 |
| 본문 | 맑은 고딕, system-ui, sans-serif | 16 / 28px | 400 |
| 인용 | 명조 계열 | 18 / 30px | 400 |
| 패널·모달 제목 | 고딕 계열 | 18 / 26px | 600 |
| 메뉴·버튼·입력·표 | 고딕 계열 | 14 / 22px | 400~600 |
| 필드 라벨 | 고딕 계열 | 13 / 20px | 600 |
| 보조 설명·메타데이터 | 고딕 계열 | 12 / 18px | 400 |
| 코드·소스·토큰 | Consolas, monospace | 14 / 22px | 400 |

시스템 글꼴을 우선하며, 별도 배포 폰트를 도입할 때만 라이선스와 한글 지원 범위를 확인한다. 가독성을 위해 본문 자간은 기본값, 제목 자간은 -0.02em 이내로 제한한다. UI 라벨은 명조체로 바꾸지 않는다. 긴 한글 제목은 줄바꿈을 허용하고 고정 높이로 자르지 않는다.

본문은 왼쪽 정렬한다. 양끝 맞춤으로 단어 사이를 벌리지 않는다. 읽기 영역 최대 폭은 720px, 좌우 여백은 기본 40px(좁은 데스크탑에서는 24px)로 제안한다. 코드·표는 자신의 영역에서 가로 스크롤하며 앱 전체 폭을 밀지 않는다.

## 5. 간격·모양·깊이

| 항목 | 설계값 | 용도 |
| --- | --- | --- |
| 간격 배수 | 4, 8, 12, 16, 24, 32, 48px | 임의의 화면별 간격을 줄인다 |
| 아이콘과 라벨 | 8px | 버튼·메뉴·행 |
| 필드 간격 | 20px | 관련 입력 묶음 |
| 폼 섹션 간격 | 32px | 주제가 다른 입력 묶음 |
| 패널 패딩 | 24px | 설정·모달 내부 |
| 버튼·입력 반경 | 4px | 각진 인쇄물 인상을 유지 |
| 팝오버·모달 반경 | 6px | 콘텐츠 표면 구분 |
| 배지 반경 | 3px | 상태·태그 |
| 기본 선 | 1px | 패널·행·입력 경계 |
| 선택 표시 | 2px | 탭 밑줄 또는 행 측면 |
| 일반 아이콘 | 16px, 필요 시 20px | 텍스트 크기와 함께 조절 |
| 클릭 영역 | 기본 36×36px 이상 | 아이콘 도형과 클릭 영역을 구별 |

일반 패널·문서·표에는 그림자를 쓰지 않는다. 떠 있는 메뉴·모달만 `0 8px 24px rgb(36 37 33 / 12%)` 정도의 약한 그림자를 허용한다. 브랜드 표시 외에 장식용 이중선은 남용하지 않는다.

레이어의 상대 순서는 본문 → 고정 툴바 → 팝오버 → 모달 오버레이 → 모달 콘텐츠 → 모달 내부 팝오버다. 포털도 같은 테마를 상속한다. z-index 숫자는 구현 시 공통 토큰 한 곳에서 관리한다.

## 6. 화면별 배치 기준

### 앱 셸과 문서

왼쪽은 문서 트리·검색·즐겨찾기, 오른쪽은 백링크·아웃고잉 링크·태그다. 승인 시안의 목차·속성 패널을 새 기능으로 추가하지 않는다. 초기 적용은 기존 셸의 280px / 중앙 가변 / 320px 배치를 유지하고, 패널 폭 변경은 화면 설계와 별도로 정합성을 확인한다.

탭 스트립과 문서 헤더는 분리한다. 탭 넘침은 탭 줄에서 처리한다. 검색 입력·필터는 고정하고 결과 목록만 스크롤한다. 중앙은 헤더 아래 문서가 남은 높이를 사용한다. 설정 버튼은 좌하단에 두되 트리 마지막 항목을 가리지 않는 영역을 확보한다.

### 인증과 설치

인증 전 화면은 셸 없는 전체 화면이다. 로그인·가입 폼은 최대 400px, 설치 폼은 최대 640px의 읽기 쉬운 폭으로 제안한다. 배경은 앱 표면, 입력 면은 밝은 종이색이다. 제품명·화면 제목·폼·보조 동작 순서로 정렬하며 장식 이미지나 마케팅 문구를 넣지 않는다. 설치 단계 수는 이 문서가 새로 정하지 않는다.

### 설정

기존 [설정 화면 설계 §1.2](../spec/04.screen-design-settings.md)의 `min(1200px, 94vw)` 폭, `min(820px, 90vh)` 높이, 좌측 260px 분할을 따른다. 우측 패딩은 24px이다. 일반 조건에서는 우측 콘텐츠가 주 스크롤을 담당하고 제목·도구·액션은 보존한다.

14개 카테고리를 개인 / 워크스페이스 / 인스턴스 구역으로 묶는다. 권한에 따라 숨겨야 하는 카테고리는 비활성 메뉴로 남기지 않는다. 문서 공유·버전 기록은 설정 메뉴에 넣지 않는다.

기존 설계의 최소 뷰포트는 1280×720이다. `IR-SHELL-008`은 200% 확대에서도 두 열을 유지하되 좌측 카테고리와 우측 본문에 독립 세로 스크롤을 허용하고 제목·닫기 행을 그 밖에 두도록 확정했다. 유효 CSS 폭 900px 미만의 좌측은 min(260px,32%), 우측 여백은 16px이다. 마지막 카테고리와 실행 조작에 도달해야 하며 overflow:hidden으로 감추지 않는다. 모바일 화면 도입은 포함하지 않는다.

### 표·목록과 관리 화면

표 헤더는 앱 배경, 행은 밝은 표면을 사용한다. 기본 행 높이는 최소 40px, 줄바꿈한 행은 자연스럽게 늘린다. 텍스트 왼쪽·숫자 오른쪽·행 동작 오른쪽 정렬을 사용한다. 열 제목과 정렬 상태를 구분하고 선택·호버·키보드 포커스를 서로 다른 상태로 표현한다.

긴 경로는 필요한 끝부분을 식별할 수 있게 표시하고 전체 값을 키보드로도 확인할 수 있는 수단을 둔다. 권한으로 감춘 정보를 tooltip에 되살리지 않는다. 사용자·그룹·감사·휴지통에 같은 표 외관을 쓰되 필터와 동작은 각 SRS에서 정한 것만 제공한다.

## 7. 편집기와 복합 콘텐츠

- 읽기와 라이브 프리뷰는 동일한 본문 색상·타이포그래피를 사용한다. 원문 노출이 문서 전체 폭이나 행 위치를 크게 바꾸지 않게 한다.
- 코드 블록·인라인 코드는 본문보다 한 톤 어두운 중립 배경과 고정폭 글꼴로 구분한다. 구문색은 토큰화하며 기존 하이라이터의 밝은 테마 고정을 방치하지 않는다.
- 표는 행·셀 경계를 절제하고 숫자 정렬을 유지한다. 긴 표는 표 영역에서 스크롤한다.
- 인용은 얇은 잉크 블루 세로선, 태그는 옅은 선택 배경과 글자로 표현한다.
- 수식은 KaTeX의 배치·접근성 스타일을 보존한다. Mermaid는 앱 테마와 같은 표면·글자·선색을 사용하도록 연동한다.
- 코드·수식·다이어그램 오류는 원문을 확인할 길과 함께 인라인 오류로 표시한다.
- 비교·병합은 추가·삭제 색상과 기호/라벨을 함께 사용한다. 신문지 분위기를 이유로 차이 표시를 회색 하나로 통일하지 않는다.
- CodeMirror 위젯 여백 변경은 높이 측정과 클릭 좌표에 영향을 줄 수 있다. 기존 padding 기반 보정을 유지하며 테스트한다.

## 8. 테마와 CSS 구성

아래는 후속 구현의 권장 파일 배치이며 이번 작업에서 생성하는 제품 파일 목록은 아니다.

```text
styles/
  index.css                 # 공통 진입점
  palette.css               # 실제 색상값
  tokens.css                # 글꼴·간격·반경·깊이
  base.css                  # 기본 문서와 포커스
  shell.css                 # 셸 배치
  themes/
    newspaper-light.css     # 팔레트 → 의미별 색상
    newspaper-dark.css      # #45 시안 독립 검증 후 #46에서 작성
  integrations/
    editor.css              # 의미별 색상 → 편집기 변수
components/ui/              # shadcn/Radix 공통 부품
```

컴포넌트에는 HEX를 직접 적지 않는다. 팔레트 → 의미 토큰 → 컴포넌트의 순서로 사용한다. shadcn 변수 대응은 `background`=앱 표면, `foreground`=기본 글자, `card`/`popover`=컨트롤 표면, `primary`=잉크 블루, `primary-foreground`=버튼 글자, `accent`=선택 배경, `accent-foreground`=잉크 블루, `muted-foreground`=보조 글자, `border`=구분선, `input`=컨트롤 경계, `ring`=포커스다. shadcn의 `accent`는 여기서 브랜드 강조색이 아니라 선택 표면이라는 점에 유의한다. destructive는 오류색과 읽을 수 있는 전경색을 한 쌍으로 정의한다.

테마 속성은 문서 루트에서 관리해 body 포털까지 상속한다. `IR-SHELL-007`에 따라 개인 테마 설정은 DB 정본이고 캐시는 인증 사용자별 현재 탭 메모리에만 둔다. 인증 확인 전 첫 페인트는 OS 테마이며 영속 브라우저 캐시를 사용하지 않는다. 시스템 선택은 OS 변경을 추종하고 로그아웃·세션 무효·계정 변경 때 캐시를 폐기한다. 편집기 내부에 직접 선언된 변수는 상위 토큰 선언만으로 덮이지 않을 수 있으므로 integration 계층에서 범위·우선순위를 명시한다.

shadcn 기본 스타일을 그대로 섞지 않고 공통 래퍼에서 크기·반경·토큰을 맞춘다. [shadcn 공식 테마 문서](https://ui.shadcn.com/docs/theming)의 CSS 변수 방식에 맞춘다. Tailwind를 쓰더라도 원색·상태값을 화면 JSX마다 반복하지 않는다.

## 10. 적용 검증 기준

구현에서는 각 관련 요구사항에 대해 동작 테스트를 먼저 실패시키고 최소 변경으로 통과시킨다. 시각 변경은 기준 화면과 실제 계산 스타일·기하 검사를 함께 사용한다. 테스트가 존재한다는 이유만으로 시각 검증을 완료 처리하지 않는다.

- 1280×720, 1440×900, 1920×1080에서 본문·카테고리·액션이 잘리지 않는가.
- 키보드만으로 폼·메뉴·모달을 열고 닫으며 포커스가 돌아오는가.
- 일반/호버/포커스/선택/비활성/오류/처리 중 상태를 각각 확인했는가.
- 실제 배경과의 글자·컨트롤 대비를 측정했는가. 색상만 제거해도 상태를 구분하는가.
- 긴 한글 이름·경로·오류 문구, 빈 목록과 대용량 목록, 브라우저 200% 확대를 확인했는가.
- 편집기 포커스·한글 IME·클릭 좌표·자동 저장·병합 흐름이 유지되는가.
- 포털·편집기·수식·코드·Mermaid의 테마가 함께 바뀌는가. 다크는 별도 시안 확정 및 검증 전 완료로 보지 않는다.
- 일반 사용자·워크스페이스 관리자·슈퍼유저의 정보 노출 경계를 유지하는가.
