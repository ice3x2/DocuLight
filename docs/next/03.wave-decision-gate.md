## 2. 제가 처리하려는 것 — 이견 있으시면 말씀해 주십시오

### 처리 1 — `R33-a` 가 `R21` 개정을 따라오지 않았습니다

원장(SSOT)의 현재 문면입니다.

> `R33-a` | 빌드 산출물(정적 파일)은 **기존 Express 가 그대로 서빙**한다. Node 프로세스는 1개를 유지한다
> | 비고: 동일 오리진이라 CORS·CSRF 문제가 없고 **기존 PM2 배포 구성을 그대로 쓴다**

그런데 `R21` 이 2026-08-19 에 **백엔드 전부 신규 작성**으로 개정됐습니다. 2.0 의 Express 는 새것이라
*"기존 Express"* 에는 가리킬 대상이 없습니다. SRS 쪽 `OPS-ARCH-001` 은 이미 고쳐졌는데
**원장이 따라오지 않아 SSOT 와 파생 문서가 어긋난 상태**입니다.

`R124-a` 가 *"조항을 개정하면 그것을 인용하는 모든 자리를 함께 훑는다"* 를 명령하므로,
이것은 **새 결정이 아니라 밀린 스윕**입니다. 방향은 `R21` 이 이미 정했습니다.
독립 심의를 붙여 문면을 확정하겠습니다 — 게이트 2 의 답이 그 비고에 함께 들어갑니다.

### 처리 2 — wave 별 target 을 새로 만들지 않고 `phase-1` 을 씁니다

`kiwi-wave-master` 의 기본 경로는 wave 마다 `wave-{n}` target 을 만들어 SRS 를 저작하는 것입니다.
**이 저장소에서는 그렇게 하면 안 됩니다** — 250건이 이미 `phase-1` 에 저작돼 있고, 다시 저작하면
같은 사실이 두 곳에 적힙니다. 그것을 금지하는 것이 **`CON-ARCH-008`(한 사실은 한 곳에)** 이며,
**Phase 1 요구사항 자신**입니다. Phase 1 을 구현하면서 Phase 1 요구사항을 어길 수는 없습니다.

그래서 wave 는 `phase-1` target 안에서 **요구사항 ID 부분집합**으로 범위를 한정합니다.
스킬의 저작 단계는 이미 충족된 것으로 표시합니다(이전 세션의 `kiwi-srs` 실행이 그 저작입니다).
