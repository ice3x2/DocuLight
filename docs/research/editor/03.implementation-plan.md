## 2. 개선 전략 — 3계층

`atomic-editor` 는 활발히 개발 중입니다(2026-04 시작, 8월까지 73커밋).
무작정 고치면 **upstream 버그픽스를 받을 수 없게 됩니다.**

작업을 **코어를 얼마나 침범하는가**로 분류하고, **C 를 최소화**하는 것을 원칙으로 합니다.

### 계층 A — 코어 무수정 (`extensions` prop 주입)

| 대상 | 방식 | 참고 |
|---|---|---|
| Mermaid | 표준 `FencedCode` + `CodeInfo === 'mermaid'` 판독 → 블록 위젯 | `image-blocks.ts` |
| KaTeX `$…$` `$$…$$` | 텍스트 스캔 | `wiki-links.ts` |
| `![[…]]` 첨부 임베드 | 텍스트 스캔 | `wiki-links.ts` |
| §3.6 자동 저장 · `Ctrl+S` | `EditorView.updateListener` + `keymap` | — |
| §3.5 첨부 붙여넣기 · 드래그 | `EditorView.domEventHandlers({paste, drop})` | SilverBullet `editor_paste.ts` |
| §3.7 병합 뷰 | `@codemirror/merge` 별도 컴포넌트 | 에디터와 무관 |

### 계층 B — 래퍼 자체 구현

`AtomicCodeMirrorEditor.tsx`(815 LOC)는 **참고만** 하고 우리 래퍼를 씁니다.

이것이 해금하는 것:

| 해금 | 이유 |
|---|---|
| §3.3 소스 모드 | Compartment 로 프리뷰 확장 on/off |
| **파서 레벨 커스텀 문법** | `markdown({extensions})` 를 우리가 통제 |
| 하이라이팅 언어 추가 | `codeLanguages` 를 우리가 통제 |
| §5 인터페이스 계약 | `MarkdownEditorOptions` 를 우리 형태로 |

> **래퍼 교체가 확장의 잠금해제 열쇠입니다.** 착수 순서 1번인 근거입니다.

### 계층 C — 코어 패치 (upstream 과 갈라짐)

| 대상 | 파일 | 선행 조건 |
|---|---|---|
| §3.2 인라인 노드 단위 판정 | `inline-preview.ts:495` | **옵시디언 실물 대조** |
| §4.5 뷰포트 한정 전환 | `inline-preview.ts:395` · `:916` | **수천 줄 실측** |
| 깨진 링크 스타일 세분화 | `wiki-links.ts` | — |

**각 패치를 별도 커밋으로 격리**하여 upstream rebase 가 가능하도록 유지합니다.

## 4. 소스 디렉터리 격리 (제안 — 채택됨)

> **〔2026-08-21〕 이 절은 규범이 아니다.** 여기 적힌 레이아웃은 제안이었고
> 이후 저장소에 실제로 구현됐다. **지금의 권위는 저장소 자신과 `docs/spec/`
> 이며 이 문서가 아니다** — 둘이 어긋나면 저장소가 이긴다. 설정·코드가 이
> 절을 근거로 인용하지 않는다(`CON-ARCH-007` AC-2).
>
> **남은 것** — 모노레포 소스 레이아웃을 규정하는 요구사항이 `docs/spec` 에
> 아직 없다. `CON-ARCH-003`(Vite·React·정적 산출물)과 `CON-ARCH-005`(패키지
> 선택)는 레이아웃을 다루지 않는다. 그 요구사항을 세우는 것은 ARCH scope 가
> 다시 열리는 자리의 몫이다.

에디터 소스만 존재하는 공간을 만들어, 나머지 애플리케이션과 독립적으로 개발·테스트·브라우저 확인이 가능하게 합니다.

## 5. ⚠️ 착수 차단 사항

### 5.1 SpecKiwi SRS 게이트 (필수)

2026-08-12 실측:

| 항목 | 값 |
|---|---|
| work-mode | `wait` (= sdd 규칙 적용) |
| Active Target | **비어 있음** |
| 요구사항 총계 | **0건** |
| 등록 scope | `02.product-architecture.srs.md` (요구사항 0건) |

CLAUDE.md 규정:

> - Agents MUST NOT **implement behavior that is not covered by an SRS requirement.**
> - If `activeTarget` is empty, **report that no active target is set and ask** which target to use.
> - If no matching requirement exists, **stop and ask** whether to create/update an SRS requirement first.

→ **코드 착수 전에 다음 중 하나를 선택해야 합니다.**

| 경로 | 절차 | 특징 |
|---|---|---|
| **A. sdd (정석)** | Active Target 설정 → Editor scope SRS 생성 → 요구사항 작성 → 구현 | 규정 정합. 선행 문서 작업 필요 |
| **B. tdd (단축)** | `set_work_mode(tdd)` → step SDS 작성 → red → green → **사후 SRS 승격** | CLAUDE.md 가 명시 허용. step 범위 한정 |

> CLAUDE.md: *"In tdd mode the rule 'do not implement behavior not covered by an SRS requirement' is
> satisfied for step-scoped work by the agreed SDS plus the mandatory post-hoc promotion."*

기능 요청서 `02.feature-request-live-preview.md` 가 이미 스펙에 준하는 밀도를 갖추고 있어,
**경로 B 로 SDS 를 도출하는 편이 중복이 적습니다.** 다만 mode 전환은 사용자 결정 사항입니다.

### 5.2 git 미초기화

리포가 **git repository 가 아닙니다** (`git rev-parse` 실패).

vendor 전략은 upstream diff·rebase 를 전제하므로 **git 초기화가 사실상 선행 조건**입니다.
최소한 vendor 도입 시점의 pristine 사본을 커밋해 두어야 이후 우리 패치를 분리할 수 있습니다.

### 5.3 문서 번호 충돌 (경고)

`speckiwi` 진단 `SRS-W072`:

> `02.feature-request-live-preview.md` shares the leading number 2 with the scope document `02.product-architecture.srs.md`

scope 문서와 번호가 겹칩니다. SRS 작성 시 정리가 필요합니다.
