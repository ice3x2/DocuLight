## 2. 카테고리 배제 — ProseMirror 계열

**Milkdown · Tiptap · MDXEditor · Vditor** 는 검토 대상에서 구조적으로 배제됩니다.

이들은 문서를 **AST 로 보관**합니다. `**bold**` 를 입력하면 별표가 **소비되어 사라지므로**,
커서가 돌아왔을 때 **되살릴 원문이 존재하지 않습니다.**

CodeMirror 6 는 반대입니다 — 문서가 **소스 문자열 그 자체**이고 데코레이션이 그 위에 얹힙니다.
"커서가 들어오면 마커를 드러낸다"가 구조적으로 자연스럽습니다.

→ **R33-d(CodeMirror 를 본문 SSOT 로 둔다)와 ProseMirror 계열은 양립 불가**입니다.

## 3. 채택안 — `atomic-editor`

`Atomic` 이라는 개인 지식베이스 앱의 편집 표면을 라이브러리로 분리한 것.

| 항목 | 값 |
|---|---|
| 저작권 | Copyright (c) 2026 Kenny Bergquist |
| 라이선스 | **MIT** |
| 언어 | TypeScript |
| 구현부 | **4,962 LOC** (테스트 별도 1,123 LOC) |
| 최초 커밋 | 2026-04-22 |
| 참조 커밋 | `b6ed65f` (v0.6.2, 2026-07-11) |

### 3.1 선정 근거

1. **기능 요청서 §4 기술 제약과 우연히 일치합니다** — R33-d(본문 비-state), R33-c(프레임워크 중립), StrictMode 가드가 모두 이미 만족됩니다. 상세는 [02 문서](./02.atomic-editor-analysis.md) §2.
2. **§8-1 이 최난제로 지목한 표가 해결되어 있습니다** — WYSIWYG 셀 인플레이스 편집, 1,356 LOC.
3. **한글 IME 와 표가 실동작으로 검증되었습니다** (2026-08-12).
4. **규모가 판독 가능합니다** — 4,962 LOC 는 전량 읽고 개조할 수 있는 크기입니다.
5. **설계 주석이 충실합니다** — "왜 이 방법을 버렸는가"가 기록되어 있어, 기능 요청서 §8 난제 목록의 실전 답안 역할을 합니다.

### 3.2 라이선스 검토

MIT 는 copyleft 가 아닙니다. **사용 · 복사 · 수정 · 병합 · 배포 · 서브라이선스 · 판매**가 모두 허용되며,
사내 폐쇄 제품에 포함하고 소스를 비공개로 유지해도 됩니다.

의무는 **하나**입니다.

> *"The above copyright notice and this permission notice shall be included in all copies or substantial portions of the Software."*

→ vendor 디렉터리에 **원본 `LICENSE` 파일을 그대로 동봉**하면 충족됩니다.
소스 파일에는 저작권 헤더가 없으므로(grep 확인) 파일별 헤더 삽입은 불필요합니다.

## 4. 참조 구현 — SilverBullet

라이브러리가 아니라 앱이지만, `client/codemirror/` 아래 **52개 파일이 옵시디언식 라이브 프리뷰의 프로덕션 레퍼런스**입니다.

```
hide_mark.ts   table.ts          wiki_link.ts    fenced_code.ts
block_quote.ts list.ts           footnote.ts     editor_paste.ts
link.ts        markdown_enter.ts frontmatter.ts  task.ts   …
```

### 계보

`hide_mark.ts` 헤더에 출처가 명시되어 있습니다.

```
// Forked from https://codeberg.org/retronav/ixora
// Original author: Pranav Karawale
// License: Apache License 2.0.
```

**ixora (2023 방치) → SilverBullet (활발)** 이 이 분야의 실질 계보입니다.

### 채택하지 않는 이유

Preact 기반이고 앱 내부 `client` 객체에 강결합되어 있어 통째 추출이 어렵습니다.
**소스 참조 · 부분 이식** 용도로만 사용합니다.

### 우리가 가져올 것

| 대상 | 용도 |
|---|---|
| `hide_mark.ts` 의 `isCursorInRange` 판정 | 기능 요청서 §3.2 **노드 단위** 판정 — `atomic-editor` 는 줄 단위 |
| `table.ts` · `footnote.ts` | 표·각주 처리 대조 |
| `editor_paste.ts` | 첨부 붙여넣기(§3.5) 참고 |

> **라이선스 주의**: SilverBullet 전체는 MIT 이나, ixora 유래 파일은 **Apache-2.0** 입니다.
> 해당 파일의 로직을 이식하면 **NOTICE 유지 의무**가 발생합니다. 둘 다 허용적이지만 표기가 다릅니다.

## 5. 한글 IME — 조사 시점 리스크와 실측 결과

### 조사 시점 (정적 분석)

기능 요청서 §4.2 / 수용기준 7 이 지목한 리스크를 뒷받침하는 증거가 있었습니다.

**SilverBullet Issue #1894** (2026-03-17, **열린 상태**)

> **[Bug] Korean IME: Last character lost when composition interrupted on macOS**
> 재현: "하기" 입력 → Space 없이 → `→` / `↓` / `Enter` → **"하"만 남고 "기" 소실**
> 보고자 진단: *"known Chromium + macOS Korean IME bug affecting CodeMirror-based editors"*

관련 이슈 **#1591** (2025-10, "First composition after list unwrap inserts raw key") 도 미해결.

`atomic-editor` 는 메인 프리뷰 플러그인에 `view.composing` 가드가 없고 (표 위젯 내부에만 존재),
IME 관련 이슈도 0건이었습니다 — 즉 **검증된 적이 없는 상태**였습니다.

### 실측 결과 (2026-08-12)

> **한글 입력 정상 동작 확인.** 표도 정상 동작 확인. — 사용자 검증

### 남는 것

- **macOS 미검증.** 위 SilverBullet 이슈는 **macOS 한정** 재현입니다. 사내 macOS 사용자가 있다면 별도 확인이 필요합니다.
- **경계 조건 미검증** — 조합 중 방향키 · Enter · 포커스 이동, 표 셀 안에서의 조합, 위젯 경계에서의 조합.
- → 수용기준 7 의 **수동 체크리스트는 여전히 필요**합니다. 리스크 등급만 내려갑니다.
