## 4. §3.2 판정 단위 — 줄 단위 (스펙은 노드 단위)

```
inline-preview.ts:495   shouldHide = !activeLines.has(lineNum);
```

`activeLines` 는 선택 영역이 걸친 **줄 번호 집합**입니다 (:387~393).
인라인 강조도 이 기준으로 드러납니다 — 즉 **한 줄에 `**굵게**` 와 `*기울임*` 이 같이 있으면 둘 다 동시에 드러납니다.**

예외는 링크뿐입니다. `activeLinkStarts` 로 **노드 단위** 판정합니다 (:416~421).

### 대조 — SilverBullet 은 노드 단위

```ts
// silverbullet/client/codemirror/hide_mark.ts
if (isCursorInRange(state, [from, to])) return;
```

→ 기능 요청서 §3.2 를 정본으로 유지한다면 **이 판정 로직을 이식**해야 합니다. 코어 패치입니다.

## 5. 성능 전략 — §4.5 와 정면 충돌 (근거 있는 반대 선택)

기능 요청서 §4.5 는 "데코레이션은 뷰포트 범위만 계산"을 요구합니다.
`atomic-editor` 는 **정반대를 의도적으로 선택**했고, 그 근거를 주석으로 남겼습니다.

`inline-preview.ts:395`:

> *"Decorate the whole parsed tree — not the current viewport — so that scrolling never needs to rebuild the decoration set. **Prior design walked viewport-only and rebuilt on every scroll, which on iOS caused scroll-up momentum halts** when new decorations were applied to lines at the top of the viewport (anchor conflict with the scroll animation). Cost: a one-shot whole-doc walk on every doc / selection / focus change instead of a smaller walk on every scroll."*

`inline-preview.ts:916`:

> *"`update.viewportChanged` is intentionally NOT in this list. Scrolling alone must not rebuild decorations… the tree walk itself is single-digit ms for typical atoms."*

### 함의

- **방향키 한 번에도 문서 전체 구문 트리를 순회**합니다.
- "single-digit ms" 는 **개인 노트 규모** 기준입니다. 사내 수천 줄 문서는 **미검증**입니다.
- `ensureSyntaxTree(state, doc.length, 200)` 로 전체 파싱을 강제합니다 (:412) — 대용량 문서에서 이 비용이 별도로 발생합니다.

### 주의

**측정 없이 뒤집지 마십시오.** 반대 방향에도 함정이 문서화되어 있습니다.
뷰포트 한정으로 되돌리면 iOS 스크롤 문제가 되살아납니다.

> 참고: **같은 저장소 안에 두 전략이 공존합니다.**
> `wiki-links.ts` 는 `findWikiLinksInVisibleRanges` 로 **뷰포트만** 스캔합니다 (:421).
> 즉 저자도 일괄 적용하지 않았습니다.

## 7. 보기 전용 모드 — 있음 (단, 옵시디언 읽기 모드와 다름)

`read-only.ts` 전문 49 LOC. 두 레버를 함께 겁니다.

| 레버 | 목적 |
|---|---|
| `EditorView.editable.of(!ro)` | **UX 레버.** contentDOM 이 contenteditable 이 아니게 되어 캐럿이 없어짐 → reveal 이 발동하지 않음 → **문서 전체가 렌더 상태로 고정** |
| `EditorState.readOnly.of(ro)` | **방어 심층화.** paste / drop / IME 편집 차단 |
| `readOnlyFacet` | `inlinePreview` · `tables` 가 읽어 동작 분기 |
| `.cm-atomic-readonly` 클래스 | 스타일 훅 |

Compartment 안에 배치되어 **remount 없이 토글되고 스크롤이 보존**됩니다 (`AtomicCodeMirrorEditor.tsx:369`).
태스크 체크박스는 **의도적으로 계속 동작**합니다 (명시적 `view.dispatch` 는 `EditorState.readOnly` 에 막히지 않음).

### ⚠️ 옵시디언 읽기 모드와의 차이

옵시디언 읽기 모드는 **별도 HTML 렌더러**입니다. 이것은 **같은 CM6 데코레이션 표면을 고정**한 것입니다.
따라서 §3.1 9종 범위 밖(각주, 목차, 표 정렬 등)은 렌더되지 않습니다.

**R91(보기 권한만) 관점에서는 오히려 유리합니다** — 편집 화면과 보기 화면의 렌더 결과가 100% 동일해서
불일치가 원천적으로 발생하지 않습니다. 다만 "옵시디언 읽기 모드와 동일"을 요구한다면 갭입니다.

→ **미결 항목 3** (인덱스 참조).

### 구현 방향 (검증된 경로)

`readOnly` 와 **동일한 Compartment 패턴**으로 처리됩니다.

```ts
const previewCompartment = new Compartment();

// 라이브 프리뷰 상태
previewCompartment.of([

  imageBlocks(),
```

## 9. 확장점 — 전용 플러그인 API 는 없습니다

### 9.1 공개 config 는 콜백뿐

```ts
InlinePreviewConfig { onLinkClick? }                       // 1개
TablesConfig        { onLinkClick? }                       // 1개
WikiLinksConfig     { suggest?, resolve?, shouldResolve?,
                      onOpen?, openOnClick?,
                      serializeSuggestion?, maxSuggestions?, debounceMs? }
```

**위젯 등록소 · 노드 등록소 · 렌더러 훅이 없습니다.**
`HIDEABLE_SYNTAX` · `BLOCK_CLASSES` 등 판정 테이블은 모듈 내부 `const` 이며 export 되지 않습니다.

### 9.2 확장점 A — `extensions` prop (순수 CM6 Extension)

```ts
extensions?: readonly Extension[];   // AtomicCodeMirrorEditor.tsx:235
```

내장 확장 **뒤에** 붙습니다 (:375). 저장소 안에 **참고할 선례가 두 개** 있습니다.

#### `image-blocks.ts` — 블록 위젯 선례

CM6 제약이 주석에 명시되어 있습니다.

> *"Block widgets can't come from a ViewPlugin (CM6 requires them to originate from a StateField or a mandatory facet)"*

**Mermaid · 디스플레이 수식이 정확히 이 패턴입니다.**

⚠️ **함정** — 같은 파일의 `dimensionCache` 주석:

> 위젯이 마운트 **후에** 커지면 heightmap 이 스크롤 애니메이션 도중 자라고, iOS 에서 관성 스크롤이 멈춘다.

**Mermaid 는 렌더가 비동기라 정확히 이 케이스에 걸립니다.**
렌더 결과 크기를 캐시하고 placeholder 에 미리 크기를 잡아야 합니다. `dimensionCache` 패턴을 그대로 따르십시오.
(기능 요청서 §8-5 의 "lazy 렌더"만으로는 부족합니다.)

#### `wiki-links.ts` — 커스텀 문법 선례 (파서 무개조)

`[[위키링크]]` 는 표준 마크다운에 없는 문법인데, **파서를 전혀 건드리지 않고** 구현되어 있습니다.
import 부에 `@lezer/markdown` 도 `syntaxTree` 도 없습니다. 순수 텍스트 스캐너입니다.

| 함수 | 역할 |
|---|---|
| `findWikiLinksInVisibleRanges` (:421) | **뷰포트 범위만** 스캔 |
| `findWikiLinksInLine` (:455) | 라인 단위 파싱 |
| `fenceStateBeforeLine` (:511) | 코드펜스 안인지 직접 판정 |
| `inlineCodeSpans` (:529) | 인라인 코드 안인지 직접 판정 |

> 뒤의 두 함수가 **이 방식의 숨은 비용**입니다. 코드블록 안의 `[[abc]]` 를 링크로 만들면 안 되므로,
> 파서가 공짜로 주는 문맥 판정을 직접 구현해야 합니다.

### 9.3 확장점 B — `MarkdownConfig` (파서 레벨) ⚠️ 제약 있음

`==하이라이트==` 는 진짜 파서 확장으로 구현되어 있고 **export 도 됩니다**.

```ts
// highlight.ts
export const highlightMarkdown: MarkdownConfig = {
  defineNodes: [{ name: 'Highlight', style: t.special(t.content) }, …],
  parseInline: [{ name: 'Highlight', parse: parseHighlight, after: 'Strikethrough' }],
};
```

**그런데 `extensions` prop 으로는 주입할 수 없습니다.** 래퍼가 하드코딩합니다.

```ts
// AtomicCodeMirrorEditor.tsx:338
markdown({
  base: markdownLanguage,
  codeLanguages: [...codeLanguages],   // ← 고정
  extensions: highlightMarkdown,       // ← 고정
}),
```

`@lezer/markdown` 파서는 **생성 시점에만** 구성되며 런타임 추가 경로가 없습니다.

→ **파서 레벨 확장을 쓰려면 래퍼 교체가 강제됩니다.** 하이라이팅 언어 추가도 마찬가지입니다.

### 9.4 두 방식 비교

| | **A. 텍스트 스캔** (wiki-links 방식) | **B. 파서 확장** (highlight 방식) |
|---|---|---|
| 주입 경로 | `extensions` prop ✅ | **래퍼 교체 필요** |
| 코드펜스 · 인라인코드 회피 | 직접 구현 | 파서가 처리 |
| 중첩 · 우선순위 | 수동 | `after: 'Strikethrough'` 선언 |
| 성능 | 뷰포트만 스캔 가능 | 증분 파싱 |
| 적합 대상 | `[[…]]` `$…$` 처럼 구분자가 뚜렷한 것 | 복잡한 중첩 문법 |

> **래퍼를 자체 구현하면 이 제약이 사라집니다.**
> `markdown({ extensions: [highlightMarkdown, ...우리 문법] })` 를 우리가 통제하게 되어 A·B 양쪽이 열립니다.
> §3.3 소스 모드 때문에 **어차피 래퍼는 자체 구현해야 하므로**, 래퍼 교체가 확장의 잠금해제 열쇠입니다.

## 10. 스타일 커스터마이징 — 완전히 가능

**39개 CSS 변수**가 노출되어 있습니다.

```
--atomic-editor-fg / -fg-muted / -fg-faint
--atomic-editor-bg / -bg-panel / -bg-surface
--atomic-editor-accent / -accent-bright / -accent-soft
--atomic-editor-link / -link-hover
--atomic-editor-font / -font-mono / -body-size / -body-leading / -measure
--atomic-editor-hl-{keyword,string,number,comment,type,function,property,
                    regexp,escape,tag,variable,operator,invalid}
--atomic-editor-border / -radius / -code-bg / -code-rail
--atomic-editor-selection-bg / -search-bg / -search-bg-active
--atomic-editor-initial-reveal-bg / -initial-reveal-bg-strong
```

| 위치 | 내용 |
|---|---|
| `.atomic-cm-editor` (`inline-preview.css:28`) | 다크 기본값 |
| `[data-theme="light"] .atomic-cm-editor` (:775) | 라이트 오버라이드 |

### 적용 규칙

1. 변수로 덮지 못하는 레이아웃·간격은 `.cm-atomic-*` 클래스 직접 오버라이드
2. `styles.css` **뒤에** 우리 CSS 를 로드
3. vendor 하면 `inline-preview.css`(30KB) 자체를 편집해도 됨

### R1 관점 제안

옵시디언 변수명(`--text-normal` · `--background-primary` …)으로 **매핑 레이어를 한 겹** 두면
옵시디언 테마 CSS 를 거의 그대로 얹을 수 있습니다. 한 번 만들면 테마 대응 비용이 사라집니다.
