## Validation, search state and stale selections

Reuse #72's server/client name validator: NFC normalize then trim both ends; require 1–120 Unicode code points; reject U+0000–U+001F and U+007F in the normalized trimmed value. Count code points, not UTF-16 units; do not silently truncate with HTML maxlength. Preserve the typed field on failure; use the normalized value in confirmation and POST. Accept duplicate names, path punctuation and reserved filenames as display names; never query global duplicate availability.

Validate required fields before opening L2. Initially disable `만들기` until administrator selection, with persistent explanation; submission also guards blank/invalid name and stale/missing administrator. Invalid name receives `aria-invalid`, linked field error and focus on submit. Composition changes do not trigger validation/focus jumps; validation is on blur/submit, with subsequent corrections after an error.

Picker states are idle (`두 글자 이상 입력하세요`), loading, successful empty, results and safe failure with query retry; the current catch-to-empty is not evidence of an empty result. Use the shared picker improvement, not a fork. A different search query does not by itself revoke a separately displayed selection. Replacing/removing the selected principal or changing any form field invalidates the frozen confirmation/warning request. Late requests cannot repopulate another query, form mount or identity. Server rejection `unknown-administrator` retains the form and explains that the target must be selected again; remove its actionable selection. Do not infer current existence or eligibility from an empty warning array. Search omission is not proof of deletion. Existing createWorkspaceAs checks existence only; stronger current-status/system-group restrictions are not established by this issue and must not be silently invented.

## One L2 and fresh warning context

Every valid form submission opens exactly one L2 risk dialog, even default `없음` and no warnings. Submit alone sends no creation request. It contains normalized workspace name, selected administrator name/kind/status and `관리`, `default` plus selected initial level, and all applicable warnings. It never displays affected/reached/accessor counts, a count-recount control, L3 text token, a second permission confirmation, or an automatic grant before creation.

Use existing server `grantWarnings` for suspended-subject and open-signup-edit. Actual HTTP `GET /grant-warnings` currently forwards principalId/entryId only, although the service also accepts defaultGroupLevel. Required narrow adapter: for the superuser creation context, pass a validated `none|view|edit` defaultGroupLevel to that service and expose its existing reason-code array; preserve old consumers. Do not trust optional signupMode being absent as evidence the instance is not open. A fresh existing settings query may supply immediate form guidance; the L2 must obtain current warning facts for its selected principal/default tuple. No warning query error is interpreted as no warnings.

While warning facts load, show `권한 부여 내용을 확인하는 중입니다`, disable execution and retain Cancel. Failure shows safe retry in this same dialog. At execution re-read warnings; if changed, keep the same dialog, present the new warning set and require another explicit activation. No mutation until the displayed normalized input/selected ID/default level and latest warning context match. This is a preflight guard, not a server reservation: no atomic preview version/token exists and do not claim it prevents all concurrent policy changes. Server rechecks superuser and administrator existence at execution.

Preserve the required delayed-effect notice, but make its subject precise: `워크스페이스와 초기 권한은 지금 생성됩니다. 앞으로 추가되는 문서에는 설정한 권한이 적용됩니다. 이미 열람한 내용은 권한을 회수해도 되돌릴 수 없습니다.` Pair default view/edit with existing inheritance explanation where applicable; do not imply workspace-admin authority is defeated by a broken descendant inheritance flag. Existing ConfirmGate's generic `다음 정리 시점` text is false for creation. A narrowly scoped custom delayed-notice slot/prop is allowed, retaining generic defaults for unrelated consumers and the creation delayed-notice accessible region. This does not change confirmation grade or defer the actual creation.

Risk focus starts on Cancel. Cancel/Escape before mutation closes only L2 and restores focus to `만들기`; form values remain. Risk overlay uses shared layering and focus trap. During actual pending commit suppress another execution and dismissal/navigation that would discard the only result owner; preserve a visible `만드는 중입니다` status. Do not equate aborting a fetch or closing a dialog with cancelling server creation. Resolve ordinary input/picker Enter and composing Enter before form handling, so selecting a principal or committing Korean text cannot open/execute L2.

## Required integration and truthful outcomes

1. Add the bounded authenticated `POST /api/workspaces` route/client method that invokes existing `createWorkspaceAs`, not createNode or a client series of independent create/grant calls. Request is exactly `{name:string,administratorId:string,defaultGroupLevel:'none'|'view'|'edit'}`. Validate types, name and enum before any mutation; do not coerce unexpected levels to a wider permission. Existing domain omission default `none` remains unchanged for existing non-HTTP callers. Live actor authority is mandatory.
2. Proposed wire success is HTTP201 `{workspace:{id,name,createdAt}}`, projecting existing `{ok:true,workspace}`. This is a required new adapter shape, not a claim it exists today. Existing `{ok:false,rule:'needs-superuser'}` maps to403; `unknown-administrator` to safe400 field failure. Input-validation400 returns a finite field classification for name/administrator/default level. Never return filesystem paths, SQL, stack traces or raw exception messages. Other HTTP/network failures use generic safe text and the uncertainty rules below.
3. Replace optional void onCreate with a required promise-bearing creation callback/result. Keep the accepted returned workspace ID distinct from any later refresh result. No immediate gate close, list success, field reset or parent callback before real accepted201. Missing callback cannot create a fake success path. Pending guards exist synchronously in the submission owner as well as disabled controls; rapid double click/Enter sends one POST per attempt. This is client duplicate prevention, not server idempotency.
4. On accepted201, store the returned ID/name in the parent creation owner, close the risk dialog and switch back to the all list with an observable parent-owned polite success status. Refresh all/managed lists, scope choices, relevant session counts and shell workspace data through existing #72 ownership. Select the returned ID, never search by display name. Preserve the ID as desired selection while fresh lists load. Do not fabricate adminless or fabricate a list row to make selection appear successful.
5. If refresh fails after accepted201, retain `워크스페이스를 만들었습니다. 목록을 새로 불러오지 못했습니다.` and a read-only `목록 다시 불러오기` action; POST must not repeat. The parent keeps the accepted identity until reads settle. If a fresh authoritative list excludes the ID because authority changed, show the safe current-access outcome, use #72 fallback, and do not reveal more details or switch back to an executable creation attempt.
6. Before-request/known rejected validation or authorization outcomes retain the draft; a retry after correction requires a fresh L2. A warning-fetch failure retries only the read. Successful creation clears the old draft only after its accepted result is owned above the unmounted form. Cancellation before POST returns to the prior list selection/scroll and focuses the originating `새 워크스페이스`; if absent, focus the list heading. Success focuses the selected row's management action after actual refreshed mounting, falling back to parent status/heading while loading or if the row vanishes. No row index assumptions, focus to body, or scroll-to-top on every read.

Current service semantics are preserved: generate server identity and directory/sidecar, create an admin ACL for the selected principal, omit default ACL for `none`, otherwise grant exactly view/edit. Existing grantedBy/null and creation plus correlated grant audit records stay with the service. The creator's superuser authority is not an invented second admin ACL. A group administrator is an ACL principal, not a request to edit membership. Verify resulting access through actual sessions, not only the POST body.

## Explicit recovery and contract gaps

**B1 — partial storage failure.** createWorkspaceAs calls createWorkspace, which inserts the workspace record before asynchronous directory/sidecar writes; ACL/audit follow. It has no demonstrated atomic rollback/recovery contract. A thrown error can therefore leave an incomplete workspace. #72 rename's `sidecarSync=pending` contract does not apply to creation; never manufacture that success. Preserve draft and show `생성 완료 여부를 확인하지 못했습니다. 다시 만들기 전에 전체 목록을 확인하세요.` for potentially committed/unclassified failures, with navigation to refresh the all list. Do not claim nothing changed, grants completed, or a failed request is safely retryable. Failure-injection evidence must expose the actual state. Reliable partial-create repair/compensation requires separate SRS/scope before promising all-or-nothing creation.

**B2 — lost response/idempotency.** Existing service/HTTP contract supplies no idempotency key or request-to-workspace lookup. Network timeout/abort after POST may mean success. Disable repeating that uncertain attempt, retain values and offer list inspection; duplicate display names are allowed, so a name match cannot establish the created ID. No automatic retry, UUID header fiction, inferred success, automatic delete or undo. Cross-tab/reload exactly-once behavior and guaranteed recovery of an unknown ID are unsupported. An explicit later new attempt is a new operation, not a claimed retry guarantee; do not advertise an idempotent retry action until a contract is supplied.

**B3 — fresh administrator eligibility.** Principal search excludes rejected subjects, but service execution currently accepts any existing principal. Warning endpoint is not an existence/status validation endpoint. Use actual search and execution rules; tests should document stale status/deletion behavior. A stronger “selected administrator always currently eligible” assurance needs a precise SRS-backed server rule; do not label it implemented merely because the picker omitted a row.

These gaps do not prevent designing the supported happy path, safe preflight/validation rejection, cancellation, or accepted-success/list-refresh handling. They prevent closing stronger atomicity, idempotency, repair or fresh-eligibility claims. No new policy or broad storage transaction project is silently authorized here.
