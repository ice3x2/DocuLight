## 문제와 결과

워크스페이스 관리자 부여는 L2 확인 전에 서버가 최신 권한 범위와 영향 정보를 권위 있게 계산해야 한다. 현재 공유 조회의 `reached`는 ACL 상속이 끊긴 하위를 제외하지만 워크스페이스 `admin`은 그 하위에도 적용되는 상방 게이트라, 이 값을 관리자 부여 영향으로 표시하면 실제 효과를 축소한다.

## 범위

- 워크스페이스 관리자 부여 전용 영향 미리보기 API 또는 동등한 서버 계약
- 현재 요청자의 관리 권한, 대상 워크스페이스와 주체, 고정 `admin` 레벨을 실행 직전에 재검사
- `FR-CONFIRM-004`, `FR-CONFIRM-011`, `FR-CONFIRM-012`, `SEC-WORKSPACE-002`에 맞는 한 번의 L2 확인 입력
- 미리보기 이후 관련 상태가 바뀌면 기존 동의를 잠그고 다시 조회

## 완료 기준

- [ ] 서버가 워크스페이스 관리자 부여의 정확한 적용 범위를 현재 DB/ACL 상태에서 계산한다.
- [ ] 상속 끊김을 view/edit 부여와 같은 방식으로 제외하지 않는다.
- [ ] 존재/권한 거부가 비가시 워크스페이스나 주체를 열거하지 않는다.
- [ ] UI는 이 응답이 없거나 오래됐으면 관리자 부여를 실행하지 않는다.
- [ ] 취소는 쓰기를 만들지 않고, 수락은 기존 ACL 부여 서비스를 한 번만 호출한다.

## 관련 작업

- #72 워크스페이스 관리·전체 목록 화면 연결 및 디자인 적용
- 요구사항: `IR-WORKSPACE-001` AC-3, `FR-CONFIRM-004`, `FR-CONFIRM-011`, `FR-CONFIRM-012`, `SEC-WORKSPACE-002`

관리자 제거는 기존 직접 ACL entry ID, L2, 마지막 관리자 경고 계약이 있으나 같은 화면의 추가/제거를 함께 안전하게 연결하려면 이 부여 관문을 먼저 닫는다.
