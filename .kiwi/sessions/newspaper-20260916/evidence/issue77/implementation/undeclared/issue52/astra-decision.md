## 2. 반드시 보존할 검색 의미

- 축은 기존 `SEARCH_AXES`의 **이름·본문·태그·첨부 이름** 넷이며 순서를 유지한다. 기본값은 이름 하나다. PDF 본문은 본문 축에 속하며 다섯째 축·PDF 페이지 이동을 만들지 않는다.
- `search-axes.ts`의 저장 키·직렬화·복원·깨진 값 fallback을 그대로 사용한다. 현재 세션에서 전부 해제할 수 있는 동작과, 빈 저장값이 다음 방문에 기본값으로 돌아오는 기존 동작도 바꾸지 않는다. 마지막 체크를 강제로 유지하거나 이름을 자동으로 켜지 않는다.
- 필터 변경은 **즉시 반영·기존 저장 경로 호출**이다. 적용/취소 버튼이나 별도 임시 선택 상태를 추가하지 않는다. 팝오버를 닫아도 변경을 되돌리지 않는다.
- 질의 상태는 App이 소유한다. 입력을 갱신하는 기존 검색 호출 시점과 query+axes 키를 유지한다. 새 debounce, Enter 제출 방식, URL 동기화, 질의 영속 저장을 도입하지 않는다.
- `cmdk`의 `shouldFilter={false}`를 유지한다. 서버 결과의 권한·순서·일치 판정을 클라이언트에서 다시 수행하지 않는다. 결과 개수나 거르기 전 분모를 새로 표시하지 않는다.
- 태그 클릭은 기존 두 진입점에서 검색 탭을 열고 같은 `#태그명` 질의 경로로 간다. #52에서 축을 태그로 강제 변경하거나 별도 결과 화면을 만들지 않는다.
- 한 결과 문서에 제목은 하나이며 서버가 준 발췌들이 그 아래에 쌓인다. 동일 문서의 발췌 수만큼 문서 제목/선택 항목을 복제하지 않는다.

## 3. 고정 검색+필터 영역

검색 패널 상단에 가시 라벨 **“검색”**을 둔다. 라벨은 13/20px, 입력과 연결하며 placeholder만으로 대신하지 않는다. 라벨 아래에는 입력과 필터 버튼을 **한 행**에 둔다.

| 항목 | 구속력 있는 기준 |
| --- | --- |
| 상단 고정 영역 | 패널 폭 안에서 좌우·상단 여백 8px, 하단 여백 8px; `flex-shrink:0` |
| 라벨과 입력 행 간격 | 4px |
| 입력 행 | 줄바꿈 없음, 입력·필터 높이 36px, 간격 8px |
| 입력 | 남은 폭 전부, `min-width:0`, 14/22px, 공통 입력 경계·배경·반경 4px |
| 필터 버튼 | 48×36px, 줄어들지 않음, 가시 문구 “필터”, 접근 가능한 이름 “검색 대상” |
| 입력 placeholder | “이름 · 본문 · 태그 · 첨부 이름”; 좁은 폭에서 잘리는 placeholder를 레이아웃 최소 폭으로 삼지 않음 |
| 안내 | 행 아래 6px 간격, 12/18px, “2자 이상 낱말을 포함해 입력하세요.”; 입력과 `aria-describedby` 연결 |

고정 영역은 일반 문서 흐름에서 결과 영역과 분리하며 viewport 기준 fixed 위치를 새로 만들지 않는다. 결과를 스크롤해도 라벨·입력·필터의 좌표가 변하지 않는다. 패널 폭 180px에서도 8px 좌우 여백, 8px 간격, 48px 필터를 유지하고 입력은 남은 108px를 사용한다. #50 셸의 열 폭·축소·설정 하단 바는 변경하지 않는다.

키 입력 또는 결과 조회 중에도 입력과 필터를 사용할 수 있다. 조회 중이라는 이유로 readonly/disabled를 붙이거나 초점을 결과로 옮기지 않는다.

## 4. 필터 팝오버

#48 공통 Radix Popover를 사용한다. 트리거의 `aria-expanded`·팝오버 연결과 초점 복원 계약을 유지한다. 검색은 page 소유 오버레이이며 다른 모달의 존재만으로 승격하지 않는다.

- 기본 폭 **240px**, 최대 폭 `calc(100vw - 48px)`, 패딩 **12px**, 반경 **6px**, 트리거 간격 **4px**, 우측 정렬(`align=end`)을 기본으로 하되 Radix collision 처리를 유지한다.
- 최대 높이는 실제 남은 공간과 viewport 바깥 여백 24px에 맞춘다. 넘칠 때 팝오버 내부 스크롤로 마지막 체크박스·설명에 접근한다.
- 가시 제목 **“검색 대상”**은 13/20px·600, 제목 아래 간격 8px이다.
- 네 체크박스는 세로 배치한다. 각 라벨 행은 최소 **36px**, 체크 표시와 문구 간격 **8px**, 문구 14/22px이다. #47 공통 Checkbox와 연결된 label을 사용한다. 체크박스와 라벨을 누르면 같은 축을 한 번만 변경한다.
- 체크된 상태는 실제 check 표시와 접근성 checked 값으로 드러낸다. hover는 `surface-control`/기존 공통 표현, focus는 2px 초점선과 2px 분리, 활성 팝오버 트리거는 공통 열린 상태 표현을 사용한다.
- 아래에는 8px 간격, 12/18px의 고정 문법 안내를 둔다: **“공백은 AND, |는 OR입니다. |로 나눈 각 묶음에 2자 이상 낱말이 필요합니다. 괄호는 문자로 검색합니다.”**
- 체크 변경 후 팝오버는 열린 채로 유지한다. Escape/바깥 클릭의 기존 닫기와 트리거 초점 복원을 보존한다. 팝오버 안 Space/Enter가 결과 문서를 열거나 외부 폼을 제출하지 않는다.

## 5. 결과 정보 계층과 G36 경계

각 서버 결과를 기존 cmdk 선택 항목 하나로 표시한다. 현재 응답 `SearchDocumentBody`에는 `nodeId`, `name`, `workspaceName`, `excerpts`만 있으며 **경로 필드는 없다**. #52는 경로를 새 API로 요청하거나 트리에서 합성하지 않고, 현재 워크스페이스 이름을 메타데이터로 표시한다. 응답에 없는 작성자·날짜·권한·전체 경로·PDF 이동 링크를 추가하지 않는다.

| 계층 | 표현 |
| --- | --- |
| 결과 그룹 | 최소 높이 40px, 좌우 8px·상하 8px 패딩, 그룹 사이 1px 장식 구분선 |
| 문서 제목 | 14/22px·600, `text-primary`, 문서마다 한 번 |
| 워크스페이스 이름 | 제목 아래 2px, 12/18px, 사이드바 전용 보조색 |
| 발췌 묶음 | 메타데이터 아래 6px, 각 발췌 사이 4px, 14/22px, `text-primary` |

제목·워크스페이스명·발췌는 긴 한글과 무공백 문자열도 행 안에서 줄바꿈한다. 최소 폭을 내용 길이로 밀어내지 않는다. 콘텐츠 양에 따라 높이가 자연스럽게 늘어나며 목록 전체가 스크롤한다. 그룹 내부에 별도 스크롤바를 만들지 않는다.

**G36 미결인 결과 상한·발췌 길이·일치 강조 방식은 결정하지 않는다.** 새 결과 수 제한, 페이지네이션, 더 보기, 발췌 글자 수 제한, line-clamp/말줄임, 발췌 재생성, `<mark>` 또는 부분 굵게 표시를 추가하지 않는다. 서버가 준 제목/발췌의 문자열·순서를 그대로 일반 텍스트로 표시한다. 현재 서버 구현의 발췌 길이 값을 새 규범으로 승격하지 않는다.

## 6. 선택·hover·focus와 비해당 상태

- default는 패널 표면과 기본 글자다. hover는 공통 hover 표면을 사용한다.
- selected는 **cmdk의 현재 선택 결과**를 의미한다. `surface-selected` 배경과 2px 세로 표식, 기존 `aria-selected`를 함께 유지한다. 열린 중앙 문서와 별도로 새로운 선택 상태를 만들지 않는다.
- focus는 선택 표식에 추가되는 2px 초점선·2px 분리 영역으로 표현한다. 스크롤 경계에서 초점선이 잘리지 않도록 결과 영역에 필요한 내부 여유를 확보한다.
- 보기 권한으로 반환된 결과는 열 수 있는 결과이며 편집 권한이 없다는 이유로 비활성화하지 않는다. 서버가 제외한 결과를 disabled 행으로 되살리지 않는다.
- 검색 입력과 필터의 readonly/disabled는 현재 기능에 해당하지 않는다. 비해당 근거는 사용자가 검색을 계속 수정할 수 있다는 계약이다. 조작 없는 제목/발췌에 입력 invalid 상태를 부여하지 않는다.
- 권한 필터·요청 실패·빈 응답을 선택/비활성 스타일로 대체하지 않는다.

## 7. 실제 query 상태와 재시도

#51과 같은 원칙으로 실제 query 상태를 전달한다. `documents.length===0`만 보고 로딩/실패/빈 결과를 결정하지 않는다. App이 기존 `useSearch`의 상태를 읽고 AppShell을 거쳐 SearchPanel에 전달한다. SearchPanel은 직접 fetch하거나 서버 상태를 자체 복제하지 않는다.

현재 입력·축에 대한 표시 우선순위는 다음과 같다.

| 조건 | 표시·행동 |
| --- | --- |
| 공백만 있는 질의 | 안내용 EmptyState: “검색어를 입력하세요.”; 로딩·무결과·오류로 표현하지 않음 |
| 비어 있지 않은 질의 + 선택 축 0개 | 안내용 EmptyState: “검색 대상을 선택하세요.” / “필터에서 검색할 대상을 선택하세요.”; 현재 query의 비활성 상태이며 fetch/retry 없음 |
| 실제 enabled 요청이 진행 중 | LoadingState “검색 중…”; 결과 영역 `aria-busy=true`; 입력·필터는 활성 유지 |
| 현재 요청 실패 | ErrorState “검색 결과를 불러오지 못했습니다.” / “잠시 후 다시 시도하세요.”; 실제 `searchResults.refetch()`에 연결된 “다시 시도” |
| 현재 요청 성공 + 0건 | EmptyState “검색 결과가 없습니다.” / “검색어 또는 검색 대상을 바꿔 보세요.” |
| 현재 요청 성공 + 결과 | 받은 결과 그룹 목록 |

disabled query가 가진 pending 상태를 loading으로 해석하지 않는다. 재조회가 실제 진행 중이면 같은 LoadingState를 사용하고 기존 결과 항목을 현재의 확정 결과로 동시에 표시하지 않는다. 실패가 나면 이전 성공 결과를 성공처럼 남기지 않는다. 결과 캐시 정책은 변경하지 않고 이 규칙은 화면 표시를 정한다.

현재 query+axes에 속한 응답만 화면 상태를 결정한다. 이전 질의의 늦은 성공/오류가 새 입력의 상태를 덮어쓰지 않는다. 빈 입력이나 축 0개로 바뀌면 이전 오류·재시도 버튼도 현재 상태에서 제거한다. retry는 현재 enabled 질의와 현재 축의 기존 query만 재조회하며 입력·필터·저장된 축을 초기화하지 않는다. 자동 retry 횟수·polling·query key·네트워크 정책을 새로 정하지 않는다.

네트워크/5xx 오류와 인증 실패를 질의 문법 invalid로 오인하지 않는다. 401 등 기존 인증 처리 계약을 유지하고 새 로그인 정책이나 별도 세션 엔진을 만들지 않는다. 서버 응답 원문·스택·내부 경로를 오류 문구에 출력하지 않는다.

## 8. 최소 2자·잘못된 질의의 표시 경계

현재 HTTP 검색 응답은 `{documents}`이며 검색 질의에 대한 `empty`/`too-short` 오류 필드나 전용 invalid 응답 계약을 노출하지 않는다. 따라서 **#52는 새로운 클라이언트 문법 파서나 길이 차단을 넣지 않는다.** 문자열 전체 길이만으로 최소 길이를 판정하거나 OR/AND 묶음 판정을 단순화하지 않는다. 기존 query 전송 조건도 유지한다.

최소 길이·문법은 §3·§4의 지속 안내로 전달한다. 현재 서버에서 정상 응답한 빈 결과를 UI가 임의로 “잘못된 질의”로 바꾸거나 `aria-invalid=true`로 표시하지 않는다. 전용 질의 거절 계약이 없다는 것이 현재 invalid 상태의 비해당 근거다. 일반 HTTP 오류는 §7 오류 상태로 표시한다. 향후 실제 전용 오류 계약이 도입되면 그 별도 작업에서 가시 오류·`aria-invalid` 연결을 결정한다.

회귀가 지켜야 할 FR-SHELL-014 의미는 다음과 같다.

- 공백은 AND, `|`는 OR, AND가 더 강하게 묶인다.
- 단일 항은 2자 이상이어야 한다. AND 묶음에는 2자 이상인 항이 하나라도 필요하다.
- `|`로 나뉜 각 묶음이 독립으로 위 조건을 만족해야 한다. 모든 항을 무조건 2자 이상으로 강제하지 않는다.
- 괄호는 연산자가 아니라 검색 문자열이다.

**구현 입력에서 관측한 별도 경계:** 현재 `/api/search` 라우트는 `search-service.ts`의 검색으로 연결되어 있고, 읽은 서비스의 이름/본문 일치는 문자열 `includes` 경로다. `domain/search/query.ts`에는 위 문법 파서가 있으나 읽은 HTTP 경로에서는 그 연결이 확인되지 않았다. 이는 정적 의사결정 관측이며 실행 검증 결론이 아니다. 독립 회귀에서 실제 서버로 확인해야 한다. 실패하면 mock 결과로 통과시키거나 #52에서 서버를 몰래 고치지 말고, FR-SHELL-014의 별도 구현/수정 범위로 root에 보고한다. 디자인 결정 완료가 이 기능 회귀의 미확인 상태를 없애지 않는다.

## 9. 키보드·IME·스크롤

cmdk Input/List/Item의 역할·활성 항목 이동·결과 열기·`shouldFilter=false`를 유지한다. Arrow 키로 결과를 이동하고 Enter로 현재 결과를 여는 기존 경로를 보존하며, 결과 선택이 외부 폼 제출로 이어지지 않는다. 긴 목록의 활성 결과는 결과 영역 안에서 보이는 위치로 스크롤된다. 새 전역 단축키·선택 모드·자동 문서 열기를 만들지 않는다.

IME 조합 중 Enter는 cmdk 결과 선택/문서 열기/외부 폼 제출로 처리하지 않는다. 조합 완료 뒤 사용자가 별도로 Enter를 눌러야 결과 선택이 가능하다. 입력값 동기화는 기존 controlled query 경로를 유지한다. #52는 composition 중 검색 요청 자체를 차단하거나 새 debounce를 정의하지 않는다. **조합 중 결과 열기 요청 0건**과 **조합 중 검색 요청 정책 유지**를 구분해 검증한다. 필터 체크박스의 Space/Enter는 체크 동작에만 쓰인다.

검색 패널과 중간 flex 래퍼의 `min-height:0`, `min-width:0`를 유지한다. 고정 검색 영역을 제외한 결과 영역 하나가 남은 높이를 받으며 `overflow-y:auto`를 소유한다. cmdk List와 외부 결과 영역에 중복 세로 스크롤을 만들지 않는다. 별도 팝오버가 열렸을 때 그 팝오버의 내부 스크롤은 허용한다.

검색어는 한 줄 입력의 기존 가로 이동을 사용하고, 결과 텍스트는 내부 줄바꿈을 사용한다. 긴 문자열 때문에 검색 패널·셸 전체에 새로운 가로 넘침이 생기면 안 된다. #50이 정의한 좁은 셸의 가로 스크롤은 그대로 유지한다.

## 12. 실제 HTTP 문법 연결 결함 처리

**A로 결정한다. #52 안에서 `FR-SHELL-014`의 실제 HTTP 연결을 최소 수정한다.** 명세가 이미 존재하고 `Stability=evolving`이며, 실제 query 문법 회귀가 #52 완료 기준에 포함된다. 별도 이슈를 만드는 것을 수정의 선행 조건으로 두지 않는다.

발견 증거는 같은 디렉터리의 `http-search-query-contract-gap.txt`다. 실제 제품 Express `/api/search`에 `q='회의록 | 존재없음'`을 보낸 시험이 HTTP 200 응답까지 도달했지만, 접근 가능한 `회의록` 문서가 나와야 하는 assertion에서 빈 목록으로 실패했다. 이 기록은 Sol이 수행한 진단의 raw 증거이며 Astra가 검증을 재실행한 결과가 아니다.

이 절은 앞선 §1·§8·§11의 서버 변경 금지 및 별도 수정 범위 분리 결정을 **아래 연결 수정에 한해서만** 대체한다. 나머지 UX·검색 의미·G36 경계와 금지사항은 유지한다. #52는 실제 HTTP 회귀와 독립 검증이 통과할 때까지 열린 상태로 유지한다.

### 12.1 허용 범위와 연결 계약

- 허용 범위는 기존 `domain/search/query.ts` 재사용, `search-service.ts`의 질의 평가·기존 발췌 연결, 필요한 최소 라우트 연결과 관련 테스트다.
- 파서는 요청당 한 번 사용한다. 파싱 결과의 **OR 묶음 중 하나가 만족되고, 그 묶음의 모든 AND 항이 해당 문서의 선택된 검색 축 안에서 일치**해야 결과에 포함한다. 서로 다른 선택 축에서 항이 일치해도 같은 문서의 AND를 충족한다. 선택되지 않은 축은 기여할 수 없다.
- 대소문자·부분 문자열 일치의 기존 방식을 유지한다. 괄호 해석·길이 판정·빈 파이프 처분은 기존 파서가 소유한다. 서비스·HTTP·UI에 별도 파서를 만들지 않는다.
- 파서가 거부하는 빈/최소 길이 미달 질의와 축 0개는 기존 응답 형태인 **HTTP 200 `{documents: []}`**로 끝낸다. 새 상태 코드·오류 필드·클라이언트 검증 정책은 추가하지 않는다. 거부 질의는 문서 본문·PDF 추출까지 진행하지 않는다.
- 권한·서비스 가능 노드 필터를 통과한 문서만 검색한다. 숨은 문서·삭제 노드·예약 경로의 처리와 워크스페이스 경계를 유지한다.
- 문서 제목은 한 번만 반환한다. 발췌는 만족한 OR 묶음에 기여한 실제 일치 지점에서 기존 형식으로 만든다. 여러 OR 가지가 같은 일치 지점을 공유해도 조립 때문에 복제하지 않는다. PDF 페이지 정보도 유지한다.
- 요청 안에서 같은 문서 본문 읽기·PDF 추출을 항이나 OR 가지마다 반복하지 않는다. 기존 축별 수집을 공유하고, 이름만 선택한 검색에서 본문/PDF를 읽지 않는다.

### 12.2 엄격한 TDD 순서

1. 제거된 진단을 영구 HTTP 회귀 테스트로 복구하거나 적절한 검색 HTTP 테스트에 옮긴다.
2. 실제 제품 Express `/api/search`를 통과하는 테스트에서 **수정 전 red**를 다시 확인한다. 기존 로그는 발견 증거이며 영구 회귀 테스트를 대신하지 않는다.
3. 필요한 서비스 테스트도 구현 전에 작성하고 red를 확인한다.
4. 최소 구현으로 green을 만든 뒤 관련 HTTP·검색·권한·웹 회귀를 수행하고, 별도 Sol 검증자가 판정한다. 테스트를 완화하거나 파서 단위 테스트로 대체하지 않는다.

| 재현 | `회의록 \| 존재없음`이 접근 가능한 `회의록` 문서를 반환 |
| AND/OR | 두 항 모두 있는 문서·하나만 있는 문서를 구분; OR 가지 순서에 결과 의미가 달라지지 않음 |
| 최소 길이 | 단일 1자 거부, 2자 수용, `회의 가` 수용, `가 나` 거부, `회의 \| 가` 거부 |
| 혼용 | `회의 규정 \| 일정`의 AND 우선순위, 각 OR 묶음의 독립 최소 길이 판정 |
| 문자 취급 | 괄호는 문자, 앞뒤·연속 파이프와 공백 처리는 기존 파서와 일치 |
| 네 축 | 이름·본문·태그·첨부 이름 각각의 일치; 축 해제 후 배제; 같은 문서의 선택 축 간 AND |
| 결과 형태 | 문서당 제목 하나, 실제 발췌, 중복 OR 가지의 문서/일치 지점 중복 방지, PDF 페이지 유지 |
| 권한 | 비인증·보기 권한·숨은 문서·삭제/예약 경로의 기존 차단과 정보 비노출 유지 |
| 비용 | 거부 질의의 본문/PDF 읽기 0회, 이름 전용 검색의 본문/PDF 읽기 0회, 복합 질의의 문서당 반복 읽기·추출 없음 |
| 제품 연결 | 실제 HTTP의 문법 결과와 #52 검색 UI를 연결해 결과 선택·필터·retry·늦은 응답 회귀 확인 |

### 12.4 금지사항과 증거

**금지:** G36의 결과 상한·발췌 길이·강조 방식 확정, 새 순위·색인·캐시·병렬 스캔·패키지, #75 색인 작업 선행 구현, 권한 필터 이동/완화, UI 측 OR 결과 합성, mock으로 실제 HTTP 실패 은폐.

요구사항의 기존 단위 테스트 증거는 유지하되, 수정 후 실제 HTTP 증거를 별도로 남겨야 한다. 이 절을 기록하면서 코드·SRS·이슈를 변경하거나 검증을 실행하지 않았다.
