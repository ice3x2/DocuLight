가상화기의 `rowHeight`와 실제 행 높이를 함께 40px로 맞춘다. 트리 높이는 #50이 확보한 실제 남은 공간을 사용하며, 고정 640px 때문에 마지막 행이 설정 바 아래로 내려가면 안 된다. 가상화·기존 treeitem 역할·키보드 이동을 유지한다.

## 3. 상태 표현

| 상태 | 표현과 동작 |
| --- | --- |
| default | 패널 배경, `text-primary`; 보조 문구는 사이드바 전용 보조색 |
| hover | `surface-control`; 선택 행은 선택 배경 유지 |
| focus | 공통 2px 초점선과 2px 분리 공간; 선택과 동시에 표시 |
| selected | 선택 배경·세로 표식·기존 선택 의미를 함께 유지 |
| disabled | 해당 조작만 disabled 토큰과 실제 비활성 의미 적용 |
| readonly | 읽을 수 있는 이름·열기·선택·복사는 유지; 행 전체를 비활성처럼 흐리게 하지 않음 |
| invalid | 이름 입력에 오류 경계·`aria-invalid`·연결된 오류 문구 |
| loading | 실제 요청 상태에만 공통 LoadingState, 목록 영역 `aria-busy` |
| empty | 성공한 빈 결과에만 공통 EmptyState |
| error | 실제 실패에 공통 지속 오류 안내; 가능한 기존 재조회만 연결 |

보기 권한과 pass-through를 같은 상태로 취급하지 않는다. pass-through의 기존 펼치기·통과 동작과 메뉴별 제한을 그대로 따른다. 상태 표시를 위해 감춰진 노드나 권한 정보를 추가로 가져오지 않는다.

초기 빈 즐겨찾기 문구는 **“즐겨찾기한 항목이 없습니다.”**, 보조 문구는 **“트리의 메뉴에서 문서나 디렉토리를 추가할 수 있습니다.”**로 한다. 접근 가능한 문서가 없는 경우에는 기존 `EmptyState`의 두 문구를 유지한다. 빈 폴더마다 가짜 자식 행을 만들지 않는다.

## 4. 드래그 표식

- 현재 트리의 내부 노드 드래그 이동은 활성화하지 않는다. #51의 표식은 기존 **외부 파일 업로드 드롭**에 한정한다.
- 대상 판정은 기존 업로드 계약을 사용한다. 업로드 대상인 디렉토리에는 선택 배경과 2px 점선 테두리, **“파일 업로드”** 문구를 표시한다. 행 높이·들여쓰기는 변하지 않는다.
- 파일 노드·업로드 권한 없는 위치에는 허용 표식을 표시하지 않는다. 필요하면 **“이 위치에 업로드할 수 없습니다.”**로 알리며, 숨은 정보나 존재 여부를 설명하지 않는다.
- dragleave/drop/취소 후 표식을 제거한다. 자식 아이콘 사이 이동 때문에 깜빡이지 않게 한다.
- 행 사이 삽입선, 이동/복사 커서, 자동 폴더 펼침, 새 확인 절차는 추가하지 않는다. 드래그 중 알 수 없는 파일 크기·형식을 추측해 성공을 표시하지 않는다.

## 5. 컨텍스트 메뉴

기존 Radix ContextMenu를 유지하고 #48의 메뉴 표면 규칙을 적용한다. 기본 폭 240px, 최대 폭 `calc(100vw - 48px)`, 항목 최소 높이 36px, 좌우 패딩 12px, 표면 패딩 4px, 모서리 6px이다. 실제 남은 높이를 넘으면 메뉴 내부에서 스크롤한다.

항목 순서·문구·권한·즐겨찾기 라벨 전환은 기존 계약에서 읽는다. 삭제만 기존 destructive 표현을 사용하며, 비활성 삭제는 disabled 표현이 우선한다. 워크스페이스 행에는 노드 메뉴를 새로 만들지 않는다. 파일 전용 항목의 노출 규칙도 유지한다.

키보드 탐색·Escape·우클릭 경로를 보존한다. 생성·개명을 선택한 뒤 메뉴가 닫히면서 인라인 입력의 초점을 빼앗으면 안 된다. 다른 경로에서의 초점 복원도 기존 계약을 유지한다.

## 6. 즐겨찾기

- 행은 **최소 52px**, 세로 패딩 6px로 한다. 이름 14/22px, 아래 워크스페이스 이름 12/18px의 두 줄 구조를 사용하고 긴 내용은 자연스럽게 늘린다.
- 종류 아이콘과 이름 영역, 우측 해제 버튼을 분리한다. 해제 버튼은 항상 보이는 36×36px ghost 조작으로 두며 접근 가능한 이름 **“{항목명} 즐겨찾기 해제”**를 유지한다.
- 해제 조작이 문서 열기를 함께 실행하면 안 된다. 실제 해제 결과에 따라 행이 사라지는 기존 흐름을 유지한다. 새 확인창·되돌리기·낙관적 삭제 정책은 추가하지 않는다.
- 문서 이름은 기존 열기 버튼이다. 디렉토리 이름에 새 열기 동작을 부여하지 않는다.
- 해제 후 초점은 남은 다음 행의 해제 버튼, 없으면 이전 행, 목록이 비면 즐겨찾기 탭으로 이동한다. DOM에서 제거된 버튼에 초점을 남기지 않는다.

## 7. 인라인 생성·개명

입력은 현재 노드 또는 생성될 위치의 기존 인라인 행에 유지한다. 높이 36px, 14/22px, 공통 입력 토큰·반경 4px을 사용한다. 기존 기본값 전체 선택과 초기 초점을 보존한다.

가상화 행 아래로 도움말·오류를 넘쳐 그리지 않는다. 이름 입력 중에는 **트리 위 고정 보조 영역**에 가시 라벨과 **“Enter로 확정 · Esc로 취소”**를 표시하고 입력과 연결한다. 오류도 이 영역에서 대상 이름과 함께 표시한다. 이 영역은 트리에 할당하는 높이에서 제외한다.

- 조합 중 Enter는 이름 확정·서버 요청·트리 활성화로 이어지지 않는다. 조합을 마친 뒤 별도의 Enter로 한 번만 확정한다.
- Esc는 기존 취소 경로이며 서버 요청이 없다. blur에 새 자동 저장·자동 취소 동작을 붙이지 않는다.
- 빈 값은 기존 기준으로 막는다. 금지 문자·길이·충돌 규칙을 클라이언트에 추가하지 않는다.
- 서버가 확정한 이름·접미사 안내·트리 재조회 흐름을 유지한다. 로컬에서 성공한 노드를 지어 넣지 않는다.
- 실제 서버 오류가 전달되는 경우에만 그 오류를 표시한다. 오류 데이터가 없는 경로에 가짜 오류나 성공을 만들지 않는다.

**연결 경계:** 현재 결과물이 조회/서버 오류 상태를 받지 못한다면 이를 표시하려면 기존 상태의 얇은 전달이 필요하다. 그 연결은 root에 변경 경로를 명시해 범위를 배정받는다. 별도 요청 엔진이나 새로운 재시도 정책을 만들지 않으며, 미연결 상태를 완료로 보고하지 않는다.

## 8. 넘침과 200% 확대

#50의 열 폭·설정 하단 행을 그대로 따른다. 긴 이름·깊은 들여쓰기가 중앙 문서나 패널 폭을 밀지 않는다. 트리의 깊이로 필요한 가로 넘침은 **트리 내부**, 즐겨찾기의 긴 이름·워크스페이스 이름은 **행 내부 줄바꿈**으로 처리한다.

트리 이름은 한 줄 축약을 허용하되 전체 이름을 hover와 키보드 focus 양쪽에서 읽을 수 있는 설명 표면으로 제공한다. `title` 속성만 사용하지 않는다. 설명은 기존 이름만 사용하고 뷰포트 안에서 줄바꿈하며 초점을 빼앗지 않는다. 이름 입력 중에는 설명 표면이 입력을 덮지 않는다.

마지막 행·인라인 입력·해제 버튼·메뉴 마지막 항목·설정 버튼이 모두 도달 가능해야 한다. 확대를 이유로 탭·행 조작·들여쓰기 의미를 숨기지 않는다.

| IME | composition 이벤트 회귀와 실제 한국어 IME 입력을 구분해 기록. 조합 Enter 요청 0건, 조합 종료 후 별도 Enter 요청 1건. 합성 이벤트만으로 실제 IME 통과를 주장하지 않음 |
| 드롭 | 허용 디렉토리와 금지 대상, dragleave/drop 정리, 내부 이동 비활성 유지. 표식과 기존 업로드 판정 일치 |
| 즐겨찾기 | 파일·디렉토리 추가, 파일 열기, 각 행 해제, 해제 클릭의 열기 누출 없음, 제거 후 초점 위치 확인 |
| 실패·빈 결과 | 지연 응답·성공 빈 목록·조회 실패·서버 이름 거부·충돌 접미사. 서로 다른 상태와 실제 요청/응답에 맞는 결과 확인 |

실제 200% 증거에는 확대 전후 CSS viewport와 스크린샷을 남긴다. `deviceScaleFactor` 또는 절반 viewport만으로 실제 확대를 대신하지 않는다. 실제 한국어 IME는 별도의 직접 입력 증거가 필요하며 Playwright의 합성 composition 시험과 구분한다.

제품 변경은 실패하는 행동/계산 스타일·기하 테스트를 먼저 확인한 뒤 구현한다. 구현자와 별개의 검증자가 요청·응답, 계산 스타일, 기하, 스크린샷과 회귀 결과를 확인한다. CSS 클래스 존재만으로 통과시키지 않는다. 이 문서에는 테스트 실행 또는 통과 주장이 없다.

## 10. 범위 밖과 비해당 판정
