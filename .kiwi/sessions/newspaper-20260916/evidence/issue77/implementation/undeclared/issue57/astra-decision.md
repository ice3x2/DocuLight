## Server/local conflict surface

Keep conflict resolution inline within the current document tab, above its existing editor, not a new blocking modal. Display a compact persistent warning strip using warning surface/status-warning, 1px subtle boundary, 12px inset and natural wrapping. Visible text: `저장 중 원본이 바뀌어 병합이 필요합니다. 편집 내용은 유지됩니다.` Announce the transition with an alert once; do not repeatedly announce full body or steal editing focus when the response arrives. Preserve the shell's existing conflict/automatic-save-paused indication.

Use the single shared `@codemirror/merge` component in explicit conflict mode. Left header: `서버 내용`, read-only. Right header: `내 편집 내용`, editable. The shared #56 version mode remains two read-only panes with a restore action; do not infer mode from translated labels or apply its read-only setting to conflict. Source data remains exactly the server conflict body and local editing body supplied by the existing DocumentSurface path, not a normalized/rendered Markdown string.

Inherit #56's two side-by-side minimum-240px panes, local horizontal overflow below their combined width, bounded vertical source scroll, fixed-within-component pane headers, 14/22px mono and theme tokens. The surrounding document-content scroll reaches the warning and action at 200%; no sticky footer overlays text or main-editor controls. No new conflict-specific palette, width cap, toolbar, pane-swap or per-chunk accept/reject action.

Use #55's actual `+ 추가` / `− 삭제` chunk labels and success/danger roles. Here the baseline is the server pane; right-hand additions/removals describe local draft differences from that baseline, not the previous saved version. Keep marker signs outside copied/saved source. Complete raw-source alternatives follow #56's visually-hidden, accessibility-present technique; the right-hand alternative follows the actual live merge draft and is not an aria-live region. Real populated CodeMirror panes, not hidden source copies, provide visual comparison.

One primary action below the panes: keep `이 내용으로 저장`, with nearby instruction `오른쪽 내용을 확인한 뒤 저장하세요.` Invocation reads the current right-hand editor document and calls the existing resolve callback with those exact bytes. It must not submit the original prop, the whole left pane, a visually hidden stale copy or concatenated diff markers. No second confirmation is added to merge submission; it is the existing resolution/save operation, not a new overwrite policy.

Color/theme/layout rerenders cannot destroy the active merge editor, replace an edited draft with initial props, reset selection/undo/scroll or trigger saves. Keep the existing local body and original editor available through conflict. Do not introduce a second controlled React body state or silently synchronize divergent editors with a new winner rule. If concurrent editing, repeat conflicts or in-flight saves expose a real data handoff defect requiring external wiring, report the exact failing sequence and separate scope before repairing it. A styling issue must neither introduce nor hide data loss.

For #57, the authoritative server conflict response supplies `current:string`; an empty string is valid server content and must remain comparable/resolvable. Missing conflict-body presentation is N/A under this contract, so do not introduce a missing-body branch, disable resolution for empty text or add a refetch control. The client error type permits an absent `current`, but out-of-scope useAutosave collapses that value with `error.current ?? ''`; DocumentSurface cannot recover the distinction. If handling nonconforming/optional client responses becomes necessary, trace it as a separate client/hook plumbing concern before implementation, not as an inferred #57 UI state.

## Rejected-save body rescue

Use a persistent inline error strip with danger surface/status-danger, 12px inset, 4px radius, no shadow and a clear text heading. Safe copy: `저장하지 못했습니다. 편집 내용은 그대로 남아 있습니다. 본문을 내려받아 보관할 수 있습니다.` This is deliberately generic: the existing rejected status can represent permission loss, missing target or transport failure. Do not expose raw response text, node/server path, internal rule/stack, or distinguish a forbidden target from a missing one through a guessed reason.

Keep the current local-download action and data path. Visible label `내려받기`, accessible name `편집 중인 본문 내려받기`; use shared secondary styling, minimum 36px target. It downloads the latest body from the existing local body authority with the current file name and Markdown MIME/UTF-8 behavior, including edits after rejection. It does not fetch server body, need renewed read permission, save to server, clear rejection or navigate away. Keep exact Korean/emoji/newlines/whitespace and do not prepend error text or timestamps to the file.

Do not add a separate clipboard feature or save-retry action in this slice. Selecting/copying existing body remains possible. Initiating a browser download is not proof that the user completed a filesystem save, so no “saved safely” toast or automatic discard follows. The rejected editor stays mounted and editable under the existing model; server permission remains the authority for persistence. Theme, banner insertion and download must not change selection or replace the body. Any download failure behavior added must represent an observable client error rather than a fabricated server diagnosis.

## Existing replacement confirmation

The entry condition is **only** the presence of AppShell's existing `confirmReplace` prop. FR-SHELL-012 specifically requires confirmation for conflict and rejected active tabs; normal active-tab replacement and Ctrl+click retain their existing behavior. This decision does not add a generic dirty-document warning policy.

Replace the bare `role=alertdialog` div with the existing shared Radix AlertDialog from #48. The interaction is the existing single-document discard confirmation: L2-shaped explicit accept/cancel, consistent with FR-CONFIRM-002's irreversible local-loss criterion. No L3 typing token, impact count, fetch, permission recount or extra confirmation is justified. Reusing the AlertDialog primitives is sufficient; do not use ConfirmGate in a way that adds nonexistent recount/async ownership.

- Title: `편집 중인 문서`.
- Description preserves the current concrete warning: `지금 문서에 저장되지 않은 편집이 남아 있습니다. {name} 을(를) 열면 그 편집이 사라집니다.` Render supplied name as text, fully wrapping; do not derive hidden source-document metadata unavailable in the prop.
- Cancel `머무르기` uses secondary styling and receives initial focus. Accept `그래도 열기` uses destructive styling and calls the existing accept callback once only after deliberate activation.
- Cancel button and Escape invoke cancel once and leave the original active document/body/merge draft/cursor unchanged. Outside pointer interaction does not dismiss or accept. Focus stays trapped while open; background tree clicks cannot replace the pending target. No default Enter handler that accepts from the dialog itself or cancel button.
- A composition Enter must not activate acceptance. Do not install global hotkeys overriding CodeMirror/IME. Keyboard Enter/Space on the focused accept button can accept after composition ends; Tab order is description/controls as appropriate, with cancel before accept.
- Use #48 dialog geometry: maximum 560px, width capped by 24px outer margins, 24px inner padding, 6px radius, control surface and existing overlay. At 200% long descriptions scroll internally while title and cancel/accept remain reachable; buttons wrap if needed, with no text truncation or overlap.
- On cancel, restore focus to the captured invoking element if it still exists, otherwise a stable existing active-document heading/region; on accept, use the existing new active-document focus target when available. Do not force focus to a removed tree row, invent App/DocumentArea focus wiring or claim a focus return without browser evidence. An unavailable appropriate parent focus target is an explicit integration gap for separate scope.

Keep callbacks owned by App. AppShell adds presentation and local one-shot activation protection only; it does not open tabs, choose a replacement document or clear document state itself. If the prop/target changes while the dialog is open, display current prop values and execute only its current callbacks, never a saved stale closure. Do not claim a success announcement inside a dialog that its callback unmounts; there is no new parent toast/live-region contract.

## State rules and no-loss constraints

| State | Required scoped presentation |
| --- | --- |
| Conflict | Warning plus available server/local merge, preserving local body; no automatic accept/save |
| Rejected | Persistent generic error plus local download, preserving latest body |
| Empty server conflict body | Valid string content: render the empty left pane and retain ordinary resolution; missing-body state is N/A for #57's authoritative server contract |
| Merge invocation | Call existing resolve with latest draft; do not treat void return or idle state as completion |
| Actual later conflict/rejection | Reflect supplied status, preserve draft/body and existing recovery; no silent retry loop |
| Replacement open | Shared modal confirmation, initial cancel focus; only explicit accept discards via parent |
| Replacement canceled | Original tab, local body, merge draft and selection remain; no save or navigation side effect |
| Theme change | Existing surfaces update colors without body/instance/history replacement |

Native raw Markdown has no invalid-field validation; malformed Markdown is not a save rejection. Loading/busy/success indicators are applicable only when an existing authoritative signal supplies that phase. `useAutosave` currently lacks reliable merge-submission completion, so its absence is a documented wiring gap rather than permission to fake the state. The existing resolve callback and server result are exercised in regression without changing the hook.

No affirmative message or callback return may be used as proof of persisted merged text. Do not mark resolved on click, download, theme switch or cancellation. Existing normal save, conflict hash, pause/resume, rejection, local-body rescue and tab ownership contracts remain intact. If actual product evidence shows an unmet persistence/recovery outcome, do not close that requirement based only on component rendering; separately trace the required external correction.
