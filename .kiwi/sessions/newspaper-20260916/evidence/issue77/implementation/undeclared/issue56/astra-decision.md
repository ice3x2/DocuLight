## Layout and version rows

Keep version history as an inline region within the active document tab, not a new modal or browser route. It remains before the normal document surface in the current integration; do not destroy that surface merely to paint history. Region uses document surface/primary text, 1px subtle boundary, no shadow and 16px inner padding. Title `버전 기록` uses 18/26px sans 600. Lists and controls use the existing shared UI tokens, not the 720px reading-column cap.

Use the existing list-then-comparison structure at every supported width. A side-by-side third navigation column would consume the editor width unnecessarily. The version list has a maximum height `min(240px, 30dvh)` and its own vertical scroll, minimum shrink allowance zero; title/state messages stay outside list scroll. Comparison is below with 16px gap. The existing document-content scroller retains access to both history and the normal editor if their combined height exceeds the available tab height; avoid a fixed footer that overlays either. No fixed-height row clips text.

Each version row has minimum 56px height, 8px vertical/12px horizontal padding and a subtle bottom rule. Main metadata: `{seq}판` in 14/22px 600; `작성자 {author}` and the actual `createdAt` in 12/18px secondary text. Keep the complete returned author identifier, including long Korean/Latin strings, selectable and wrapping; do not resolve it through a new principal API. Render timestamp in a `<time dateTime>` with the original server timestamp visibly available; preserve its timezone/precision instead of guessing local timezone or relative age. Missing legacy metadata is `작성자 정보 없음` / `시각 정보 없음`, never a fabricated current user/time. Preserve API row order and stable sequence keys, not array-position identity.

Row metadata and actions may wrap to a second line. Existing buttons are labeled `{seq}판 비교` and `{seq}판 복원`, minimum 36px, with an 8px gap. Compare is secondary, row restore is ghost/secondary so dozens of rows do not become primary actions. Keep full accessible names. No whole-row click target containing nested buttons.

Selected comparison row uses selected surface, 2px action-primary side rule and visible `비교 중` text. Its compare button has a programmatically exposed selected/pressed state; do not put `aria-selected` on a plain listitem without a supporting role. Hover is control surface; focus is 2px focus ring plus 2px separation, kept inside reserved scroll padding. Selection becomes current only for the successfully loaded sequence. A pending new choice is labeled loading and must not display the old snapshot under the new sequence label.

## Honest states and asynchronous identity

| Operation/state | Frozen behavior |
| --- | --- |
| Initial list request | Shared LoadingState, `버전 기록을 불러오는 중입니다.`, named region `aria-busy=true` |
| Successful empty list | Shared EmptyState, `보관된 버전이 없습니다.`; no comparison/restore action |
| List error | Shared ErrorState, `버전 기록을 불러오지 못했습니다.` and actual `다시 시도`; never endless loading/empty success |
| No comparison selected | Compact neutral instruction `비교할 버전을 선택하세요.`; no default auto-load or guessed selection |
| Version-body loading | `선택한 버전을 불러오는 중입니다.` in comparison area, `aria-busy`; list remains usable |
| Compare error | `선택한 버전을 불러오지 못했습니다.` with retry for that exact node/sequence; no empty document substituted |
| Restore pending | Target action reads `복원 중…`; prevent duplicate mutation for this document from either row or footer; stable target identity |
| Restore failure | Inline alert `버전을 복원하지 못했습니다.` plus a real retry route to the same operation; preserve history/current body and do not invoke success callback or close |
| Restore accepted | Only after successful response invoke `onRestored` once; preserve existing close-on-success as the scoped completion feedback. Do not set a local success announcement immediately before the callback unmounts this component. |

List/compare requests capture node ID and sequence and ignore stale completions after a different selection, node or unmount. Reset old document's rows/selection when identity changes; never show document A data inside B's history. Retry means the actual operation, not remounting an arbitrary subtree. Empty string is a valid loaded version; absent data is distinct.

A restore response and a later document read are distinct outcomes. Within #56, report mutation success only after the existing restore request succeeds, call the existing completion callback once, and do not add cache invalidation, body/hash refresh, a new refresh-error state, an automatic restore retry or stale-autosave suppression. Test the existing product caller's resulting behavior and persisted same-node server body separately. If the visible document remains stale, a subsequent read fails, or an in-flight old save overwrites the restored body, record it as an unmet integration outcome requiring separate traced App/DocumentArea/useAutosave scope; do not mask it with a success assertion about the visible body. Do not route restoration through editing the comparison buffer or change snapshot/retention semantics to simplify state handling.

## Restore action, confirmation and permissions

Restore always targets the stored `{nodeId, seq}`. The row button and selected comparison footer use the same handler. Footer label is `이 버전으로 복원`, with persistent nearby text `현재 본문을 {seq}판으로 바꿉니다.` It restores that snapshot, not the right-hand comparison text. Footer primary action is unique within the comparison area; do not retain the misleading generic `이 내용으로 저장` label for version comparison.

Preserve the existing **immediate restore** flow. No new L2 dialog, typing confirmation or additional “are you sure” step is authorized. FR-CONFIRM-002/003 derive a reversible immediate single-document operation as L1; this is not the binary-upload L2 rule. Server restore currently snapshots previous saved content. The current void restore response supplies no exact undo snapshot identity, and the current UI does not supply a safe undo action. **That pre-existing L1 undo-completeness gap is explicitly outside #56**, per orchestration scope confirmation. Do not fabricate an undo button, guess the previous sequence or claim full L1 compliance. Any repair requiring an exact undo target belongs to a separately traced follow-up. Preserve any existing applicable confirmation behavior elsewhere.

Allow list/compare only through the existing authorized version reads. Restore requires existing effective edit/admin permission and remains server-checked. Where authoritative permission is already available through the scoped component's existing contract, an unavailable visible restore control is disabled with `편집 권한이 필요합니다.` using explicit disabled tokens. Do not invent an edit default or add parent permission propagation under #56; missing UI permission plumbing is a separate integration gap. Do not infer authorization from author, successful listing or a stale opened tab. Preserve the existing server rejection and show an honest failed operation on permission loss. No internal path, hidden author information beyond the returned metadata, or missing-versus-forbidden explanation is added.

Opening/listing/comparing must not start an edit session, create a snapshot, save, mutate selection in the live editor or replace its body. VersionHistory continues to use its existing `currentBody` input without introducing a new live-editor getter, controlled text mirror or parent bridge. Test the provided input byte-for-byte and separately observe whether the real product caller supplies the intended current body. If `bodies[nodeId] ?? ''` supplies stale saved text or substitutes empty text for unavailable body, document that caller gap for a separate SRS/issue; do not claim comparison with the latest unsaved draft or fix the caller inside #56. Restoration retains existing unsaved/conflict protections and local-body recovery paths, with their presentation owned by #57.

## Shared comparison and accessible raw source

Retain `@codemirror/merge` and one MergeView component. Version comparison is two **read-only** panes: left `보관된 {seq}판`, right `현재 본문`. There is no editable draft to discard in this mode. Conflict usage remains left server/read-only and right local/editable with its existing resolve callback; #56 must not make conflict mode read-only or alter its save behavior. Use a small explicit mode/action distinction rather than interpreting labels or pretending every `onResolve` means the same operation.

Pane headers are outside the code scroll, use app surface, primary 13/20px 600 text and a bottom subtle rule. Source content uses #54's 14/22px mono/document surface and the #55 addition/deletion cues. No 720px measure inside diff panes. Two panes remain side-by-side, each minimum 240px; on narrower effective widths the **comparison viewport** scrolls horizontally, keeping both panes available instead of hiding or stacking one. Each pane's long lines scroll locally. Bound code height with `clamp(180px, 45dvh, 480px)` and retain independent content scrolling; ensure headers and restoration action remain reachable through the surrounding document-content scroll at 200%. Provide named keyboard-focusable overflow regions where required; do not trap text-navigation keys.

Pure insertion, pure deletion and changed chunks retain the real visible `+ 추가` / `− 삭제` labels or equivalent accessible gutter markers from #55. Success/danger colors supplement these signs. Labels follow actual chunk updates/virtualized reentry and are excluded from copied/restored/saved source. In version comparison, the baseline is the selected saved version: a deletion is present on the left and absent on the right; an addition is present on the right. No hardcoded pane-wide “all added/all deleted” label.

Keep complete raw-source alternatives for accessibility, including text outside virtualized CodeMirror DOM. Use clearly named `<pre>` alternatives (e.g. `보관된 3판 전체 원문`, `현재 본문 전체 원문`) with a standard visually-hidden technique: positioned/clipped small box, no normal-flow geometry, no `display:none`, `visibility:hidden`, `hidden` attribute or `aria-hidden`. They are noninteractive, not Tab stops. Do not hide the real CodeMirror content from accessibility, especially the editable conflict pane. Alternatives must not be `aria-live`, so changing a version does not announce entire documents. A success/status sentence may announce the selected version instead.

These complete alternatives do not substitute for the real diff: actual `.cm-mergeView` must have two populated, nonzero-size panes and actual difference markers. Preserve source bytes and whitespace. In conflict mode the right-hand alternative must track the live edited draft rather than stale initial props; reuse editor update data without controlled rerender/remount. No ordinary visual duplicate of either full source is printed above/below the diff, and hidden alternatives must not widen the page or intercept pointer events.

## Independent review disposition

Medium 1 accepted (2026-09-17): the initial decision prescribed same-node body/hash refresh, stale-autosave suppression, a refresh-failure state and a live-editor getter whose implementation would require App/DocumentArea/useAutosave changes outside #56's stated files. Those wiring prescriptions are withdrawn. #56 now uses the existing `currentBody`, restore request and completion callback, implements honest scoped operation states, and retains actual product compare/restore regression. Missing refresh/live-body/autosave/permission propagation is an explicit separate SRS/issue integration gap, not implicit #56 authorization and not a passing regression. No implementation was changed by this disposition.

Rereview Medium accepted (2026-09-17): `onRestored={() => setPanel(null)}` unmounts VersionHistory, so a local success status set before that callback would not provide observable persistent feedback. The restore-success row now requires only the existing close-on-success contract. Failure stays visibly in the mounted history and must not invoke `onRestored`. A persistent success toast/live-region announcement would require a separately scoped parent handoff and is not part of #56. Comparison-selection announcements remain local because successful comparison does not unmount history. No implementation was changed.
