## Inline state machine and ordinary list

All inline stages occupy the current #61 right pane, preserving modal title/close geometry and category navigation. Never create a second general Dialog for issuance/reveal. State changes focus their own heading/control without recreating the settings shell.

| State | Contents / transitions |
| --- | --- |
| List | Heading, permission-scope explanation, `새 액세스 토큰`, metadata table, account-state notice. New opens form. |
| Form | Name, scope, expiry, `취소`, `발급`; cancel returns list/focus to New. Failure keeps form/values. |
| Issuing | Actual issuance Promise pending; one request guard, inputs/issue disabled, status `토큰을 발급하는 중입니다.`. Do not claim cancellation of an already-sent request. |
| Reveal | Exact newly issued token in one selectable read-only field, one-time warning, `복사하고 닫기`, `닫기`. No token list in this stage. |
| Copy pending | Await actual clipboard Promise; `복사 중…`, no duplicate copy or premature clearing. |
| Discard confirmation | Same pane and same reveal value remain; explicit last-chance warning, `계속 보기`, `그래도 닫기`. It is not the PAT-revocation L2 dialog. |
| Revoke L2 | Separate #48 AlertDialog from list metadata, exact target ID captured; no secret involved. |

While issuance is actually pending, do not let a local cancel/category/close pretend the server operation was aborted. Keep the inline operation pending until it settles, with an explicit waiting explanation and no abort endpoint; the B1 handoff must cover that interval as well. Auth invalidation still overrides it and discards any later secret. No browser unload persistence or beforeunload policy is introduced.

List heading `액세스 토큰` uses 18/26px sans 600. Preserve the top explanation that MCP/API use these tokens and actual permission is the intersection of scope and current effective permission; preserve the bottom account-active-state invalidation notice. One primary `새 액세스 토큰` action, minimum 36px, remains available in a successful empty list. Do not add filter/search/pagination/counts absent from the current contract.

Metadata table retains exactly name, scope, expiration, last use and action columns. Rows minimum 40px with natural multiline height, 8px vertical/12px horizontal cells, app-surface header, document-surface body and subtle rules. Names wrap fully; date/scope/action columns remain readable. The table may have a local horizontally scrolling viewport when necessary; it cannot widen the modal. Give that overflow region a name and keyboard reach only when required. Last row/action remains reachable in #61's right scrollport.

Use existing labels `읽기 전용`/`읽기+쓰기`, date rendering and `사용 안 함` for null last-use. Expired rows remain listed with explicit `만료됨`; revoked rows show `폐기됨` instead of an active revoke action. Keep supplied order and stable IDs. An expired but not revoked token retains its existing revoke action. Never add a token prefix/hash/secret column, hidden tooltip or owner detail.

Expired metadata is visually quieter using readable secondary text and the status label, **not whole-row opacity 0.55** that also fades the still-active action/focus. Normal text must remain ≥4.5:1 and controls keep normal contrast. This is the approved shared-state interpretation of the older “dim expired rows” design; update the old opacity-specific assertion to verify actual semantic contrast/differentiation, not to weaken it into class presence.

## Issuance form and outcome ownership

Form column is max 560px within existing right padding, with no new card. Labels 13/20px 600, input/select text 14/22px, help/error 12/18px, controls min 36px/4px radius, field gap 20px and action gap 8px. Header `새 액세스 토큰`; name uses a native text input with persistent label. Preserve the existing trimmed nonempty-name requirement, no new length/pattern rule. Show initial form without errors; empty-name submit creates a connected inline name error and does not call issuance.

Keep exactly the existing radio scope group (default read-only) and native expiry select: 30, 90, 180, 365 days, default 90. No non-expiring, custom-date or admin scope. Use token-contract as the options source. Form's cancel and issue are distinct buttons; Enter submits only after composition ends. Native radio keys, select keys, paste and Korean names work. No confirmation gate is added to issuance.

On issuance, capture name/scope/expiry once, guard same-tick and repeated submissions and await the actual Promise. `undefined`, missing callback or thrown failure is not successful issuance: retain form and values, display safe `토큰을 발급하지 못했습니다. 입력을 확인하고 다시 시도하십시오.`, and allow deliberate retry. Missing callback disables issue with an unavailable explanation. Do not close the form on failure as current code does. Do not show raw exception/API payload that could include a token.

Only a valid successful `{token}` result for the current owner/request enters reveal. Never put that token into list rows, query cache, shared app state, URL or durable storage. Transient callback transport is not permission to retain it in the parent. A stale result after owner invalidation/unmount/departure must be ignored and released; do not autoissue again, silently autorevoke or resurrect its UI. The existing App issuance adapter is explicitly in scope: return the successful secret to its current requesting child without making delivery depend on metadata refetch success. Start metadata refresh separately, expose its failure through B4, and never misreport an issued token as a failed issuance or automatically repeat issuance. Product tests must delay/fail refresh after successful creation and still observe exactly one issuance and one reveal.

## One-time plaintext, clipboard and explicit departure

Reveal title `토큰이 발급되었습니다.` is focusable for the transition. Show one native read-only textarea/field labeled `발급된 액세스 토큰`, 14/22px mono, control surface/border-control, 4px radius, full width and no spellcheck/autofill. It is intentionally **readable, selectable plaintext during this one authorized stage**, not disabled and not a password field that prevents manual rescue. Long token strings visually wrap or scroll locally without adding characters; copying uses the exact original string, never selected display text plus line breaks. Do not auto-copy or place the value in aria-live text, descriptions, toast messages, titles or data attributes. There must not be a hidden second plaintext copy.

Persistent warning: `이 값은 지금 한 번만 보입니다. 닫으면 다시 볼 수 없고, 잃으면 새로 발급해야 합니다.` It describes display lifetime, not automatic revocation. Closing/discarding the reveal does **not** revoke the newly created PAT or cancel issuance.

`복사하고 닫기` calls the native clipboard API and clears plaintext/returns to list **only after fulfillment**. Treat unavailable clipboard, synchronous throw and rejected Promise as failure: preserve plaintext, show `복사하지 못했습니다. 위의 값을 직접 선택해 복사한 뒤 닫으십시오.`, keep keyboard manual selection/copy available, and allow retry. A manual copy cannot be reliably detected, so explicit close still follows discard confirmation. No fallback clipboard library, execCommand workaround, secret download or background clipboard overwrite is added.

Guard copy callbacks with owner/request generation. Late clipboard success/failure after explicit invalidation must not reopen a stage, set state in a new owner's panel or execute a stale navigation. While copying, do not drop the value before settlement or start a second copy. Auth invalidation may erase local state immediately; an already-issued clipboard write cannot be recalled, and the UI must not claim otherwise.

Departure behavior is precise:

| Intent while revealing/confirming | Behavior |
| --- | --- |
| Escape or outside settings click | Prevent settings dismissal; keep current reveal/confirmation and value. Do not treat as discard consent. |
| Inline `닫기` / `뒤로` | Enter inline discard confirmation; pending destination is token list. |
| Explicit settings close or another category | B1 intercepts before unmount, remembers only that exact destination/closure callback, and enters the same discard confirmation. |
| `계속 보기` | Cancel pending departure and return to reveal with value intact; restore focus to its close/copy area. |
| `그래도 닫기` | Erase local plaintext and invalidate pending copy callbacks first, then perform the single accepted destination. No duplicate transition. |
| Successful `복사하고 닫기` | Erase local value, return to token list and focus `새 액세스 토큰`; do not invent a remembered category jump. |
| Logout/session invalidation/owner change | Immediate plaintext erasure without a keep-secret prompt; ignore outstanding issuance/copy completions and unregister leave hooks. |

Discard confirmation retains the visible plaintext so the user can still choose to keep/view/copy; it is not an additional issuance or revoke modal. Use a warning block and actual buttons, initially focusing `계속 보기`. On unconfirmed category/close gestures, the parent must keep this component mounted. Do not inspect secret DOM to implement guards. Once a departure is pending, another click must not silently replace its destination; require cancel/continue before another target is selected.

When closing without successful programmatic copy, the token list shows the existing non-secret notice `평문은 다시 볼 수 없습니다. 필요하면 새로 발급해야 합니다.` If the accepted destination closes settings/leaves the token category, that notice must be retained only as non-secret UI state for the next appropriate token-list return through the explicit handoff; never retain the token itself or display a transient local notice that is unmounted before it can be read. Missing non-secret notice lifetime across such departure is part of B1, not permission to extend secret lifetime.

## Revocation and query states

Revoke is self-only and L2 under FR-CONFIRM-006. Use existing ConfirmGate with exact supplied token ID and name, cancel-first focus, title `{name} 를 폐기합니다` and notice `이 토큰을 쓰던 클라이언트는 즉시 인증되지 않습니다. 되돌릴 수 없고 새로 발급해야 합니다.` No plaintext, typed token, unrelated count, additional confirm or bulk action. Cancel/Escape cause no revoke; outside click follows #48 alert rules. Server remains authority, including superusers attempting another user's PAT.

Implement the authorized B3 Promise/outcome handoff before claiming revoke feedback complete. Show actual pending and prevent duplicate confirmation. Failure keeps the row/target and safe error; deliberate retry repeats the existing L2 flow. Confirmed success completes revocation, then requests metadata refresh. During refresh or its failure, do not present a stale actionable row as a fresh revoke opportunity. The query retry is distinct from retrying the mutation; never show optimistic success before the server confirms or change token state solely because a void callback returned.

Successful empty list may show `발급된 액세스 토큰이 없습니다.` only with B4's authoritative ready/empty state. Implement loading, safe list error and actual query retry through the authorized typed handoff. Current `rows=[]` alone cannot distinguish them. Query loading/error presentation must preserve any current one-time reveal and must not turn successful issuance/revoke into failed operations. Do not automatically poll expiry/last-use, enumerate other accounts or add a new endpoint.

## Theme, forced colors, zoom and focus

Use approved semantic roles in light/dark; no new raw palette, opacity-faded action or theme-specific secret copy. Reveal/code font remains 14/22px mono. Focus is a visible 2px ring plus 2px separation; readonly plaintext remains selectable. In `forced-colors:active`, allow system colors (`Canvas`, `CanvasText`, `ButtonText`, `Highlight`) and real borders/outlines to represent controls, radio selection and focus; do not globally set forced-color-adjust:none, rely on shadows/background fills, or use GrayText for readable expired metadata with active actions. Expired/revoked/error meaning always has text. Use Playwright `page.emulateMedia({forcedColors:'active'})` and inspect actual browser rendering; do not change Windows contrast settings or automate native dialogs.

Keep #61 two-column modal geometry and independent scroll, including below-900px settings layout. No new mobile layout or PAT popup at narrow widths. Names/warnings wrap; token never widens the modal; metadata table owns any horizontal scrolling. All list/form/reveal/confirmation actions are reachable at 200%, with the fixed settings close guarded as above. Color-only changes do not clear forms, secrets or focus or reissue tokens.

Form cancel and completed list return focus `새 액세스 토큰`. Reveal focuses heading/readonly area, not a destructive action; discard confirmation focuses `계속 보기`; revoke alert cancel returns to its row action (or stable list fallback if gone). Native text/radio/select/clipboard keys are preserved, with no global Escape handler that bypasses the shell. IME Enter in the name cannot issue or accept a confirmation until composition ends.
