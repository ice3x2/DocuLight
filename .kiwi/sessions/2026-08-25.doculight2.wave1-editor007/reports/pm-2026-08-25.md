## 4. 실행 중 늘어난 Task 둘 — 이 회차에서 가장 중요한 발견

`T-PH001-02` 가 표를 고치고도 판정 ②(칸 클릭)가 서지 않는 것을 보고, **원인이 표 밖에 있음**을 찾아냈다.

CM6 는 블록 위젯의 높이를 `getBoundingClientRect` 로 재는데 그 값은 `margin` 을 포함하지 않는다. `editor.css` 의 `.dl-mermaid { margin: 0.6em 0 }` 때문에 mermaid 블록마다 heightmap 이 약 1.2em 씩 모자랐고, 데모 문서는 표 위에 mermaid 가 다섯이라 표에 이르면 **-38px** 가 어긋났다. 그래서 칸을 눌러도 클릭이 표를 지나 아래 줄로 라우팅됐다.

**표에 국한된 문제가 아니었다** — 문단도 인용도 한 줄씩 밀려 있었다. 사용자에게 이미 보이던 결함이며, 같은 함정이 표에서는 이미 잡혀 CSS 주석에 증상까지 적혀 있었는데 mermaid 에는 적용되지 않았다.

`table-widget.ts` 를 기준선으로 되돌려도 어긋남이 같음을 확인해 **이 wave 의 변경과 무관한 선재 결함**임을 분리한 뒤, 겉보기를 바꾸지 않는 쪽(여백을 바깥 컨테이너의 `padding` 으로)으로 고쳤다.

## 6. `existing-test-weakened-or-deleted` 게이트 처리

이 게이트는 자동 승인 대상이 아니므로 PM 이 직접 재고 판정했다.

| 확인 | 결과 |
| --- | --- |
| 스크롤 top | 오류 블록 **0개** |
| `scrollTop=2000` | 오류 블록 **정확히 1개**, 문구 `No diagram type detected matching given configuration for text: 이건 mermaid 문법이 아…` |

**오류 표시 동작은 멀쩡했다.** 종전에는 heightmap 이 짧아 CM6 가 뷰포트 밖 위젯까지 과다 렌더했고 그 덕에 top 에서도 잡혀 단언이 **우연히** 통과했다. 어긋남이 사라져 CM6 가 제대로 언마운트하자 그 우연이 사라졌다.

그래서 **약화가 아니라 교정**으로 판정하고 경계를 못박았다 — 단언 `errorBlocks === 1` 은 글자 그대로 유지, 세는 위치만 이동, 「하나라도 나오면 통과」 금지, **뮤테이션 탐침으로 그 항이 여전히 무는지 확인**. 자식이 오류 경로의 클래스를 제거하자 `SDS-AC-4` 가 단독으로 죽었고 원복 후 12/12 로 돌아왔다.
